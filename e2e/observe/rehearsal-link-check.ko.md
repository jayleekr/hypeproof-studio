# 리허설 링크 확인 — 사람이 한 번 누르는 절차

대상: JY · 소요 **3분** · 준비물 없음 · 관련 [#1131](https://github.com/jayleekr/hypeproof-studio/issues/1131) ·
[#1132](https://github.com/jayleekr/hypeproof-studio/issues/1132)

브라우저에서 만든 수업을 **링크 한 번으로 앱에서 여는** 것이 C안이다. 오늘 기계로 잴 수 있는
데까지는 쟀고, **실제 브라우저 클릭으로만 답할 수 있는 것 둘**이 남았다.

1. 링크가 **확장까지 닿는가**
2. 창이 여러 개일 때 **어느 창이 받는가**

기계로 못 잰 이유는 [실패 경로 문서](../../docs/design/rehearsal-entry-failure-paths.md) §5.3 에
있다 — 합성으로 밀어 넣은 URL 은 `handleProtocolUrl(): not handled` 로 떨어진다. **계측기의
한계이지 제품 결함이 아니다.** 그래서 사람이 한 번 눌러야 한다.

---

## 하기 전에 (30초)

```bash
# 1. Studio 를 평소처럼 켜 둔다 (끄지 않는다 — 켜져 있는 상태가 강사의 실제 상황이다)
# 2. 창을 두 개 이상 열어 둔다  ← 질문 2번을 같이 답하려면 필요하다
# 3. 앱 버전을 적어 둔다
defaults read "/Applications/HypeProof Studio.app/Contents/Info" CFBundleShortVersionString
```

**버전이 왜 필요한가**: 지금 출하된 앱에는 **리허설 링크를 받는 코드가 아직 없다**(#1132 는
아직 브랜치에 있다). 그래서 **수업이 열리지 않는 것이 정상**이다. 이 확인의 목적은 수업을
여는 것이 아니라 **링크가 앱까지 가는지**와 **확인 창이 붙는지**를 보는 것이다.

---

## 누르기

```bash
open e2e/observe/rehearsal-link-check.html
```

페이지에 버튼이 둘 있다. **1번을 먼저** 누른다.

| | 무엇 | 정상이면 |
|---|---|---|
| **1번** | 대조군 (`…://file/tmp`) | **경고 창이 뜬다** → 뜨면 **아니오**를 누른다 |
| **2번** | 리허설 링크 (`…://hypeproof.hypeproof-chat/rehearse?ticket=…`) | **확인 창이 안 뜬다** |

**1번을 건너뛰면 안 된다.** 1번은 "링크가 앱까지 가는 길이 살아 있다"를 증명하는 자리다.
1번이 안 되면 2번의 "아무 일도 안 났다"는 **제품이 조용한 건지 길이 끊긴 건지 구분이 안 된다.**
오늘 하루 우리를 가장 많이 속인 것이 정확히 그 구분이었다.

### 브라우저가 먼저 묻는 창은 우리가 보려는 것이 아니다

브라우저가 *"HypeProof Studio을(를) 여시겠습니까?"* 를 띄울 수 있다. **그건 브라우저 것이다.**
열기를 누르고 **그다음**에 나오는 것을 본다.
다만 **그 창이 떴다는 사실 자체는 알려 달라** — 강사가 겪는 단계가 하나 느는 것이고,
그것도 결과다.

---

## 결과가 무슨 뜻인가

| 1번 | 2번 | 뜻 | 다음 |
|---|---|---|---|
| 경고 뜸 | 확인 창 **안 뜸** | **원하던 결과.** 길은 살아 있고 리허설 링크에는 확인이 안 붙는다 | "링크 한 번" 확정 |
| 경고 뜸 | 확인 창 **뜸** | 오늘 기계 측정이 **뒤집혔다** | 설계가 바뀌는 게 아니라 **화면 문구가 하나 는다** |
| 경고 **안 뜸** | (무엇이든) | **길이 끊겼다.** 앱 미설치·스킴 미등록 등 | 2번 결과는 읽지 않는다. 아래 "아무 일도 안 났을 때" |

그리고 **2번에서 확인 창 말고 무엇이 보였는지**가 남은 질문 1번의 답이다.

- **앱이 앞으로 나오거나 알림이 하나 떴다** → 링크가 **확장 라우팅까지 닿았다**. (지금 앱엔 받는
  코드가 없으니 "확장을 찾을 수 없다" 류의 말이 나올 수 있다. **그 말이 나오는 것이 좋은 신호다.**)
- **정말 아무 일도 없었다** → 확장까지 안 갔을 수 있다. 아래 절차로 한 번 더 본다.

---

## 알려 줄 것 (이게 있어야 한 번 누른 게 헛되지 않는다)

1. 앱 버전 (위에서 적은 것)
2. 1번에서 경고가 **떴는지**
3. 2번에서 확인 창이 **떴는지**
4. 2번에서 **그 밖에 보인 것** — 앱이 앞으로 나왔는지 · 알림이 떴는지 · 아무 일도 없었는지
5. 창이 여럿이었다면 **어느 창이 반응했는지** (마지막에 보던 창인지, 처음 연 창인지)
6. 창이 떴다면 **화면 사진** 한 장

## 아무 일도 안 났을 때만 (추가 2분)

앱이 남기는 기본 로그에는 이 판정에 필요한 줄이 안 들어간다(trace 수준이라). 한 번 더 볼
여유가 있으면 이렇게 한다.

```bash
# Studio 를 완전히 종료한 뒤
"/Applications/HypeProof Studio.app/Contents/MacOS/HypeProof Studio" --log trace
# 창이 뜨면 rehearsal-link-check.html 에서 2번을 다시 누른다
```

그리고 아래 파일을 보내 준다.

```bash
ls -t ~/Library/Application\ Support/HypeProof\ Studio/logs/*/main.log | head -1
```

그 안에 `handleProtocolUrl` 이 들어간 줄만 있으면 충분하다.

```bash
grep handleProtocolUrl "$(ls -t ~/Library/Application\ Support/HypeProof\ Studio/logs/*/main.log | head -1)"
```

- `not handled` 로 끝나면 → 오늘 기계 측정과 **같은 상태**다. 확장까지 가는 경로를 따로 봐야 한다
- 그 줄조차 없으면 → **URL 이 앱에 도달하지 않았다.** 전혀 다른 문제다

---

## 이 확인이 답하지 않는 것

- **수업이 실제로 열리는지**는 여기서 알 수 없다. 받는 코드(#1132)가 아직 출하되지 않았고,
  티켓도 가짜이며, 교환 엔드포인트도 아직 없다.
- 오늘 기계로 잰 "확인 창이 안 붙는다"는 **합성 경로** 기준이다. 이 확인은 그것을
  **실제 클릭으로 다시 재는 것**이지 처음 재는 것이 아니다.
