# 공통 측정 코어 요구사항

상태: 구현 전 계약 제안. 2026-09-13. Owner: jayleekr.
상위: [INT-MC-01–03](../intents/measurement-core.md). 추적: [#1020](https://github.com/jayleekr/hypeproof-studio/issues/1020), [#1021](https://github.com/jayleekr/hypeproof-studio/issues/1021).

각 행은 의도·출시 단계·관찰 가능한 수용 기준을 가진다. **P0도 현재 구현 완료를 뜻하지 않는다.** 테스트 ID의 상세와 실행 상태는 [검증 문서](../testing/measurement-core.md)가 소유한다. 설계상 잠정값은 실제 호스트 측정 후 근거와 함께 수정한다.

## 용어와 완료의 구분

- 작업: 사용자가 달성하려는 실제 일. 여러 호스트·세션·에이전트가 연결될 수 있다.
- 관찰: 어댑터가 실제로 수신한 사건. 모델이 작성한 설명은 관찰된 결과로 승격하지 않는다.
- 근거: 관찰의 특정 부분이나 실제 결과물 버전을 가리키는 참조. 해시만으로 인간 판단·진실성이 증명되지는 않는다.
- 해석: 근거에 대한 검토 가능한 주장. AI 작성·사용자 진술·사용자 확인·검토자의 판단을 구분한다.
- 작업 카드: 결과·판단·근거·미확인 사항을 검토하는 제품 화면/문서.
- 제출 묶음: Jay가 검토하여 공유 범위를 선택한 특정 revision. 로컬 보관함의 영속 접수와 원격 접수는 다른 상태다.
- Asset: 후보 역량 모델의 항목. 항목의 수·표시 이름을 저장 포맷·호스트 UI에 고정하지 않는다.

작업 완료, 기록 완료, 해석 검토, 제출 접수, 연구 검토, 역량 향상은 각각 별도 상태다. 한 상태로 나머지를 자동 완료 처리하지 않는다.

## 정책 경계와 변경 규칙

P0의 로컬 보관 정책은 Jay의 새 도구에만 적용한다. 원격 수집과 전 멤버 강제 적용은 P1 계약 및 별도 운영 준비가 있어야 한다. 기존 Studio 학습자 수집·권한·삭제 정책은 유지한다. MC-17의 6개 모델 기본 채택은 Jay의 2026-09-13 결정으로 이번 범위에 포함한다. [HC 계약](capability-model-contract.md)과 [#852](https://github.com/jayleekr/hypeproof-studio/issues/852)는 호환성·해석 버전·근거 검증을 구현하는 연결 작업이며 채택 결정을 다시 기다리는 게이트가 아니다. 검증된 수치 평가나 사람의 향상 주장은 별도 증거가 필요하다.

구현 PR은 다루는 MC ID, 실제 경로, 실행 증거, 남은 NOT RUN을 명시한다. 호스트 기능이나 포맷을 확인할 수 없으면 지원 제한을 기록하고 계약을 수정하며 조용한 추정·우회로 통과시키지 않는다. 요구사항 번호는 재사용하지 않는다.
