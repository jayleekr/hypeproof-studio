# 이용권·수업 예산·사용량 정산 요구사항

2026-09-08 · 상태: 제안, 구현 전 · #800 / #746 / Lab #777.
상위 [Product Intent](../PRODUCT-INTENT.md)의 이용 권한 Intent와
[설계](../design/access-budget-settlement.md), [검증 계획](../testing/capability-and-access.md)을 연결한다.
AB-*는 REQ-L5, AE-17/20/27/32, MU-03~08의 후속이며 기존 계약을 폐기하지 않는다.
아래 행은 구현 완료나 실제 결제 정책 채택을 뜻하지 않는다.

## 사용자 맥락

| 사례 | 권한·예산의 출처 | 담당자가 할 수 있는 일 |
|---|---|---|
| 강의료에 AI 포함 | 구매/지원 계약의 수업 이용권 → 기관·기수 공용 자원 | 담당 강사가 배정된 한도 안에서 학생·단계·모델·도움 범위를 설정 |
| 개인 구독, AI 포함 | 구독의 유효한 상품 revision과 이용 기간 | 본인의 허용 모델·Effort·기능을 선택하고 본인 잔여 상태 확인 |
| 개인/기관 BYO | Studio 기능 이용권 + 별도로 검증된 공급자 연결 | 해당 계정 권한으로 실행. 외부 청구·잔여는 확인 가능한 범위만 표시 |
| 구독자가 수업 참여 | 명시적으로 선택된 수업 지원분 또는 허용된 개인 이용권 | 수업 정책 안에서 하나의 비용 출처로 실행. 자동 합산·이중 차감 없음 |
| 기관이 여러 강사·반 운영 | 기관 계약 → 강사/기수 할당 → 학생별 사용 상한 | 위임받은 범위의 재배분, 추가 허용, 신규 작업 일시정지 |

## 계약과 완료 기준

| ID | 요구사항과 수용 기준 | Intent / 검증 |
|---|---|---|
| AB-01 | 상품·기능 이용권과 공급자 원가표를 별도 revision으로 고정한다. SKU/계약/유효기간/포함 단위/초과·이월·갱신 규칙이 없는 포함형은 활성화 불가. 현재 견적용 좌석·시간 원가를 API 정산 단가로 사용하지 않는다. | INT-ACCESS-01/06; CA-T01/02 |
| AB-02 | 개인·기관·수업 이용권은 같은 Service 집행 계약을 사용한다. 개인을 가짜 코호트에 넣지 않는다. 계정/기관/수업/구매자/사용자/비용 출처를 구분하고 서버가 관계를 확인한다. | INT-ACCESS-03/08; CA-T03 |
| AB-03 | 실행 가능 범위는 플랫폼 안전 정책, 조직 정책, 유효 이용권, 수업/단계 정책, 사용자 승인, 실제 런타임 지원의 교집합이다. 거부 우선. 유료 플랜·강사 이름·프롬프트·BYO가 권한을 확대하지 않는다. | INT-ACCESS-02/04; CA-T03/04 |
| AB-04 | RBAC와 대상 배정·위임 한도를 함께 검증한다. 강사는 담당 반의 예산을 배분·축소하고 승인된 여유 안에서 추가 허용할 수 있다. 기관 총예산·판매 가격·결제·개인 잔액은 권한 없이 변경할 수 없다. 동시 수정은 revision 충돌로 재검토한다. | INT-ACCESS-02/08; CA-T04/07 |
| AB-05 | 작업은 비용 출처 하나와 계약·수업 정책 revision에 귀속된다. 소진/오류/만료 때 개인 잔액·다른 반·BYO·다른 모델로 자동 전환하지 않는다. 허용된 전환은 사용자에게 조건을 표시하고 다음 작업에서 명시적으로 선택한다. | INT-ACCESS-01/04; CA-T05 |
| AB-06 | 새 유료 시도 전에 공용·개인 한도와 동시 슬롯을 하나의 원자적 판정으로 예약한다. 다른 제한 단위는 별도 확인한다. 중간 실패는 부분 예약 없이 거부하며, 재로그인·토큰 재발급·수업 재입장으로 기간 사용량을 초기화하지 않는다. | INT-ACCESS-06/08; CA-T06/07 |
| AB-07 | SDK 보조 호출·재시도·멀티모델 비교의 각 실제 공급자 시도를 작업에 연결한다. 동일 보고는 한 번만 반영하고 서로 다른 실제 시도는 각각 정산한다. 기존 model_usage_requests/usage_log/usage_request_settings를 연결하고 같은 호출을 두 원장에서 합산하지 않는다. | INT-ACCESS-06; CA-T08/09 |
| AB-08 | 공급자·실제 모델·protocol·service tier·캐시 종류/TTL·도구 단가의 관측 여부를 보존한다. 정수 금액 단위와 명시적 반올림을 쓴다. 요청한 모델명이나 현재 가격으로 미확인 과거 비용을 확정하지 않는다. | INT-ACCESS-06; CA-T02/09 |
| AB-09 | 종료 상태와 측정·원가·예산 정산 상태를 구분한다. 부분/미보고는 미정산 자원을 유지하고 지연 보고로 멱등 보정한다. 타임아웃/중지/예약 만료만으로 비용을 0 또는 잔여로 반환하지 않는다. 확인된 미실행만 취소한다. | INT-ACCESS-06; CA-T08/10 |
| AB-10 | 브라우저·Computer Use·검색·저장·격리 실행 비용을 해당 meter로 예약·정산한다. 요청 수, 토큰, 슬롯, 초, 통화는 서로 바꿔 쓰지 않는다. 상한을 구할 수 없는 실행은 통제된 예산 경로에서 열지 않거나 별도 명시된 노출 한도로 운영한다. | INT-ACCESS-06/08; CA-T06/09 |
| AB-11 | 학생/개인은 본인 포함 범위·출처·기준시각·잔여 상태·부족 사유·추가 허용 요청을 본다. 크레딧은 환산/만료/revision 정의가 있을 때만 쓴다. 강의료를 학생 현금 잔액처럼 표시하지 않는다. | INT-ACCESS-01/05; CA-T11 |
| AB-12 | 담당 강사는 자기 수업의 실제·예약·미확인·예상 소진 및 학생별 배분을 본다. 운영자는 권한 범위의 공급자 청구 대조와 미정산 사유를 본다. 다른 기관·개인 비용과 원문 대화는 기본 공개하지 않는다. | INT-ACCESS-02/06; CA-T04/11 |
| AB-13 | 한도 도달·구독 종료·일시정지는 새 유료 실행에 적용한다. 중지·기존 파일·자기 결과 열람/로컬 검증·내보내기·기존 보존 정책은 유지한다. 유료 검증은 별도 잔여 자원이 필요함을 설명한다. 수업 마무리 자원은 총예산 안에서 미리 배정한다. | INT-ACCESS-05; CA-T12 |
| AB-14 | 구독·갱신·변경 이벤트는 신뢰 가능한 서버 수신/조회로 확인한다. 중복·역순·지연/재전송과 기간 경계를 처리하며 로그인 성공/결제 페이지 복귀만으로 이용량을 부여하지 않는다. 변경 전후 계약과 진행 중 예약은 소급 변환하지 않는다. | INT-ACCESS-03/06; CA-T01/13 |
| AB-15 | 보수적 잔여와 확인 시각, 예약·미정산·초과 노출을 함께 보고한다. 초과가 관측되면 원장을 음수 노출까지 사실대로 유지하고 새 실행을 차단한다. 알려진 소계와 완전한 총액을 구분하며 정확한 다음 질문 수를 지어내지 않는다. | INT-ACCESS-06; CA-T07/10 |
| AB-16 | 사용량 정산과 고객 청구·입금·강사료/파트너 정산을 연결 ID로 구분한다. 청구 대조의 차이는 조정 이력으로 남기며 사용량 저장이 입금·급여 지급을 발생시키지 않는다. 현재 가격·결제·환불·보존 설정을 바꾸지 않는 합성 검증부터 한다. | INT-ACCESS-06; CA-T09/14 |
| AB-17 | 모델·Effort·도구·도움 수준·예산 차단은 관측의 실행 조건이다. 비용·구매 등급·많은 반복을 역량 점수로 사용하지 않고 학습 증거와 별도 접근 제어한다. | INT-ACCESS-07; CA-T15/18 |
| AB-18 | 새 금액 한도는 명시적으로 구성한 대상에만 적용한다. 이전 앱도 서버 게이트를 우회할 수 없고 지원하지 않는 계약은 설명 가능한 거부를 받는다. 기존 수업의 계약·배포 상태와 새 설계의 지원 범위를 명시한다. | INT-ACCESS-08; CA-T03/12/14 |

## 아직 확정되지 않은 상업 값

포함량/단위, 가격별 모델 접근, 초과 과금·이월·환불·유예, BYO 제품 지원, 공급자 청구 연결,
수업 마무리 여유의 크기는 각 상품의 확정 계약으로 제공해야 한다. 코드 상수나 운영 기본값으로
임의 확정하지 않는다. 이 결정을 기다리더라도 합성 계약을 통한 엔진·권한·화면 검증은 진행할 수 있다.
