## 아직 확정되지 않은 상업 값

포함량/단위, 가격별 모델 접근, 초과 과금·이월·환불·유예, BYO 제품 지원, 공급자 청구 연결,
수업 마무리 여유의 크기는 각 상품의 확정 계약으로 제공해야 한다. 코드 상수나 운영 기본값으로
임의 확정하지 않는다. 이 결정을 기다리더라도 합성 계약을 통한 엔진·권한·화면 검증은 진행할 수 있다.

## P1 구현 범위 (#853)

`worker/src/lib/access-contracts.ts`와 기존 admin 인증 아래 `/admin/access/*`가
상품 revision·서버 확인 계약 이벤트·개인 계정·기관/수업 연결을 저장한다. `/v1/access`는
본인 이용권만 반환한다. 강사의 `/admin/cohorts/:cohort/access`는 기존 issuer scope로
자기 반 계약 메타데이터만 읽는다. 개인을 코호트에 넣거나 issuer 역할을 예산 소유권으로 바꾸지 않는다.

현재 지원하는 명시적 판매 정책은 초과 거부·이월 없음·유예 없음, 갱신 none/calendar다.
다른 정책은 누락값으로 추정하지 않고 게시를 거부한다. 같은 기간의 가격·포함량 변경과
기간 중첩은 충돌이다. 다음 기간 이벤트가 너무 일찍 오면 `renewal_not_effective`로 거부하여
현재 이용권을 지우지 않는다. 확인된 발효 시점에 재전송하며, 결제 공급자 webhook adapter는 아직 없다.
서버 운영자의 확인 참조를 가진 이벤트 수신은 실제 결제 서비스 연동 완료를 뜻하지 않는다.

`HPS_ACCESS_CONTRACTS=enabled`와 migration 0007이 있어야 새 API를 사용한다.
합성 게시본은 dev에만 허용한다. 운영 게시본은 별도 검토한 정확한 SHA-256 digest 목록에
있어야 한다. 게시 검증 명령은 [설계의 운영 절차](../design/access-budget-settlement.md#p1-게시와-운영-경계)에 있다.
이 단계는 AB-01/02/05/14/18의 저장·조회 부분, AB-04의 기존 강사 조회 권한을 다룬다.
실제 유료 요청 집행·정산·강사 예산 수정은 후속 단계이며 P1만으로 CA-T03/05/13 전체를 통과했다고 하지 않는다.


## P2 구현 범위 (#854)

`usage_jobs`와 `usage_attempt_costs`는 기존 `model_usage_requests.request_id`에 계약/기간/가격 귀속과 최신 원가 상태를 연결한다. `usage_cost_evidence`는 누적 사용량 snapshot의 불변 이력이다. `usage_log`와 `usage_request_settings`를 추가 비용으로 합산하지 않는다. 같은 작업의 사용자/출처/기간/수업 정책을 바꾸려 하면 전체 등록 transaction을 거부한다.

별도 공급자 가격 revision은 실제 응답 모델·protocol·등급·지역·기간 및 meter별 유리수 요율을 갖는다. 각 meter를 정수 micro 통화 단위로 올림하고 합친 뒤 명시된 FX revision으로 한 번 환산한다. 공급자 청구와의 차이는 별도 invoice adjustment로 남기며 원 보고를 덮어쓰지 않는다. 지원하지 않는 비용 차원·캐시 분해·미보고는 partial/unpriced로 유지한다. 공급자 요율/환율/상한의 운영 기본값은 없다.

SDK/proxy의 응답 hook은 선행 귀속된 시도에만 원가 증거를 기록한다. 일반 legacy 요청은 자동으로 소급 가격을 붙이지 않는다. 원가 관측 실패는 미정산으로 남는다. 원가표가 신규 실행 승인 목록에서 빠져도 이미 게시된 과거 revision으로 시작한 시도의 정산을 막지 않는다. 실제 모델이 달랐다면 운영자가 공급자 확인 참조와 당시 유효했던 원가표를 지정하는 명시적 reconciliation이 필요하다.

이는 AB-07/08/09/10/16의 원가 엔진·이력 부분이다. 모든 경로의 전송 전 예약·실행 귀속, 재시도별 집행, 기간 예산 조정은 #855에서 통합한다. 세금/매출/고객 청구/입금/강사료 지급 API는 추가하지 않는다.


## P3 구현 범위 (#855)

`budgets.ts`와 `budget-admission.ts`가 AB-02/03/05/06/07/09/10/14/15/18의 Service 집행을 연결한다. 운영자가 계약 기간의 포함 자원으로 pool을 만들고 명시된 가격 revision·최대 노출 근거·전체/개인 동시 슬롯을 설정한다. allocation은 상위 자원을 미리 배정하고, cap은 사용 시 상위와 함께 확인하는 상한이다. 기관 → 반 → 학생 및 같은 계정의 여러 반 공통 상한을 지원한다. 새로운 반 배정/상한·pause·자원 변경은 revision 비교와 이력을 가진다.

`x-hps-funding-source`가 개인 또는 예산 필수 반에서 필요하다. `x-hps-turn-id`는 서버가 인증 주체와 함께 작업 ID로 변환한다. proxy/Agent SDK의 실제 각 HTTP 시도는 기존 usage request ID로 예약되고 전송된다. 관리 경로에서는 숨은 공급자 재시도/대체 모델을 쓰지 않는다. 다른 이용권/기간/정책으로 같은 작업을 이어 가는 요청은 거부한다. 이전 앱도 필수 반에서 예산 게이트를 우회할 수 없다.

현재 관리 실행은 확인 가능한 Anthropic Messages/OpenAI Chat text와 허용된 로컬 도구에 한정한다. 모델·Effort·도구는 이용권과 기존 수업/프로필 권한의 교집합이다. SDK 검색, 서버 hosted tools, 이미지/음성, 별도 격리 실행과 관찰 평가 API는 비용 상한/계측이 연결되기 전에는 이 경로에서 열지 않는다. 브라우저의 로컬 기능이 허용되어도 이미지 포함 요청은 아직 관리 예산 경로에서 지원하지 않는다. BYO·Gemini·GLM도 지원을 추정하지 않고 설명 가능한 거부를 반환한다.

개인 구독은 account identity와 계약 기간으로 실행하며 클래스/session DB 행을 만들지 않는다. 공유 자원의 음수 노출은 해당 기간 신규 실행을 중지시킨다. 하위 배정의 초과를 다른 반의 잔액으로 자동 충당하지 않는다. 강사 위임 화면·학생 사용량/이용권 선택 UI는 #856, 실제 공급자/수업 관측과 출시 증거는 #857 범위다.


## P4 구현 범위 (#856 / #847)

기존 채팅의 모델/Effort 제어 옆에 이용권·사용량 패널을 연결한다. 서버가 확인한 출처를 사용자가 직접 선택하고 그 턴의 proxy/브라우저 반복/SDK HTTP 호출에 같은 출처와 작업 ID를 전달한다. 이용권의 기능 범위로 프로필을 좁히며 모델을 자동 교체하지 않는다. SDK 사용 불가 때 관리 이용권을 다른 실행 경로로 자동 전환하지 않는다. 개인 계정은 서버가 확인한 별도 history scope로 보존하며 수업 liveness를 생성하지 않는다.

학생 조회는 본인 사용·예약·미확인과 공유 잔여를 구분하고 기준 시각을 표시한다. 끝난 현재 계약도 열람할 수 있다. 현금 환산 크레딧·정확한 남은 질문 수·자동 업셀은 없다. 추가 사용 요청은 담당 반의 검토 기록이며 잔액을 직접 늘리지 않는다. 요청 검토 완료와 예산 변경은 별도 조작이다.

Chalk `/budgets`는 기존 Service forwarder와 issuer scope를 사용한다. `budget_delegations`의 별도 담당 반/배정/ceiling/revision이 있어야 예산을 바꿀 수 있다. 위임 변경·학생 배분·pause는 이력을 남기고 동시 취소/수정이 저장을 막는다. 새 학생 cap을 나중에 만들어도 해당 기간의 이전 시도와 원가를 포함하므로 사용량을 초기화할 수 없다. 동시 실행 상한을 줄여도 이미 실행 중인 시도를 강제 종료하거나 비용을 반환하지 않는다.

운영자 `/operator/budgets`는 기존 admin 인증을 통해 기간/배정, 공급자 시도·정산 상태, invoice adjustment와 변경 이력을 읽는다. 검토한 계약/위임/복구 문서를 확인한 뒤 기존 API로 저장한다. Chalk는 관리자 비밀번호와 운영자 원가 API를 전달하지 않는다. 실제 수업 분포가 검증되기 전 예상 소진 시각은 unavailable로 표시한다.

## P5 구현·인수 범위 (#857)

연결 계정 비활성화/토큰 재발급이 새 예산 주체를 만들지 않도록 거부하고, 수업 예산 초기화 후의 새 계정 연결은 명시적 이관이 필요하다. 강사 mutation에는 현재 계약·기간 활성 상태도 원자적으로 검사한다. 기존 deployment workflow에 additive 0007~0010을 연결했다.

실제 D1에서 취소·미정산·동시 갱신·늦은 과거 정산을, 실제 pinned SDK에서 채팅·재시도·로컬 Read 후속 호출을 검증했다. 단일 실제 공급자 요청도 usage 수집까지 확인했다. [결과](../research/budget-readiness-2026-09-08/README.md)와 [활성화·복구 절차](../operations/access-budget-release.md)를 따른다. 운영 집계는 확보했지만 실수업 비용 분포·승인 상품/요율·공급자 청구 대조·결제 adapter는 아직 완료하지 않았다. 운영 활성화와 #857 전체 완료로 해석하지 않는다.
