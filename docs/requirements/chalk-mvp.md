## 진입·목록 (UX)

| ID | 요구 |
|---|---|
| UX-01 | 강사 토큰이면 Studio 에 Chalk 면이 보이고, 학생 토큰이면 보이지 않는다. 서버에서도 강사만 쓸 수 있다 |
| UX-02 | 강사의 강의 목록(초안·확정)이 서버에 저장되고, 앱을 다시 열어도 이어서 작업할 수 있다 |
| UX-03 | 수업 계획서는 HTML 파일이다. Studio 내장 브라우저로 완성 모양을 보고, 편집기로 원문을 열어 고칠 수도 있다 |
| UX-04 | Chalk 화면은 Studio 기존 디자인(색·글꼴·아이콘·간격·패널 배치·입력 요소·오류 표시)을 따른다. Chalk 전용 스타일을 만들지 않는다 |
| UX-05 | 새 화면은 Studio 기존 화면 요소를 먼저 재사용한다. 화면이 들어가는 PR 은 머지 전에 JY 가 개발판(dev) Studio 에서 직접 검수한다 |

## 생성 (GEN)

| ID | 요구 |
|---|---|
| GEN-01 | 다섯 가지를 입력받는다: 대상, 전하고자 하는 에셋(7개 중), 수업 방식, 요구사항, **형식(1회성 워크숍 / 여러 회차 트랙)** |
| GEN-02 | 수업 모형 후보를 모형 카드의 필드(잘 맞는 목표, 피할 조건, 선행지식)로 고르고, 고른 근거와 제외한 근거를 보인다 |
| GEN-03 | 작성 순서를 따른다: 증거 → 성취기준 → 본질적 질문 → 금지 개입 → 활동. 순서는 제품 지식에 들어 있다(볼트 초안에서 가져옴) |
| GEN-04 | 초안은 제품의 계획서 규격을 따른다(볼트 12절에서 출발, 13절 여부는 결정 2) |
| GEN-05 | 초안마다 쓴 제품 지식의 버전 번호를 기록한다. 같은 버전으로 같은 초안을 다시 만들 수 있다 |
| GEN-06 | 생성기는 강사 구독(4-3절)이나 서버(조직 키) 중 하나로 돈다. 서버로 돌 때는 강사용 호출 경로가 새로 필요하다(강사 토큰은 지금 학생용 대화 경로에서 막힌다). 어느 쪽이든 기록·비용은 서버에 남는다 |

생성기(대상·에셋 입력)는 [chalk-authoring.md](./chalk-authoring.md) GEN 묶음과 연결된다.

## 피드백과 검사 (FB)

| ID | 요구 |
|---|---|
| FB-01 | 강사가 말로 고칠 점을 주면 초안이 고쳐지고, 바뀐 곳을 비교해 볼 수 있다 |
| FB-02 | 초안이 바뀔 때마다 교육 기준 검사가 돌고, 결과가 편집기에 문제 표시로 뜬다(항목 ID 와 위치) |
| FB-03 | 초안 단계의 검사는 막지 않는다. 막는 것은 확정할 때뿐이다 |
| FB-04 | 문맥을 봐야 하는 항목은 모델이 판정하고, 결과에 모델과 판정 지시문의 버전을 함께 남긴다. 예: "아이가 만든 게임 속 점수"는 아동 점수화가 아니다. 힌트가 정답을 담고 있으면 금지 개입이다 |
| FB-05 | 피드백과 수정 이력을 모두 남긴다. 나중에 생성기를 고치는 재료가 된다 |

## 강의 만들기 (OUT)

| ID | 요구 |
|---|---|
| OUT-01 | 수업 계획서를 학생이 실제로 돌 형태로 바꾼다. 형태는 이 문서 11절의 결정 3 에 따른다 |
| OUT-02 | 학생 코치 설정(실행 방식·모델·도구·안전 장치)이 제품 규칙을 따른다. 아동 수업이면 미성년 모더레이션·위험 도구 차단·도구 승인 게이트가 켜져 있어야 확정할 수 있다 |
| OUT-03 | 강의를 활동 단위(부품)로도 저장해 다음 강의에서 다시 쓸 수 있다 |
| OUT-04 | 저장·확정·전달은 이미 운영 중인 서버 기능을 쓴다. 확정본은 바뀌지 않고, 동시 편집은 조용히 덮어쓰지 않는다 |
| OUT-05 | 에셋을 학생에게 점수로 보이지 않는다. 채점표(0/1/2)를 쓰는 강의는 만들지 않는다. 에셋은 관찰 기록과 성장 코멘트로만 남긴다(6/8 교정, 헌법 B-2) |

강의 만들기(대상·에셋 출력)는 [chalk-authoring.md](./chalk-authoring.md) OUT 묶음과 연결된다.

## 리허설 (RH)

| ID | 요구 |
|---|---|
| RH-01 | 강사가 학생 조건으로 들어가 채팅을 넣고 코치 응답을 본다 |
| RH-02 | 리허설 대화는 어느 경로로 돌든 기록이 서버에 남는다. 서버를 거치지 않는 강사 구독 리허설은 앱이 대화와 점검 결과를 서버에 올린다. 이 기록도 확정 근거가 된다(결정 8, 7판) |
| RH-03 | 계획서의 예상 막힘을 리허설 점검표로 띄우고, 강사가 항목마다 알맞음·고칠 것을 표시한다 |
| RH-04 | 리허설 중 앱을 닫아도 원래 강사 자격으로 돌아갈 수 있다. 원래 자격은 앱의 비밀 저장소에 보관한다 |

## 강의 계획안 (PLAN)

| ID | 요구 |
|---|---|
| PLAN-01 | 형식(1회성 워크숍 / 여러 회차 트랙)에 따라 시간 규격을 고른다. 워크숍은 5블록 코어, 트랙은 110분 블록 두 개 + 휴식 |
| PLAN-02 | 지도안과 함께 운영 계획안을 만든다. 둘 다 HTML 파일이고 서로 오갈 수 있다 |
| PLAN-03 | 시간표는 블록마다 시각·길이·활동·핵심 에셋·산출물을 담는다. 합계가 회차 길이와 ±10분 안인지(G2-9), 정리가 10분 이상인지(G3-4) 검사한다 |
| PLAN-04 | 블록마다 진행자·보조 강사·아이·부모의 행동을 따로 적는다. 가족 수업이면 부모에게 역할 이름을 준다 |
| PLAN-05 | 준비물을 종류(물리 / 디지털 / 계정·설치) × 주체(강사 / 학생 / 부모)로 나눠 점검 목록으로 만든다. 강의 설정에서 나오는 준비(학생 토큰 발급, 필요한 스킬 팩 탑재 확인 등)는 자동으로 들어간다 |
| PLAN-06 | 진도 차이를 흡수하는 완충 블록과, 시간이 남을 때·모자랄 때 할 일을 적는다 |
| PLAN-07 | 운영 위험과 위험마다 첫 대응 멘트를 적는다(AI 지연, 콘텐츠 가드, 진도 격차, 부모 과개입, 시간 초과) |
| PLAN-08 | 사전 안내·동의 항목과 수업 후 제공물을 적는다. 동의서에는 학생이 쓰는 모델과 계정 구조가 들어간다 |
| PLAN-09 | 블록마다 종료 판정(무엇이 참이면 넘어가나)과 막힐 때 할 일을 적는다. 넘어가는 기준은 시각이 아니라 조건이다 |
| PLAN-10 | 같은 계획안에서 진행자용 런북과 참가자용 안내문을 따로 뽑는다 |

## 강사 구독 연결 (SUB)

| ID | 요구 |
|---|---|
| SUB-01 | 강사는 자기 Claude 또는 Codex 구독을 연결해 생성기·피드백·리허설을 돌릴 수 있다. 개발용 Studio 의 로컬 구독 실행 방식을 쓴다 |
| SUB-02 | 배포판 Studio 에서도 강사 토큰이면 구독 연결을 켤 수 있다. 학생 토큰에서는 켜지지 않는다 |
| SUB-03 | 구독이 없거나 연결하지 않으면 서버(조직 키)로 돈다 |
| SUB-04 | 구독 자격은 강사 컴퓨터에만 두고 서버로 보내지 않는다 |
| SUB-05 | 리허설 화면과 기록에 리허설 경로와 수업 경로의 차이(모델, 안전 장치)를 나란히 보이고, 다르면 경고한다. 경고는 확정을 막지 않고, 확정 기록에 그 차이가 함께 남는다 |
| SUB-06 | 강사는 채팅 대화만으로 Chalk 기능(입력, 초안 생성, 검사, 피드백 반영, 계획서 편집, 리허설, 확정·내보내기)을 모두 쓸 수 있다. 각 기능은 AI가 부르는 도구로 제공된다 |
| SUB-07 | 화면 버튼과 AI 도구는 같은 기능 구현을 부른다. 한쪽에만 있는 기능은 없다 |
| SUB-08 | 강사 채팅은 학생 채팅창과 같은 자리·모양의 화면을 강사 모드로 쓴다. 강사 모드는 지시문과 도구 묶음이 다르고, 학생 토큰에서는 열리지 않는다 |
| SUB-09 | 모델은 드롭다운으로 고른다. 목록은 연결된 쪽(Claude 구독, Codex 구독, 서버)이 허용하는 것이다 |
| SUB-10 | 모델 이름을 직접 입력할 수 있다. 드롭다운과 같은 설정을 바꾼다. 없는 모델이면 오류를 보이고 이전 모델을 유지한다. 슬래시 명령(`/model`)은 만들지 않는다 |
| SUB-11 | 채팅창에 지금 연결과 모델을 늘 보이고, 대화·초안·리허설 기록마다 쓴 모델을 남긴다 |

## 계획서 형식 (HTML)

| ID | 요구 |
|---|---|
| HTML-01 | 지도안·운영 계획안·진행자 런북·참가자 안내문을 HTML 파일로 만들고 Studio 내장 브라우저로 연다 |
| HTML-02 | 한 파일에 사람용 모양과 기계가 읽는 표식(절, 단계, 예상 막힘, 지원 등)을 함께 담는다. 검사·학생용 단계 목록·리허설 점검표가 이 파일에서 나온다 |
| HTML-03 | 파일 하나로 완결되고 외부 의존을 최소로 해서 나중에 웹에 그대로 올릴 수 있다 |
| HTML-04 | 밝은 바탕(다크모드 없음), 폭 하나, 글자 크기 계층을 지킨다 |

## 저장 형식 (SCH)

| ID | 요구 |
|---|---|
| SCH-01 | 강의 저장 형식에 검사가 읽어야 할 칸을 더한다: 단계별 시간, 단계별 금지 개입, 선행·배제 조건, 대상 층. 지금은 칸이 없어 검사 항목이 건너뛰어지거나 문장을 추측해 판정한다 |
| SCH-02 | 대상 층 칸의 이름은 `scope` 가 아니라 `audience_tier` 같은 별도 이름으로 한다. 볼트에서 `scope` 는 문서의 유효 범위라는 다른 뜻이다 |
| SCH-03 | 이름이 같다고 다른 개념을 잇지 않는다. 저장 형식의 `evidence` 는 활동 유형 표시이고, 검사가 보는 "증거물"과 다르다. 9/20 에 이어 붙였다가 되돌린 기록이 코드에 있다 |

## 지식원 (KB)

| ID | 요구 |
|---|---|
| KB-01 | Chalk 와 Studio 는 실행 중에 볼트를 읽지 않는다. 지식은 Studio 서버에 있다 |
| KB-02 | 볼트에서 출발 자료를 한 번 가져온다. 무엇을 어느 커밋에서 가져왔는지 기록한다. 수업 모형 카드는 `family` 가 `reference` 가 아닌 것만 가져온다(ID·파일 이름으로 거르지 않는다) |
| KB-03 | 제품 지식에는 버전 번호가 있다. 바뀔 때마다 새 버전이 되고 옛 버전도 읽을 수 있다 |
| KB-04 | 닫힌 어휘(수업 모형의 목표 29개·조건 9개)를 제품이 검사한다. 어휘 밖의 값은 저장하지 않는다 |
| KB-05 | 나중에 Sediment 로 옮길 수 있게 Sediment 의 문서 모양(필드 + 본문)을 따른다 |
