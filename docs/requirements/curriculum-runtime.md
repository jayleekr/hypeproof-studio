# Curriculum Runtime requirements

Status: proposed contract, not implemented. 2026-09-29. Owner: jayleekr. Epic [#1388](https://github.com/jayleekr/hypeproof-studio/issues/1388).
Parent: [INT-CR-00–09](../intents/curriculum-runtime.md). Source: *HypeProof Studio Curriculum Runtime PRD v1.0* (2026-09-28), preserved verbatim at [docs/design/curriculum-runtime-prd-v1.0-2026-09-28.md](../design/curriculum-runtime-prd-v1.0-2026-09-28.md); §-numbers refer to it.
Derived: [plan, DAG and gap matrix](../plan/curriculum-runtime.md) · [verification CR-T](../testing/curriculum-runtime.md).

Each row has a stage, intent links, the curriculum weeks it serves, an observable acceptance criterion, the existing requirements it reuses, and its verification IDs. **P0 does not mean implemented.** No row here is evidence of implementation, deployment or classroom use. Test detail and run status belong to the verification document. Code paths named in a row are 2026-09-29 observations of what the row changes or reuses, not a claim that the code satisfies it.

How to read the columns:

- **Weeks** — the curriculum weeks (PRD §4) whose required behaviour the row serves. `W1` is Week 1 ("누구의 어떤 어려움인가?") through `W6` ("무엇을 만들고 무엇을 배웠나?"). Work ranking uses the earliest week as a tie-breaker after dependency order and priority.
- **Reuses** — existing registry IDs that already govern part of the behaviour. The row does not restate them; it states only the curriculum-specific delta. Their ownership and work items do not move (for example AE-05/18/37 stay with `review-validity` #557, WEB-07/08 with `publish-recovery` #1018). A dash means nothing existing covers it.
- **SX-48 constraint** — every row in sections E (Evidence) and G (Venture Memory), and CR-10, CR-12, CR-13, CR-16, CR-21, CR-44, CR-46, CR-47, CR-48, CR-52, CR-55, CR-56, CR-58, CR-67, CR-69, CR-73, CR-81, reads or writes the existing `hps-observation/1` / measurement-core store (`worker/src/lib/measurement-core/`) and cites SX-48. No second store, second validator copy or second scorer.

## Terms

- Artifact version: an immutable, content-addressed (SHA-256) snapshot of the files that make up a product, deck, review or report (PRD §10.4). A browser result, a verification report or a published test version always names one.
- Experiment Browser: the embedded browser as the place where the student's product is rendered, operated by AI, tested by humans, observed and turned into evidence (intent decision D1). Built on `BrowserControl` (`extensions/hypeproof-chat/src/browserControl.ts`), `browserMcp.ts`, `nativeBrowser.ts` and ADR 0002.
- Participant: a person outside the class who opens a published test version. Not a HypeProof user; has no login.
- Observed / Interpreted / Assumed: the three confidence classes of an evidence item (PRD §5.3, §10.2). Only Observed may be presented as fact, and only with source references.
- Capability: a named class of AI work (`text.fast`, `reasoning.high`, `coding`, `vision`, `research.grounded`, `browser.agent`, `image.generate`, `speech.transcribe`) that a policy maps to a concrete model (PRD §5.4).

Requirement existence, implementation, deployment, classroom use and learning effect are separate states. One never completes another.

## Scope

- P0 covers PRD P0-1..P0-9 and the §14 loop. PRD §8 P1 features and §9 non-goals are out of scope.
- PRD §4 says the runtime must support the six-week sequence. Week behaviours that no P0-n acceptance criterion names have their own rows, read as what the P0 features must do for that week: repeated use and returning sessions CR-72 and the failure/safety review of the product's AI behaviour in the Critic skill CR-47 (W2); channel experiments CR-73, stakeholder roles with the payer/user distinction CR-75, impact and other metrics CR-76 (W3); comparison experiments CR-74 and product version diff CR-77 (W4); the fact/assumption register CR-82 (W5); a stable demo from a pinned published version CR-22, the version/evidence timeline CR-78 and the "belief changed because…" story CR-79 (W6). Randomised assignment of participants to variants is not among them; PRD §8 lists A/B templates as P1.
- The observation, evidence and interpretation core belongs to [MC-01–48](measurement-core.md) and [SX-44–48](studio-learning-experience.md). CR rows extend it; they do not own it.
- Model access, budgets and settlement belong to [MU-01–08](model-access-usage.md), [AB-01–18](access-budget-settlement.md) and [AE-25–33](learning-agent-experience.md). The gateway rows add the capability vocabulary, the student-app endpoint with its rate limits, raw-input handling (CR-83) and the coach's use of it (CR-84), and the curriculum attribution dimensions.
- Browser verification validity belongs to [AE-05/18/37](learning-agent-experience.md). Publishing belongs to [WEB-07/08](chalk-authoring.md) and error inspection to WEB-06; WEB-09 (web-app template build and run) is not reused.
- The six student-visible stages of PRD §3 (Research → Think → Build → Test → Evidence → Deck) are screen structure, which [INT-SX / SX](studio-learning-experience.md) owns: the mission header and today's actions from the session design file (SX-01, SX-02), the split of learning information, workspace and evidence record (SX-05), and weeks and steps as data (SX-56). CR adds no stage navigation of its own; stage names shown to students are Korean copy under the SX rules.
- PRD §2.2 lists six gaps. Four are rows: provider keys in student apps (CR-29), a native external test link (CR-17), product usage as evidence (CR-23) and the coach not reliably using HypeProof-native infrastructure (CR-84). Two are not P0 rows. "Shared data across devices" for student apps is the rich shared backend that PRD §8 lists as P1; Venture Memory (section G) is the only cross-device state in scope. "Camera/microphone availability in preview" is not enabled in the Experiment Browser; a student app that needs a device is tested through its published version on the participant's own device, under CR-66.
- Weekly Review Packs are prepared by the team's explicit "Prepare Weekly Review" run and then cached (PRD P0-8 generation strategy, CR-49). Preparing a pack automatically before the directing session without a student action is not a P0 row; a team without a pack shows "missing" (CR-53), and opening never generates (CR-50).
- Open decisions that block a default but not the design: default link expiry (CR-19), default retention of declared raw participant input (CR-67, and the gateway path of CR-83), whether returning-session linkage may be on by default for minor cohorts and how long a participant pseudonym lives (CR-65), and any minor-cohort consent path (Lab).
