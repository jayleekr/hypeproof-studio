# Curriculum Runtime requirements

Status: proposed contract, not implemented. 2026-09-29. Owner: jayleekr. Epic [#1388](https://github.com/jayleekr/hypeproof-studio/issues/1388).
Parent: [INT-CR-00–09](../intents/curriculum-runtime.md). Source: *HypeProof Studio Curriculum Runtime PRD v1.0* (2026-09-28); §-numbers refer to it.
Derived: [plan, DAG and gap matrix](../plan/curriculum-runtime.md) · [verification CR-T](../testing/curriculum-runtime.md).

Each row has a stage, intent links, the curriculum weeks it serves, an observable acceptance criterion, the existing requirements it reuses, and its verification IDs. **P0 does not mean implemented.** No row here is evidence of implementation, deployment or classroom use. Test detail and run status belong to the verification document. Code paths named in a row are 2026-09-29 observations of what the row changes or reuses, not a claim that the code satisfies it.

How to read the columns:

- **Weeks** — the curriculum weeks (PRD §4) whose required behaviour the row serves. `W1` is Week 1 ("누구의 어떤 어려움인가?") through `W6` ("무엇을 만들고 무엇을 배웠나?"). Work ranking uses the earliest week as a tie-breaker after dependency order and priority.
- **Reuses** — existing registry IDs that already govern part of the behaviour. The row does not restate them; it states only the curriculum-specific delta. Their ownership and work items do not move (for example AE-05/18/37 stay with `review-validity` #557, WEB-07/08 with `publish-recovery` #1018). A dash means nothing existing covers it.
- **SX-48 constraint** — every row in sections E (Evidence) and G (Venture Memory), and CR-13, extends the existing `hps-observation/1` / measurement-core store (`worker/src/lib/measurement-core/`). No second store, second validator copy or second scorer.

## Terms

- Artifact version: an immutable, content-addressed (SHA-256) snapshot of the files that make up a product, deck, review or report (PRD §10.4). A browser result, a verification report or a published test version always names one.
- Experiment Browser: the embedded browser as the place where the student's product is rendered, operated by AI, tested by humans, observed and turned into evidence (intent decision D1). Built on `BrowserControl` (`extensions/hypeproof-chat/src/browserControl.ts`), `browserMcp.ts`, `nativeBrowser.ts` and ADR 0002.
- Participant: a person outside the class who opens a published test version. Not a HypeProof user; has no login.
- Observed / Interpreted / Assumed: the three confidence classes of an evidence item (PRD §5.3, §10.2). Only Observed may be presented as fact, and only with source references.
- Capability: a named class of AI work (`text.fast`, `reasoning.high`, `coding`, `vision`, `research.grounded`, `browser.agent`, `image.generate`, `speech.transcribe`) that a policy maps to a concrete model (PRD §5.4).

Requirement existence, implementation, deployment, classroom use and learning effect are separate states. One never completes another.

Implementation PRs name the CR IDs they address, the real paths, the evidence class of each run (live-host / captured-replay / synthetic, per MC-38) and what remains NOT RUN. To change a label, a field or a target, edit this table first. Requirement IDs are never reused.
