# 수업별 Agent 경험 요구사항

상태: 제안 / NOT IMPLEMENTED AS A SET. 2026-09-08 · [#746](https://github.com/jayleekr/hypeproof-studio/issues/746).
근거: [비교 연구](../research/agent-experience-2026-09-08/README.md), [Intent·디자인](../design/learning-agent-experience.md).
이 문서는 기존 기능을 없다고 선언하지 않는다. 아래는 기존 구현을 포함한 **새로운 종단 인수 목표**다.
기존 REQ/ADM/CH/WEB/ENV/RUN/CLS/EDU 계약을 대체하지 않으며 정책 변경은 구현 PR에서 명시한다.
P0는 첫 성인 홈페이지 파일럿의 요구, P1은 운영 확대, P2는 실험이다. 출시 일정의 확정 약속은 아니다.
기준 경로는 기존 L2의 진료시간·공지 수정과 L1의 비교 판단이다. 레벨 정의는
[기존 과정](../curriculum/dental-ownership/README.md)을 유지한다. AE-35~42는 이번 설계 보강의 추가 인수 목표다.
2026-09-08 [Lab 철학 적용](../design/philosophy-alignment-2026-09-08.md)은 기존 P0를 유지하고
AE-43/44를 P1로 추가한다. 정의의 원본은 Lab에 있으며 이 표는 제품 인수 목표다.

## Acceptance requirements

상위 원칙은 [Product Intent](../PRODUCT-INTENT.md), 체험 대화 분기는
[NAT-03](studio-native-trial.md#764에서-파생한-행동-계약)을 따른다.
아래 `INT-AE-*`는 기능 의도이며 Human Asset `INTENT`와 혼용하지 않는다.
AE-01/02/36/41은 충분한 요청에 진단을 강요하지 않고 기존 맥락을 재사용하는 방향으로
해석한다. 강사·모델·SDK 기능 설정도 이 원칙과 기존 Service 권한을 함께 만족해야 한다.

## AI 이름·역할 설정의 구체 범위

사용자 추가 요청(2026-09-08): 현재 “코치”라는 고정 호칭도 강사가 바꿀 수 있어야 한다.
예: 홈페이지 수업은 “제작 파트너”, 검수 수업은 “검토 도우미”, 강사가 정한 이름도 허용한다.

기존 `ux.coach.naming_mode`의 fixed/user_names_it/pick_from_list와 `fallback_name`,
coach name/personality 저장 경로를 먼저 재사용한다. 이름 설정 기능 전체를 새로 만들지 않는다.
현재 `pick_from_list`의 학생 UI까지 구현됐다는 뜻은 아니므로 경로별 지원을 확인한다.
강사 authoring에서 설정하고 확정 수업 버전으로 전달하는 경로와 하드코딩 문구 제거가 새 작업이다.

| 필드/행동 | 제안 계약 |
|---|---|
| 표시 이름 | 강사 지정 이름. 미설정 신규 수업의 중립 기본값은 “AI 도우미” 제안. 기존 확정 수업의 이름은 자동 변경하지 않음 |
| 역할 소개 | 무엇을 도울 수 있는지 한 문장. 실제 허용 기능보다 넓은 권한을 약속하지 않음 |
| 말투/교수 전략 | 존댓말/간결함/질문 방식 등 콘텐츠 설정. SDK system prompt 소유자인 Service 경로로 전달 |
| 학생 개인화 | 고정 / 강사 후보 중 선택 / 학생 별명 허용. 수업 설정에 따르며 다른 수업에 전파하지 않음 |
| AI 고지 | 이름과 별개인 AI 배지/안내. 실존 강사나 사람의 답변으로 오인하지 않게 유지 |
| 표시 일관성 | 채팅 역할명·작명 화면·입력 안내·상태·승인 설명·오류·공유 내역에서 같은 identity를 참조. 사람 강사 명칭과 구분 |
| 버전/재현 | 새 이름은 다음 확정 실행에 적용. 과거 기록에는 당시 이름과 안정된 assistant ID를 연결 |
| 호환 | 내부 `coach` 식별자를 일괄 개명할 필요 없음. 기존 필드→새 수업 설정 매핑을 한 곳에 두고 구버전 행동을 검사 |

설정 변경이 곧 운영 수업 변경은 아니다. Service의 session-design/1은 현재 해당 필드를
받지 않으므로 schema evolution과 구버전 클라이언트 호환을 E2에서 연결한다.

## 출시 판정

P0는 AE-01~12, AE-14~16, AE-18, AE-20, AE-22, AE-25~28, AE-33, AE-35~41의 30개 행이다.
AE-26은 고정/제한 선택만 P0이며 자동/비교는 P1이다.
각 행은 최소 하나의 [인수 시나리오](../testing/learning-agent-experience.md)에 연결해야 한다.
P1/P2 항목이 기본 경로에 활성화되면 해당 시나리오도 그 출시의 필수 게이트가 된다.
독립 과제에 진입하고 도움을 선택하는 P0 기능과 사람의 전이 학습을 관찰하는 AE-24는 별도다.

계약 진화는 resolved profile의 실행 binding을 공통 참조로 설계하되 기존 관찰·공유·파일 복구를
하나의 새 저장소로 합치지 않는다. [#745의 native observation 기반](https://github.com/jayleekr/hypeproof-studio/pull/745)을
먼저 확인한다. 현재 schema에 새 필드를 임의로 넣지 않으며 구현 PR에서 양쪽 소비자·drift lock·구버전 처리와 연결한다.

E1의 표시 개선만으로 E2의 권한 계약을 PASS로 만들지 않는다. 마찬가지로 SDK 단위 테스트와
React 캡처만으로 실제 Student App→Service→SDK→browser 종단 경로가 검증됐다고 쓰지 않는다.
각 행의 실행 상태는 [테스트 계획](../testing/learning-agent-experience.md)에 기록한다.

사용자 후속 질문의 구체화: [effort·강의료 포함 사용량 설계](../design/model-effort-and-course-usage.md),
#799(E7 effort), #800(E3/E5 예산·사용량). 이 확장은 제안이며 #792의 모델 선택 실행만으로 완료하지 않는다.
