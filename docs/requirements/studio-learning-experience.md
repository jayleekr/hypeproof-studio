# 학습 경험 우선 Studio 요구사항

상태: 구현 전 계약 제안. 2026-09-18. Owner: jayleekr.
상위: [INT-SX-00~10](../intents/studio-learning-experience.md). 출처: [브레이크다운](../design/ux-principles-breakdown-2026-09-18.md) §4의 ID 할당과 [원문 설계 철학](../design/ui-philosophy-2026-09-18.md).
파생: [설계](../design/studio-learning-experience.md) · [검증 SX-T](../testing/studio-learning-experience.md) · [계획](../plan/studio-learning-experience.md).

각 행은 단계·의도·관찰 가능한 수용 기준을 가진다. **P0도 현재 구현 완료를 뜻하지 않는다.** 이 문서의 어떤 행도 구현·배포·실사용 증거가 아니다. 테스트 ID의 상세와 실행 상태는 검증 문서가 소유한다. 행에 적힌 현재 코드 경로는 2026-09-18 기준 관찰이며, 그 코드가 요구를 만족한다는 뜻이 아니라 요구가 바꾸거나 재사용할 대상이라는 뜻이다.

Intent 열의 표기: `상위 X`는 X가 이 행의 상위 계약이고 이 행은 X를 화면 행동으로 좁힌 것이다. `확장 X`는 이 행이 X의 조작·데이터 계약을 유지한 채 넓히는 것이다. 두 경우 모두 X를 복사하지 않고 참조한다.

## 용어와 완료의 구분

- 과제: 세션 설계 파일의 단계 하나를 학생이 시작해서 제출하는 단위. 여러 세션에 걸칠 수 있다. 주차는 과제의 묶음이다.
- 세션 설계 파일(Module): Chalk에서 저작하고 확정 버전으로 서빙되는 데이터 파일. 현재 스키마는 `hps-session-design/1`(`worker/src/lib/session-design.ts`)이고 이 요구는 그 확장을 요구한다. 코드가 아니라 데이터이며, 6주 커리큘럼은 이 파일 여섯 개다.
- 경계: 회고가 열릴 수 있는 세 시점. 제출(과제를 submitted로 전이), 세션 종료(연결 해제 또는 앱 종료 직전 저장), 주차 종료(주차의 마지막 과제 제출). 그 외 시점은 경계가 아니다.
- 근거: 실제 이벤트나 산출물 버전을 가리키는 참조. 학생 원문, 테스트 결과, 변경 전후, 외부 반응이 여기 속한다. 해석이 아니다.
- 해석: 근거에 대한 검토 가능한 주장. 자동 해석은 미검토 초안이며 학생 정정, 강사 확인과 revision으로 구분한다. 여섯 역량 이름은 해석의 내부 프레임이고 학생 화면의 언어가 아니다.
- 변화 기록: 여러 과제의 근거에서 반복된 패턴과 다음 실험을 보여주는 화면. 화면 이름은 "나의 변화 기록"이다. 원문의 "성장 인사이트", "나의 성장" 화면이 이것이며, 내부 개념명 growth story는 유지하되 사람에 대한 변화 주장을 하는 라벨로 쓰지 않는다.
- 실제/가상: 이벤트의 `source_state`. real(실제 외부 사용자·자료), simulated(가상 사용자·샘플·시뮬레이션), self_reported(학생 진술), unverified(출처 미확인). UI와 데이터가 같은 어휘를 쓴다.
- 강사 확인: `teacher_state`의 confirmed/disputed. 자동 해석 상태와 별개 필드이며 강사가 직접 조작했을 때만 바뀐다.

요구사항 존재, 구현, 배포, 사람의 실제 사용, 학습 효과는 각각 별도 상태다. 한 상태로 나머지를 자동 완료 처리하지 않는다. 특히 게이트가 화면에서 막힌다는 사실은 학생이 무언가를 배웠다는 증거가 아니다.

## 범위 해석

- 이 표는 학습 흐름의 화면 행동과 그 아래의 데이터 확장을 정한다. 제2 채점기, 제2 저장소, 새 점수 산식은 만들지 않는다(SX-48). 관찰·해석·검토·제출의 코어는 [MC-01~48](measurement-core.md)과 [HC-01~08](capability-model-contract.md)이 소유한다.
- 전 멤버 강제 수집이나 강제 등록은 이 표에 없다. 수집 범위·동의·삭제는 기존 NAT/AE/MC 정책을 유지한다.
- 점수·순위·배지는 어디에도 없다. 숫자는 숫자 주차(SX-51)와 접힌 방법/세부 데이터(SX-37)에만 있다.
- 6주 커리큘럼은 데이터다. GlobalBuddy 예시 여섯 파일은 세션 설계 파일이고 코드가 아니다(SX-56). 이 표는 그 파일의 내용을 정하지 않는다.
- 학생 파일럿은 포함하지 않는다. 첫 사용자는 Jay dogfood(P0~P2)이고 학생 경로는 P4 이후 조건이 갖춰진 뒤다. 게이트가 막힌다는 사실은 학습 효과의 증거가 아니다.
- Lab 쪽 선행 작업 두 가지에 의존한다. (1) SX-60은 Lab `measurement-profile.md` MP-01(score-first) 개정 결정 기록이 있어야 한다. (2) SX-41의 정책 내용(미성년 학생의 보호자 동의·강사 매개 경로)은 Lab MISSION의 아동 안전 결정 기록이 정한다. 둘 다 Studio 문서가 대신 정하지 않는다.
- 이 문서가 참조한 measurement-core 코드(`worker/src/lib/measurement-core/`)와 로컬 검토 화면(`LocalReview.tsx`, `localReviewPanel.ts`)은 2026-09-18 기준 #1042 브랜치에서 확인했고 main에는 아직 없다. 머지 상태는 구현 PR이 확인한다.
- 원문 §0 컨셉 보드와 §6~§7의 주차별 UI 목록은 이 표의 행이 아니다. 전자는 참고 이미지, 후자는 세션 설계 파일의 내용이다.

## 정책 경계와 변경 규칙

이 표의 P0는 Jay dogfood 경로의 첫 수용 목표다. 학생 화면·강사 화면·Lab 웹의 실제 변경은 각각 위의 선행 결정과 별도 배포 절차를 거친다. 기존 Studio 학습자 수집·권한·삭제 정책은 유지한다. 여섯 역량 모델의 기본 채택은 MC-17의 결정을 따르고 이 문서가 다시 결정하지 않는다.

구현 PR은 다루는 SX ID, 실제 경로, 실행 증거(live-host / captured-replay / synthetic 구분), 남은 NOT RUN을 명시한다. 화면 이름·라벨·문구를 이 표와 다르게 쓰려면 표를 먼저 고친다. 원문 철학 문서는 수정하지 않고 파생 문서를 고친다. 요구사항 번호는 재사용하지 않는다.
