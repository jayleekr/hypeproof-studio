# 모델 선택과 이용량 제어

사용자 요청 #841. 상위 Intent는 [Product Intent](../PRODUCT-INTENT.md), 기존 요구는
[모델·이용량 설계](../design/model-effort-and-course-usage.md)와 #800이다.
모델 비교 자체를 체험의 목적이나 학습 성취도로 삼지 않는다. 기본 모델로 바로 작업하고
필요할 때 사용자가 바꾼다. 이 변경은 강의료·추가 결제·월 예산을 정하지 않는다.

| ID | 동작과 완료 기준 | 구현·검증 |
|---|---|---|
| MU-01 | 서버 시크릿만 사용. 기존 수업은 유지하고 명시적 성인 proxy 실습만 공급자별 모델을 선택 | studio-model-practice; 기존 선택 UI; 실제 Mac |
| MU-02 | 허용 모델만 전송. 다른 공급자로 자동 대체하지 않고 한 사용자 요청에 상류 호출 한 번 | 실제 Hono 계약; 401/403/400/409/429/503 대조 |
| MU-03 | 호출 전에 회차·사용자 요청 횟수와 사용자 동시 슬롯 1개를 원자적으로 예약 | model_usage_requests; SQLite 20개 동시 예약 |
| MU-04 | 토큰 재발급은 회차 사용 횟수를 초기화하지 않음. 실패한 호출도 시도에 포함 | 실제 route + 재발급 테스트 |
| MU-05 | 서버 요청 ID + UUID에 실제 provider/requested/returned model과 측정 상태를 보존. 중복 정산 불가 | 멱등 terminal update; 정상·오류·늦은 보고 |
| MU-06 | 캐시를 입력에 이중 합산하지 않고 합계 차이·누락을 미확인으로 기록 | measureUsage 대조군; 실제 Gemini 총량 차이 |
| MU-07 | 운영자만 측정 집계를 조회. 금액은 가격표 연결 전 unpriced이며 정확한 잔액으로 표시하지 않음 | 기존 admin 인증의 model-usage GET; 권한 검사 |
| MU-08 | 운영 한도 미설정·원장 장애에서는 새 모델 비교 호출 차단 | 설정 없음 503; 기존 수업 경로 불변 |

## 범위와 남은 엔진 작업

`usage_log`는 기존 역사적 토큰 원장이다. `model_usage_requests`는 새 실습의 호출 허가와
보고 완전성을 보관한다. 기존 #840의 조회 UI를 교체하거나 중복 생성하지 않는다.
이번 제어는 **회차별 요청 시도 한도**이며 금액 또는 토큰 예산의 예약·정산이 아니다.
공급자 간 토큰 합계는 같은 가격을 뜻하지 않는다.

운영자가 `HPS_MODEL_PRACTICE_REQUEST_LIMIT`을 명시해야 새 실습이 열린다(1..10000).
운영 기본값은 없다. 합성 로컬 실기에서는 12회로 검사했다. 기존 수업·체험·토큰을
새 프로필로 자동 이동시키지 않는다. 런타임은 텍스트/HTML이며 SDK 파일·셸·검색 기능은 없다.

#800 후속 완료 기준: 가격 revision과 공급자 청구 대조, 토큰/금액의 원자적 예약,
코호트 공용 예산, 역할별 한도·잔여 UI, 추가 허용과 일시정지, 미정산 요청의 운영 복구.
정산 저장 실패·프로세스 소실 시 pending은 자동 해제하지 않는다. 확인되지 않은 실행을
완료로 간주해 새 유료 작업을 열지 않으며, 이 복구 UI 전에는 일반 사용자용 활성화를
완료로 보고하지 않는다. 사용자 비용 제한 및 공급자 결제는 실제 운영자가 설정한다.

시크릿 등록은 앱 재빌드가 필요 없다. GPT 계정 잔액 부족은 코드에서 우회하지 않는다.
검증 결과: [실행 보고서](../testing/model-access-usage.md).
