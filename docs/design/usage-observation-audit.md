# 사용량 관측 감사와 첫 읽기 화면 (#800)

2026-09-08 · 기반 `f259f24` · REQ-L5 / AE-17/32 / ADM-08의 일부.
Product Intent의 판단에 필요한 정보·주장보다 증거를 운영 사용량에도 적용한다.
학생의 강의료 포함 이용 범위와 플랫폼의 공급자 원가는 다른 계약이다.
이 문서는 가격·추가 결제·보존 정책이나 학생 사용량 순위를 만들지 않는다.

## 코드와 공급자 의미 감사

| 대상 | 확인한 상태 | 구현에 주는 제약 |
|---|---|---|
| `usage_log` | 입력·출력·캐시 읽기/쓰기가 기본 0, 상태와 모델 존재 | 미보고와 확정 0을 과거 행에서 복원할 수 없음 |
| `persistUsage` | 비동기 INSERT, 실패 시 session_id를 NULL로 한 번 재시도, 요청 유일키 없음 | 저장 누락·불확실한 커밋 후 중복·수업 연결 손실을 숫자만으로 배제할 수 없음 |
| `/messages`, `/chat/completions` | SDK 요청과 proxy 내부 재시도의 기록 단위가 다름 | 저장 행 수는 학생 발화 수나 전체 공급자 시도 수가 아님 |
| `/chat/completions` 비스트림 | Anthropic은 캐시 항목을 분리해 저장, OpenAI 형태는 prompt/completion 총량만 저장 | 공급자별 필드 의미와 캐시 상세를 재확인하기 전 통합 적중률 금지 |
| `/admin/cohorts/:id/usage` | 기존 조회에서 cache_write가 빠짐; 최근 N행만 반환 | 캐시 쓰기·조회 범위·시각을 함께 표시해야 함 |
| `usage-report.mjs` | 캐시 쓰기 열은 있지만 합계에서 빠짐; 기존 적중률 분모는 cache_read + tokens_in | 기존 혼합 적중률을 제거하고 네 저장값을 각각 표시 |
| `/admin/stats` | 최근 1시간 입력/출력 및 상태 집계 | 운영 건강 지표이며 완전한 원가/예산 화면으로 해석하지 않음 |
| 가격과 귀속 | D1에 provider, usage schema, 가격 revision, 실제 service tier, cache TTL, 요청/시도 ID, 수업 버전이 없음 | 현재 프로필이나 현재 가격으로 과거 행을 확정 가격 처리하지 않음 |

2026-09-08 실제 열어 대조한 공식 문서:

- [Anthropic prompt caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching): 입력·캐시 읽기·생성은 별도 항목이다. 전체 입력을 구할 때 셋을 합하며 cache TTL별 생성 항목도 구분한다.
- [OpenAI prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching): 입력 총량 안에 캐시 읽기와, 지원하는 새 모델의 캐시 쓰기 상세가 포함된다. Responses 예제를 Studio의 Chat Completions 추출기에 그대로 적용하지 않고 실제 응답 스키마를 대조해야 한다.
- [OpenAI Chat streaming](https://developers.openai.com/api/reference/resources/chat): 중단·취소 시 최종 usage 청크를 받지 못할 수 있다. 정상 종료 여부와 사용량 확인 여부는 별도다.

따라서 단순 필드 합계나 저장된 0에서 정확한 비용을 추론할 수 없다. 현재 구현이
어느 호출을 놓쳤는지의 개수까지 아는 것은 아니다. #799 실기에서 답변 종료 후 SDK
보조 호출을 관측한 사실도 같은 문제를 보여주며, 그 설정 기록은 정산 원장이 아니다.

## 첫 구현 계약 — 운영자 최근 기록

기존 Service 운영자 진단 `/admin/cohorts/:id/usage`와 기존 Admin HTML을 확장한다.
일반 강사 화면은 Chalk가 소유하며 이번에는 새로운 강사 인증 예외를 만들지 않는다.
학생/issuer Bearer는 계속 거부하고, 기존 운영자 인증과 바인딩 SQL을 재사용한다.
DB 쓰기·새 저장소·스키마 변경·App 업데이트는 없다.

- 기존 `usage` 배열은 유지하고 cache_write와 session_missing을 추가한다.
- `observation`은 조회 시각, 최근 N개 범위, 더 이전 행의 존재, 그 범위의 네 토큰 저장값, 오류/오류 중 토큰 기록/0 기록/세션 미귀속 개수를 반환한다. N은 1..500 정수, 기본 50; UI는 30이다. N+1행을 읽어 이전 기록 존재만 확인한다.
- `completeness: unverified`, `cost: {status: unknown, amount: null, reasons}`를 반환한다. 모델 이름으로 provider를 추정하지 않는다. 실패했어도 기록된 토큰은 합계에서 빼지 않는다.
- 빈 조회와 조회 실패는 다르다. 빈 조회는 저장 기록 없음, 실패/잘못된 응답은 HTTP 503이다. 새 UI에 이전 Service의 범위 없는 응답이 오면 확인 불가로 표시한다.
- 화면은 최신 조회 실패 시 이전 성공 숫자를 지운다. 비용·잔여 예산·성취도나 통합 캐시 적중률을 표시하지 않는다. 저장된 문자열은 HTML로 실행하지 않는다. 좁은 화면의 표는 키보드로 좌우 스크롤할 수 있다.
- 기존 CLI 리포트도 cache_write 합계와 기록/오류 정보를 표시하고 통합 적중률을 제거한다. D1 결과에 성공 표시나 결과 배열이 없으면 빈 성공으로 바꾸지 않는다. 자유 SQL이나 원문 조회를 추가하지 않는다.

제거/복구: 이 읽기 응답과 화면·CLI를 이전 버전으로 복귀한다. 저장된 사용량을 수정하거나
삭제할 필요가 없다. 기존 usage 배열을 소비하는 이전 UI는 새 응답의 추가 필드를 무시한다.
새 UI가 범위 없는 응답을 받는 경우에는 미확인으로 남는다.

## 다음 구현 단위 — 계획 상태

1. 기존 usage_log에 gateway request/attempt 식별과 provider·usage-schema·보고 상태를 연결한다. 시작·완료/취소·부분량·미확인·늦은 보고를 구분하고, 동일 시도 재저장과 다른 실제 시도 비용을 구분한다. `usage_request_settings`의 식별자를 재사용할 수 있는지 먼저 대조한다.
2. 공급자/모델/요청 시점/service tier/cache TTL/도구별 요금과 revision이 있는 가격 출처를 하나로 정한다. 정수 금액 단위로 산정하고 미확인 항목과 확정 소계를 따로 둔다. 과거 불완전 기록을 0원 또는 현재 가격 확정으로 소급하지 않는다.
3. 코호트 공용 예산·학생 공정 이용·동시 슬롯을 원자적으로 예약하고 관측량으로 정산한다. 중복·늦은 보고·장애·만료 예약과 상한 초과 노출을 부하 시험한다.
4. 학생에게 수업 포함 상태·자기 범위·시각·추가 허용 요청, 강사에게 자기 반의 실제/예약/미확인·조정 권한, 운영자에게 청구 대조를 제공한다. 요금과 추가 결제는 별도 결정이다.
5. 실제 강의 파일럿에서 분포와 마무리 여유를 측정한 뒤 포함 한도를 정한다. 새 유료 실행을 제한해도 중지·파일·결과·내보내기를 보존한다.

따르며 다른 도메인의 기존 미지정 소유권은 #801에서 다룬다.
