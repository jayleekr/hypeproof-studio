## 1. 사람 기준 흐름 (목표)

1. 강사가 Chalk 면에서 강의를 열고 **"리허설 시작"**(버튼 = 채팅 도구 `chalk_rehearsal_start`)
2. 앱이 서버에 교환권을 요청한다. 연습 세션·로스터 준비는 서버가 리허설 전용으로 처리한다(3절)
3. 앱이 **원래 강사 자격을 `context.secrets` 에 보관**하고, 학생(리허설) 토큰으로 같은 창을 학생 조건으로 바꾼다
4. 화면: 학생 채팅 + **리허설 점검표**(13절 예상 막힘 목록) + **경로 띠**("구독 리허설 · 모델 sonnet · 빠진 장치: 미성년 검사, 길이 제한")
5. 강사가 점검표 항목을 누르면 예상 막힘의 학생 말이 입력창에 들어간다. 보내고 코치 응답을 본다. 항목마다 **알맞음 / 고칠 것**(+ 메모)을 표시한다
6. **"리허설 끝내기"** → 앱이 보고서(스택 형식 + 점검 결과 + 경로)를 서버에 보낸다 → 판정 → **강사 자격으로 복귀**
7. 앱을 리허설 중에 닫았다 켜면: 보관된 강사 자격이 있고 리허설 좌석이 남아 있으면 "리허설을 이어갈까요 / 끝내고 돌아갈까요"를 묻는다. 끝내면 강사 자격으로 복귀한다
8. 판정이 통과면 Chalk 면에 **"확정"** 버튼 → 확정 서명. 확정 기록에 경로와 빠진 장치가 남는다

## 2. 경로 두 가지와 판정

| | 서버 경로 리허설 | 구독 리허설 |
|---|---|---|
| 모델 호출 | 앱 → 서버(`/v1/messages` 또는 `/v1/chat/completions`) | 앱 → 강사 컴퓨터 CLI(`localRuntime`) |
| 코호트 지시문 | 서버가 넣음 | **서버 조립 함수로 내려받아 넣음**(E6-7, `buildAnthropicSystemBlocks`) |
| 미성년 모더레이션·길이 제한 | 걸림 | **안 걸림** → 경고 + 기록 |
| 요청 기록 | 서버가 직접 봄(`authoring_rehearsal_turns`) | **앱이 올림**(E4-7 `POST /admin/chalk/transcripts`, `rehearsal_id` 포함) |
| 확정 근거 | 됨 | **됨**(결정 8 (나)) |

### 2-1. 판정 규칙 변경 (E6-6)

스택 `judgeRehearsal()` 의 구조 검사(단계·도움·화면·미션·도구 경계)는 **두 경로 모두 그대로** 쓴다. 바꾸는 것은 "요청 기록" 부분 하나다.

| 스택 규칙 | 바뀐 뒤 |
|---|---|
| `completed` **서버** 요청 ≥1, 없으면 `no_completed_request` | 서버 요청 **또는 앱이 올린 구독 턴**(같은 `rehearsal_id`·같은 lesson sha) ≥1 |
| 서버 요청에 `step_id` 없으면 `step_not_sent` | 구독 턴도 `step_id` 를 가져야 한다(앱이 턴마다 현재 단계를 붙인다) |
| 보고서 제출 시 서버 요청 0건이면 409 (`no_completed_request`) | 서버 요청 + 구독 턴 합이 0이면 409 (`no_request_yet`) |
| 도구 경계 검사(`agent-sdk` 만) | 구독 턴은 앱이 올린 도구 이름으로 같은 검사 |
| — | **새 검사 `checklist`**: 13절 예상 막힘이 있는 강의면 모든 항목에 표시(알맞음 / 고칠 것)가 있어야 한다. 표시가 빠지면 `checklist_incomplete` 로 실패. "고칠 것"이 있어도 판정은 통과할 수 있다 — 아래 2-2 |

### 2-2. "고칠 것"은 판정을 막나

- **막지 않는다.** 점검표는 강사의 판단 기록이고, 확정 여부도 강사가 정한다. "고칠 것"이 남아 있으면 확정 화면에 "고칠 것 N개가 남았습니다"를 보이고, 강사가 확정을 누르면 확정 기록에 그 목록이 남는다
- 이유: 판정을 모델이나 규칙이 막는 것은 강의 퀄리티 게이트(후속)의 일이다. 이번 범위는 흐름을 만드는 것이다(PRD 7판)

### 2-3. 확정 기록

스택 `authoring_confirmations` 에 칸을 더하거나(마이그레이션, 번호 리드 배정) 옆 테이블을 둔다(E6-6 에서 정함). 남길 것:

```json
{ "rehearsal_path": "subscription" | "server",
  "connection": "claude-sub" | "codex-sub" | "server",
  "model": "…",
  "missing_safeguards": ["minor_moderation", "minor_max_tokens"],   // 구독 경로면
  "checklist": { "total": 3, "ok": 2, "fix": 1, "fix_items": ["st-2"] } }
```

- 확정 화면과 확정 뒤 강의 상세에 "구독 리허설로 확정 · 빠진 장치: 미성년 검사, 길이 제한"이 보인다(PRD 결정 8 7판)

## 3. 준비를 줄인다 — 연습 세션·로스터

스택 교환권은 **열린 연습 세션 + 로스터에 등록된 리허설 학생 ID** 가 있어야 나온다(`authoring.ts:335-339`). 강사가 매번 세션 콘솔에서 이것을 하게 두면 흐름이 끊긴다.

| 안 | 내용 | 판단 |
|---|---|---|
| A | 교환권 도구가 필요하면 리허설 전용 연습 세션을 열고 리허설 ID 를 로스터에 넣는다(기존 세션 시작·로스터 API 를 서버 안에서 부름) | 🔴 **실제 수업 세션과 코호트를 공유한다.** 진행 중인 수업이 있으면 세션을 덮을 수 있다 → 쓰지 않는다 |
| B | 리허설 좌석은 세션·로스터 검사를 우회한다(닫힌 스택 방식: 게이트에서 `rehearsal` 토큰이면 가상 세션) | 학생 경로 게이트(`chat-gate.ts`)를 바꾼다. 스택 머지 뒤, 스택이 바꾼 파일. **서버 경로 리허설에만 필요** |
| C | 구독 리허설은 서버 게이트를 지나지 않으므로 세션·로스터가 필요 없다. 교환권 발급 조건만 "구독 리허설"일 때 세션·로스터를 요구하지 않게 한다 | 결정 8 (나)의 기본 경로가 구독이므로 **이것이 먼저다** |

- **결정(리드 기본값)**: C 를 먼저 한다(E6-2). 서버 경로 리허설의 준비 축소(B)는 스택 머지 뒤에 따로 판단한다. 그때까지 서버 경로 리허설은 스택 방식(세션·로스터 필요)을 그대로 쓴다
- 교환권에 `path: 'subscription' | 'server'` 를 싣는다. `subscription` 교환권으로 서버 대화 경로를 부르면 거부한다(구독이라고 해 놓고 서버 모델을 쓰는 것 방지)

## 4. 자격 보관과 복귀 (RH-04)

- 리허설 시작 때: 원래 강사 자격(issuer 토큰)을 `context.secrets` 의 **별도 키**(`chalk.rehearsal.returnIssuer`)에 넣는다. `globalState`·`workspaceState` 에는 넣지 않는다(토큰이다)
- 학생(리허설) 토큰을 `TOKEN_KEY` 에 넣는다(스택·기존 앱 방식)
- 끝낼 때: 보고서를 보낸 뒤 `TOKEN_KEY` 를 지우고 보관한 강사 자격으로 돌아간다. 보관 키를 지운다
- 앱을 켤 때: 보관 키가 있으면 리허설 중에 닫힌 것이다 → 1절 7번대로 묻는다. 리허설 토큰이 만료됐으면 묻지 않고 복귀한다
- 🔴 보관 키가 있어야만 구독 리허설이 열린다(E4-1 §2-1 리허설 좌석 예외). 학생이 받은 일반 코드로는 이 경로가 절대 열리지 않는다
- 부정 대조: 리허설 중 강제 종료 → 재시작 → 복귀까지(Playwright `_electron` 으로 자동화 가능, T0-a 발견)

## 5. 스택이 main 에 없어도 (나) 흐름을 만들 수 있나 (R5)

**가능하다. 다만 스택과 겹치는 테이블·판정을 두 벌 만들게 된다.**

| 선택지 | 내용 | 비용 |
|---|---|---|
| ① 기다린다 | E6-2~7 을 스택 머지 뒤에 착수 | 스택이 늦으면 M4 가 밀린다 |
| ② main 에 최소 구조 | 구독 리허설만: 교환권 대신 "리허설 세션 ID"(서버 발급) + 앱이 올린 턴(E4-7) + 점검표 + 판정(구조 검사 없이 턴 ≥1 · 점검표 제출) + 확정 기록 | 스택 머지 때 스택 교환권·판정·확정으로 **옮기는 이행 작업**이 생긴다. 확정 기록 테이블이 둘이 될 위험 |
| ③ 스택 꼭대기 위에서 | 스택 브랜치를 base 로 PR | 스택 PR 이 바뀌면(리뷰 반영) 계속 rebase. 우리 PR 을 스택보다 먼저 머지할 수 없다 |

- **리드 권고: ① 을 기본으로 하되, M2 끝에 스택이 머지되지 않았으면 ② 를 JY 에게 올린다.** ② 를 고를 경우 조건: 확정 기록은 스택 `authoring_confirmations` 와 **같은 모양**으로 만들어 머지 때 합칠 수 있게 하고, 이행 작업을 별도 sub-issue 로 plan 에 넣는다
- 이 판단은 plan §8 "⏸ M2 → M3" 보고에 싣는다

## 6. 채팅 도구 (E2-1 §1 에 더함)

| 도구 | 하는 일 |
|---|---|
| `chalk_rehearsal_start` | 교환권 요청(`path`) → 자격 보관 → 학생 조건 전환 |
| `chalk_rehearsal_checklist` | 13절 예상 막힘 목록과 현재 표시 상태 |
| `chalk_rehearsal_mark` | 항목 하나에 알맞음 / 고칠 것 + 메모 |
| `chalk_rehearsal_finish` | 보고서 제출 → 판정 → 복귀 |
| `chalk_confirm` | 확정 서명(통과한 최신 리허설) |

- 🔴 학생 조건으로 바뀐 동안에는 **강사 모드 도구가 AI 에 붙지 않는다.** 리허설 중의 AI 는 학생 코치다. 리허설 도구는 앱 화면(점검표 패널)과 버튼으로만 조작하고, 채팅은 학생 대화로만 쓴다. 리허설 전·후의 강사 채팅에서만 `chalk_rehearsal_*` 을 부를 수 있다
