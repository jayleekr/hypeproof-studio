# 모델의 effort와 강의료에 포함된 AI 사용량

2026-09-08 사용자 질문을 반영한 **후속 설계 제안**. 모델 선택 #792와 구분하며,
effort 구현 계약은 아래 #799 절에 기록한다. 예산 원장·과금 기능은 계속 제안 상태다.
정본 [Product Intent](../PRODUCT-INTENT.md)의 판단에 필요한 정보·최소 개입과
[INT-AE-05/07](learning-agent-experience.md)을 AE-17/27/28/32에 연결한다.

## 현재 구현에서 출발할 지점

`worker/src/lib/analytics.ts`의 `usage_log`는 모델·입력/출력·캐시 읽기/쓰기·지연·상태를
기록하며, 실패했어도 실제 토큰을 사용한 요청은 집계한다. `/admin/stats`와
`/admin/cohorts/:id/usage`는 운영 조회 경로다. 확장의 `chatPanelProvider.ts`도 SDK/proxy
사용량과 SDK가 보고한 턴 비용을 관측 기록에 남긴다. 현재 학생 ChatPanel에는 강의료에
포함된 잔여 이용량 화면이 없다. 이 로그가 있다고 예약/정산·정확한 비용·역할별 예산 화면이
완성된 것은 아니다. 저장 실패와 미확인 사용량, 가격표 revision부터 대조해야 한다.

## 결정 제안

모델은 어떤 AI를 쓸지, effort는 지원 모델에서 한 요청에 들일 작업량을 조절한다.
둘 다 높게 설정했다고 결과가 정확하거나 학습이 깊어졌다고 판단하지 않는다.
강사가 수업 기본값·변경 허용·상한을 정하고 학생은 허용된 범위에서 바꾼다.
RBAC은 설정 권한, 수업 정책은 모델/effort/예산, 교수법은 도움 시점을 각각 소유한다.

학생 입력창에는 모델과 작은 effort 제어를 둔다. 첫 상태는 강사 기본값이며 선택을
요구하는 온보딩은 만들지 않는다. 사용자 피드백(2026-09-08)에 따라 제어 이름은
`Effort`, 단계는 `Low / Medium / High`로 표기한다. 전송값과 일대일 대응하며
임의의 속도·학습 깊이 의역을 붙이지 않는다. `max`는 기본 학생 메뉴에 노출하지 않는 안을 먼저 검증한다.
같은 문구가 다른 모델에서 같은 토큰 수·속도·정확도를 보장하지 않는다.

OpenAI 공식 [모델 선택 화면](https://learn.chatgpt.com/docs/models)도 `Low`,
`Medium`, `High`와 모델별 추가 단계를 사용한다. `Low`의 빠른 응답 설명은
별도 단계명이 아니며 `mid` 대신 `medium`을 사용한다. 공급자·모델별로 가능한
추가 단계와 Service/SDK 지원을 확인한 뒤 수업 정책에서 허용한다. 현재 #799는
Anthropic의 수업 허용 low/medium/high 범위이고 GPT effort 전달 구현을 뜻하지 않는다.

지원하지 않는 모델에는 조작 가능한 effort 메뉴를 보이지 않고 이유를 상세에 표시한다.
Haiku 4.5/Sonnet 4.5의 manual thinking budget과 effort를 같은 기능으로 취급하지 않는다.
모델 변경 시 유효한 설정으로 재평가하며 변경 사유를 보이고 다음 요청부터 적용한다.
학생이 선택한 설정을 Gateway가 정규화했으면 실제 적용값·이유를 기록하고 UI에 반환한다.
현재 SDK 호환 정규화 로그만으로 이 요구사항이 완료된 것은 아니다.

모델별 차이는 공식 [effort](https://platform.claude.com/docs/en/build-with-claude/effort),
[thinking](https://platform.claude.com/docs/en/build-with-claude/extended-thinking?q=thinking),
[Sonnet 5](https://platform.claude.com/docs/en/models/sonnet-5/overview),
[Opus 5](https://platform.claude.com/docs/en/models/opus-5/overview) 문서와 Models API를
대조한다. 예를 들어 Opus 5는 thinking을 끌 때 effort를 high 이하로 제한한다.
공식 기능 지원, 해당 계정에서의 API 접근, Studio SDK/도구 실기를 별도 증거로 남긴다.

## 사용량을 보는 세 사람

강의료에 AI 이용이 포함돼 있으므로 학생의 잔여 이용량과 운영자의 공급자 원가는
같은 숫자가 아니다. 강의료·환불·추가 결제를 이 제안으로 변경하지 않는다.

| 대상 | 기본 화면 | 상세와 할 수 있는 일 |
|---|---|---|
| 학생 | 입력창 근처 ‘수업에 포함됨’. 정상일 때 작은 상태, 부족해질 때만 안내 | 자기 이용 범위·남은 상태·갱신 시각. 큰 작업의 예상 범위와 예상치임을 표시. 강사에게 추가 허용 요청. 다른 학생 사용량·기관 원가 비공개 |
| 강사 | 현재 반의 누적 사용·예약 중 사용·수업 종료까지의 예상·이상 소진 학생 | 학생별 한도와 공용 예산, 모델/effort/재시도 원인별 분해. 권한 안에서 추가 허용·새 작업 일시정지. 원문 대화를 기본 수집하지 않음 |
| 운영자 | 강의/기수별 실제 변동 원가와 예산 대비 차이 | 모델·캐시·보조 호출·브라우저/컴퓨터 환경별 비용. 강의료 대비 기여이익 분석, 미정산 사용량·공급자 청구와의 대조 |

학생에게 토큰을 현금 잔액처럼 표시하지 않는다. 내부 비용을 정산한 뒤 수업의 이용
한도로 환산한다. 학생용 ‘크레딧’을 도입한다면 정의·유효기간·모델별 차감·가격표 revision을
먼저 정해야 한다. 환산 규칙 없는 숫자나 모델별 단가가 다른 단순 토큰 합계는 피한다.
정상 상태를 매 답변의 비용 배지로 반복하지 않고, 상세는 사용자가 열어 확인하게 한다.
사용량의 많고 적음을 성취도나 학생 순위로 표시하지 않는다.

## 원장과 수업 운영

기존 `usage_log`와 요청/시도 ID를 먼저 재사용한다. 예약·정산·동시성 기능을 새로
만들기 전에 AE-17과 기존 이용 한도 계약을 조사한다. 대시보드의 별도 집계가 원장이 되지 않는다.

- 원가 계산은 실제 provider/model, 일반 입력·캐시 읽기·캐시 쓰기·출력, 적용 가격표 revision을 보존한다. 공급자의 필드 의미에 맞춰 캐시를 중복 계산하지 않는다.
- 재시도·취소·실패·subagent·보조 요청도 실제 발생분을 정산한다. 보고 누락은 ‘미확인’으로 남기고 0원으로 확정하지 않는다.
- 실행 전 보수적으로 예산을 예약하고 확정 사용량으로 정산한다. 한도 검사를 통과한 동시 요청이 예산을 여러 번 쓰지 못하도록 원자성과 멱등성을 검증한다.
- 기관/기수의 공용 예산과 학생별 공정 사용 한도를 함께 둔다. 남은 예산이 있어도 한 학생이 모든 실행 슬롯을 점유하지 못한다.
- 부족 경고 → 강사 조정/작업 범위 축소/허용된 저비용 설정 선택 순서로 안내한다. 강제 모델 교체나 자동 추가 결제는 하지 않는다.
- 한도 도달 시 새 유료 작업을 제한하더라도 진행 중 작업의 중지·파일 보존·결과 열람·내보내기는 가능해야 한다. 수업을 마무리할 여유 예산과 상한의 잔여 노출을 운영 정책으로 정한다.
- 브라우저 자체의 모든 행위를 별도 과금하지 않는다. 실제 발생하는 모델 도구 토큰, 검색/도구 공급자 요금, 격리 환경의 실행 시간·저장 비용을 원가 항목별로 집계한다.

회차별 포함 예산/학생 배분은 실제 파일럿의 사용량 분포·수업 길이·동시 인원·재시도율로
결정한다. 현재 자료만으로 강의료에 얼마를 포함해야 하는지 또는 마진을 확정하지 않는다.
평균 외에 상위 사용 구간과 장애 재시도 비용을 따로 관측한다.

## 기존 에픽에서 진행할 순서

중복/늦은 정산·여러 학생 동시 실행, 역할별 비공개, 한도 후 산출물 보존까지 필요하다.
화면 캡처나 모델 API 200만으로 예산·수업 운영 인수를 완료하지 않는다.

기준의 change-impact registry 등록과 도메인 담당 합의는 #801에서 추적한다.
이번 문서의 작성자를 기준의 권한 소유자로 자동 등록하지 않는다.

## 수업 effort 구현 계약 (#799)

REQ-M40은 Product Intent의 판단 가시성·최소 개입·주장보다 증거를 구현한다.
학생이 목적에 맞는 위임 수준을 선택하고 바뀐 조건을 확인할 기회를 제공한다.
선택 자체를 Delegate/Judgment 자산 향상이나 학습 성과로 판정하지 않는다.

- Service 기존 `model-caps`와 모델 카탈로그에서 지원 값을 파생한다. 성인
  `studio-native-trial`만 medium 기본, low/medium/high opt-in을 추가한다.
  다른 코호트나 미성년 수업의 기본값을 바꾸지 않는다.
- Module의 기존 `model` 안에 선택적 `effort: {default, allowed}`를 넣는다.
  Chalk에서 코호트 기본값 사용·강사 고정·학생 선택을 정하며, 모델 정책을
  명시한 수업에서만 effort를 따로 고정한다. Service의 저장/동결/읽기 검증과
  `binding.effort` revision이 허용 범위를 재검사한다. 기존 effort 없는 frozen
  binding은 형태를 유지하고 현재 코호트 기본값을 상속한다.
- App은 다음 턴의 설정을 시작 때 한 번 잡는다. SDK `Options.effort`와 전용
  요청 헤더, proxy 헤더를 사용하며 Gateway는 실제 모델 기준으로 최종 값을
  결정한다. 지원하지 않는 모델의 effort는 미지원으로 기록한다. 허용 범위 밖
  헤더는 403, 헤더 없는 이전 앱은 수업 기본값이다. 메시지별 override는 제거한다.
- 입력창과 Chalk에 `Effort: Low / Medium / High`, 상세에도 같은 영문 단계로 적용 기록을 둔다. 같은 표현이 모델 간
  같은 비용·속도·품질을 보장하지 않는다. 기록은 다음 요청 선택과 구분하며
  실패/지연/빈 조회는 미확인이다. 모델 변경 시 이유와 기본값 복귀를 알린다.
- SDK가 Gateway 응답 헤더를 노출하지 않으므로 같은 D1에
  `usage_request_settings`를 추가한다. 기존 `usage_log`는 비용 원장으로 남고
  새 테이블에는 UUID·수업/학생/턴 식별·실제 모델·요청/전송 effort·이유·상태·시각만
  넣는다. 대화 원문·키·토큰·원가 합계를 복제하지 않는다. 기존 인증 게이트를 거친
  `GET /v1/request-settings/:turn`은 본인과 정확히 같은 수업 버전 범위만 읽는다.
  최대 100건과 잘림 표시를 반환한다. 기록 실패는 대화를 막지 않고 미확인으로 남는다.
  보존/삭제 정책을 변경하지 않는다.

설정 기록은 Gateway 요청 단위다. proxy 내부 재시도의 전체 시도 원장이나 비용
정산 완료를 뜻하지 않는다. 공급자 전달 전 연결 실패도 실패 상태로 남을 수 있다.
SDK 보조 요청은 전달된 턴 ID가 있는 경우 함께 보인다. 모든 보조 호출이 확인됐다는
총량 보증은 #800에서 별도로 검증한다.

배포는 Service migration 0005 → Service → Chalk → App 순서다. 되돌릴 때 데이터는
삭제하지 않고 이전 코드로 복귀한다. 이전 Service는 새 effort 수업 schema를 모르므로
새 수업 발급을 멈추고 이전 버전/코드로 되돌리는 조치가 필요하다. 배포 전 실제 실행
결과와 미실행 플랫폼은 [검증 기록](../testing/lesson-effort.md)에서 확인한다.


#799 실행에서 SDK 보조 요청이 답변 종료 뒤에 도착하는 것을 관측했다.
[35건 실기와 화면 증거](../research/agent-experience-acceptance-2026-09-08/course-effort/README.md)는
설정 적용 인수이며, #800에서는 이를 턴 종료 시점의 비용 확정 근거로 쓰면 안 된다.
모델/effort 선택 복원은 성인 체험의 기존 Service 관찰 scope를 재사용해 학생·세션을
가로지르지 않는다. 200% 확대에서 전송 버튼이 밀린 관측은 접힌 카드 여백과 스크롤
접근을 수정하는 근거가 됐다. 기술 인수와 강사/학습자 파일럿을 구분한다.
