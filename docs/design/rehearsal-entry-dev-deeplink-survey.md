# 리허설 입구 — Dev 딥링크 실측 (#1189 1단계)

2026-09-21. 측정자: 에이전트 세션. 기기: 이 Mac, 공식 설치본 **0.1.56**.

**이 문서는 설계가 아니라 측정 기록이다.** `#1189` 가 "코드를 쓰기 전에 재라" 고 요구한
1단계의 결과이고, 그 결과로 **D안(딥링크 없이 앱 안에서 학생 조건으로 전환)** 이 선택됐다.

## 🔴 이 문서를 읽는 법 — 세 구역의 구분이 이 문서의 값이다

- **§1 띄워서 잰 것** — 앱을 실제로 기동하고 OS 에 물어서 얻은 값
- **§2 못 잰 것** — 시도했고 **실패했으며, 원인이 제품이 아닌 것**
- **§3 읽어서 안 것** — 소스·번들을 읽어서 안 것. 실행으로 확인하지 **않았다**

**§2 를 §1 로 읽지 마라.** §2 는 "제품이 고장났다" 가 아니라 "이 계측기로는 못 쟀다" 이다.
구분을 지우고 표만 옮기면 다음 사람이 정확히 그 오해를 한다.

## §1 띄워서 잰 것

| # | 질문 | 방법 | 결과 |
|---|---|---|---|
| 1 | Dev 앱이 URL 스킴을 등록하나 | `studio-dev.py` 로 빌드·기동 후 `NSWorkspace.URLForApplicationToOpenURL` | **등록 안 됨.** `Info.plist` 에 `CFBundleURLTypes` 자체가 없다(PlistBuddy: *Does Not Exist*) |
| 2 | 앱이 **떠 있으면** 런타임에 등록되나 | 기동 **전·후** 두 번 조회(대조군) | **변화 없음.** Electron `setAsDefaultProtocolClient` 는 이 경로에서 안 탄다 |
| 3 | `open` 으로 부르면 | `open hypeproof-studio-dev-<hash>://…` 실행 | **`kLSApplicationNotFoundErr` (-10814), exit 1** |
| 4 | Dev 가 공식 스킴을 가로채나 | Dev 기동 중 `hypeproof-studio://` 조회 | **가로채지 않는다.** `/Applications/HypeProof Studio.app` 유지 — 런처의 격리는 지켜진다 |
| 5 | `--open-url` 이라는 CLI 전달 경로가 있나 | Dev·공식 CLI `--help` 전수 | **없다. 둘 다 미지원.** ⚠️ 이 플래그를 주면 **`exit 0` 이 나오는데 그것은 모르는 플래그를 무시한 것**이다 — 성공으로 읽으면 안 된다 |
| 6 | 스킴이 이미 겹치나 | `lsregister -dump` 전수 | `hypeproof-studio:` 를 **5개 번들이 주장**한다: 설치본 · repo 빌드출력(`vscodium-base/VSCode-darwin-arm64`) · 다른 세션의 e2e 내려받기 사본 · **휴지통의 0.1.37** · Helper (Plugin) 하위번들. 현재는 `/Applications` 가 이긴다 |
| 7 | **런처를 고치면 등록되나** | Dev plist 에 `CFBundleURLTypes`(**Dev 전용** 스킴)를 되살리고 ad-hoc 재서명 → `lsregister -f` | **된다.** LaunchServices 가 Dev 앱으로 해석한다. 그리고 **공식 스킴은 영향 없다** — 스킴 문자열이 다르므로 충돌이 생기지 않는다 |
| 8 | 확장이 Dev 에서 살아 있나(양성 대조군) | exthost 로그 | **산다.** `_doActivateExtension hypeproof.hypeproof-chat` 확인 |

7번이 중요하다: **`CFBundleURLTypes` 제거의 이유가 "공식본과 스킴이 겹쳐서" 는 아니다.**
런처는 이미 `urlProtocol` 을 `hypeproof-studio-dev-<체크아웃해시12>` 로 **다르게** 바꾼다.

## §2 못 잰 것 — 원인은 제품이 아니라 계측기다

**7번까지 해도 URL 이 앱 안 핸들러에 도달하는 것은 확인하지 못했다.**

`#1180`(`feat/1132-rehearsal-uri-handler`) 코드로 Dev 를 빌드하고, 관측용 프록시
(127.0.0.1:8795 — 자가시험으로 살아 있음 확인)를 물린 뒤 딥링크를 보냈다. 요청이 오지 않았다.
기동 방식을 둘(실행파일 직접 / `open -a --args`) 다 시도했다.

**그러나 이것을 제품 결함으로 읽으면 안 된다.** 확장이 전혀 필요 없는 core URL
(`…://file/<경로>`)을 **양성 대조군**으로 보냈더니 **그것도 앱에 닿지 않았다.**
→ **OS→앱 전달 채널 자체가 이 ad-hoc 재서명 사본에서 동작하지 않는다.** 계측기의 한계다.

그러므로 **"`#1180` 의 핸들러가 Dev 에서 동작하는가" 는 이 측정이 답하지 못했다.**
그 브랜치가 스스로 적어 둔 한계 — *"라우팅을 잰 것이지 이 핸들러를 잰 것이 아니다"* — 는
**아직 그대로 남아 있다.**

### 계측기가 두 번 틀렸던 기록 — 이 문서에서 가장 값있는 부분

URL 을 짐작해서 만들었고, 두 군데가 틀렸다:

| 짐작 | 실제 | 결과 |
|---|---|---|
| 경로를 `/rehearsal` 로 | **`/rehearse`** (`rehearsalEntryHelpers.ts` `REHEARSAL_URI_PATH`) | `wrong_path` 로 파싱 거절 |
| 교환권을 `probe-cli` 로 | **`^[A-Za-z0-9_-]{16,256}$`** 를 만족해야 함 | `malformed_ticket` 으로 거절 |

둘 다 **경고만 띄우고 네트워크 호출을 하지 않는** 갈래다. 즉 프록시에 아무것도 안 온다 —
그리고 그것이 **"제품이 안 된다" 로 읽힐 뻔했다.** 실물(`rehearsalEntryHelpers.ts`)을 읽고 고쳤다.
`.claude/rules/verification.md` 규칙 1 그대로다: **판정 기준을 세우기 전에 대상을 열어본다.**

## §3 읽어서 안 것 (실행으로 확인하지 않았다)

- `origin/main` 에 URI 핸들러가 **없다.** `#1180` 은 열린 PR 이다
- 출하 0.1.56 의 번들 확장에 `registerUriHandler` **0건**, `uriHandler` contribution 없음.
  다만 `github-authentication` · `git` 등 **다른 내장 확장은 등록한다** →
  공식본에서 OS→앱→확장 기계 자체는 살아 있다(우리 확장만 그 자리에 없었다)
- `scripts/studio-dev.py` `configure_copy()` — `urlProtocol` 을 Dev 값으로 바꾸면서
  `CFBundleURLTypes` 를 **제거**한다. 둘이 어긋난 상태다: **앱은 자기 스킴이 있다고 믿는데 OS 는 모른다**
- `bin/hypeproof-studio` CLI 스크립트 이름은 Dev 에서도 **공식본 이름 그대로**다

## §4 결론과 그것이 설계에 한 일

1. **런처가 만든 Dev 앱에는 딥링크를 전달할 경로가 없다.** OS 경로는 미등록(§1-1·3),
   CLI 경로는 **존재하지 않는다**(§1-5).
2. **런처를 고치면 OS 가 Dev 로 해석하게는 만들 수 있다**(§1-7). 공식본과 충돌하지 않는다.
3. **그러나 거기까지 가도 전달이 되는지는 여기서 못 쟀다**(§2).

→ 즉 **딥링크를 유지하는 안은 "Dev 에서 검증 가능한지" 자체가 불확실**하다. 되는지 모르는 채로
만드는 일이 남는다. **D안(앱 안 전환)은 그 불확실성을 우회하는 것이 아니라 제거한다** —
URL 이 없으면 §1·§2 전체가 무효가 된다. 이것이 D 를 고른 첫 번째 근거다.

## §5 이 측정이 기기에 남긴 것 (전부 되돌렸다)

Dev 사본 2개(각 490MB) 삭제 · 등록한 Dev 스킴 `lsregister -u` 해제 · 관측 프록시 종료(8795 해제) ·
임시 worktree 제거. 런처가 `official_app_unchanged: true` 로 검증하며, 측정 후 **공식본이 여전히
`hypeproof-studio:` 를 소유하는 것**과 **실행 중이던 공식 앱을 죽이지 않은 것**을 확인했다.
프로덕션 접촉 없음.
