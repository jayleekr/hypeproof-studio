## 채팅과 멀티모델에서의 구체 변화

AI 이름을 바꿀 수 있게 하는 이유는 수업에서 맡는 역할을 명확히 하기 위해서다.
질문하는 튜터, 함께 만드는 파트너, 읽기 검토자 등 도움 방식은 과제에 맞게 정하되,
특정 이름/모델이 교사의 권위나 실제 도구 권한을 대신하지 않는다.

모델 비교의 성공은 “더 좋은 모델을 골랐다”가 아니라 어떤 근거를 믿고 무엇을 보류했는지
학습자가 설명하는 것이다. “둘 다 아직 채택하지 않기”, 사람에게 검토 요청하기도 유효한 선택이다.
모델의 두 번째 의견은 인간 peer critique를 수행한 것으로 기록하지 않는다.

검증 자동화 뒤에도 사실/한계·확신·미검증 위험에 대한 최종 판단이 남아야 한다.
자동 반복 횟수보다 어떤 피드백 기준으로 방향을 바꿨는지 본다. 과제에 불필요한 추가 승인이나
강제 설명을 매번 요구하지 않고 기존 발화·선택을 재사용한다. 필요한 도움과 접근성을 유지한다.

## Epic #746 적용과 완료 경계

E1은 목표·추천·학생 선택과 AI 역할의 구분, E2는 선택 가능한 도움/권한 환경,
E3는 문맥·결과·판단 기록의 재개와 소유, E4는 최신 검수 근거와 한계,
E5는 인간 피드백·전이·퇴화 가능성 관찰, E7은 근거 기반 모델 비교에 연결한다.
E6는 실제로 필요한 웹 밖 과제의 별도 실험 지위를 유지한다. 새 에픽이나 제품을 추가하지 않는다.

P0 30개 행과 첫 성인 L2 경로는 유지한다. AE-43/44와 AE-T37/38은 D5의 P1 연구/사회적
교정 범위다. 기존 수업 공유/관찰 계약을 우회하는 자동 원문 수집이나 새 학습자 등급을 만들지 않는다.
동의된 사람 관찰·전이 검증이 없으면 기술 시나리오가 통과해도 학습 효과는 NOT RUN/미확인이다.

다음 원본 개정에서는 이 문서의 pin과 관련 절의 의미를 비교하고 영향받는 Intent·AE·테스트를
갱신한다. 연구 결과가 기존 자산 가설과 맞지 않으면 결과를 숨기거나 Studio만의 정의를 만들지 말고
출처와 한계를 포함해 Lab의 가설 수정 입력으로 남긴다.
