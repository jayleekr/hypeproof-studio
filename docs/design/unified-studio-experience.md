# 하나의 Studio에서 체험과 수업 이어가기

2026-09-10 · [Intent/Epic #915](https://github.com/jayleekr/hypeproof-studio/issues/915)
상태: Intent·설계 발행안. 신규 UX·전환·자동 릴리스 게이트는 구현 전이다.
제품 책임: Jay (`jayleekr`). 기존 `products.yaml`의 App/Service owner `jay`에 연결한다.
문서 작성자에게 새 권한을 부여하거나 기존 미지정 traceability owner를 일괄 변경하지 않는다.

상위: [Product Intent](../PRODUCT-INTENT.md), [NAT](../requirements/studio-native-trial.md),
[AE](../requirements/learning-agent-experience.md), [이용 권한 AB](../requirements/access-budget-settlement.md).
제품 전략의 부모는 Lab [제품 라인업](https://github.com/jayleekr/hypeprooflab/blob/a4fe9be03dcb8890b42e1020dc4d357687f82acc/products/PRODUCT-LINEUP.md)의 Studio 사용자 제품 역할이다.
새 체험 제품이나 별도 강사 제품을 만드는 Intent가 아니다.
철학과 후보 역량 정의는 상위 문서가 참조하는 Lab 원본을 따른다. 여기의 Product Intent는
Human Asset `INTENT`를 평가하는 검사나 강제 질문 절차가 아니다.

## 문제와 확인한 기반

체험과 수업은 같은 App을 사용하지만, 로컬 리허설을 위해 만든 앱 사본·바로가기·개발 서버가
사용자용 체험처럼 남았다. [#911](https://github.com/jayleekr/hypeproof-studio/issues/911)에서
일반 설치·실행 중 체험·바로가기 대상의 버전이 달랐음을 확인했다.
[#912](https://github.com/jayleekr/hypeproof-studio/pull/912)는 같은 설치본 사용과 전달 확인을
문서화했다. 그 문서와 다운로드 완료는 실제 업데이트·공개 서버 전환의 완료 증거가 아니다.

조사 기준: main `928b7dd`.

| 확인한 구현 | 이 설계에서 재사용할 것 | 아직 입증하지 못한 것 |
|---|---|---|
| `StartPage.tsx`, `startPage.ts`, `startPageProtocol.ts` | 참여 코드 확인, 프로그램 소개, 시작·재연결, 실패 시 이전 코드 복원 | 활동 목록·복수 활동 재개·원자적 전환 |
| `workspaceRouting.ts`, `workspacePreparation.ts`, `sessionSpool.ts` | 작업 폴더 준비, 실행 기록·세션의 기존 경계 | 전환·크래시·동일 폴더 충돌에서 모든 경로의 격리 |
| Service profile/native-trial/access-budget 계약 | 인증·참여·기간·사용량·비용 출처 검증 | 코드 없는 공개 체험 가입 UX와 운영 정책 |
| 공통 release/updater, native trial fixture/manifest | 하나의 산출물 배포, 검증 모드·번들 해시 기록 | 두 활동과 각 지원 OS를 막힘 없이 검사하는 자동 공개 승격 게이트 |

확인한 것은 소스와 #911의 제한된 로컬 관측이다. 이 표를 신규 US 테스트의 PASS로 옮기지 않는다.

## Product Intent

> 사용자는 하나의 Studio에서 AI 체험과 수업을 선택하고, 자신의 대화와 결과물을 잃지 않고
> 이어간다. 어떤 앱이나 서버를 열어야 하는지 판단할 필요가 없어야 하며, 제품 개선은
> 체험과 수업에 함께 전달되어야 한다.

| ID | 사용자에게 제공할 경험 | 상위 원칙 | 관측과 반증 |
|---|---|---|---|
| INT-US-01 | 한 설치본·한 시작 화면에서 원하는 체험 또는 수업을 시작한다. | Useful work first, Minimum necessary intervention | 처음 온 사용자가 별도 앱·커맨드 팔레트·개발 서버 선택 없이 유효한 활동에 도달한다. 코드/권한 부재를 숨긴 시작 버튼, 잘못된 수업 진입은 반증이다. |
| INT-US-02 | 활동을 바꾸고 돌아와도 자기 작업을 이어간다. | Ownership를 지키는 실제 작업, Human judgment stays visible | 이전 대화·초안·파일을 다시 열고 어느 활동의 작업인지 안다. 파일 손실, 다른 활동 문맥·도구·권한 유입, 자동 공유는 반증이다. |
| INT-US-03 | 현재 활동과 도움·실행 범위·사용량을 이해하고 선택한다. | Human judgment stays visible, Minimum necessary intervention | 다음 실행이 어느 활동·비용 출처에 속하는지 확인하고 전환을 취소한다. 활동 이름으로 이용권을 추정하거나 한도 초과 시 다른 출처로 자동 전환하면 반증이다. |
| INT-US-04 | 같은 제품 개선을 체험과 수업에서 사용한다. | Useful work first, Evidence over claims | OS별 같은 공개 App 산출물과 지원 Service 조합에서 양쪽 진입·작업·복귀를 확인한다. 체험 사본 누락, stale 서버, 한쪽 결과로 전체 완료를 보고하면 반증이다. |

이 Intent의 수용은 시작·전환·보존·전달 품질에 관한 것이다. 학습 효과나 독립 수행 능력을
입증하지 않는다. 사람 검증은 실제 목표를 가진 신규 사용자와 체험 후 수업에 참여하는
사용자가 별도 설명 없이 시작·복귀·사용량 출처를 설명하는 과제로 계획한다.
완료율·잘못된 활동 선택·도움 요청·복귀 실패를 관측하되 임의의 성공률이나 소요 시간 목표를
실측 결과처럼 쓰지 않는다. 합성 검증과 사람의 경험 판단을 분리한다.

## UX와 상태 경계

사용자 명칭은 **AI 체험하기 / 수업에 참여하기 / 이어서 하기**다. ‘체험판 앱’이나
‘정식판 전환’을 메뉴 이름으로 두지 않는다. 재방문 시 이전 활동을 먼저 보여주되
자동으로 유료 요청을 시작하지 않는다. ‘활동’은 UX상의 묶음이며 새 인증 역할이 아니다.

```text
HypeProof Studio
  AI 체험하기      → 기존 권한 확인 또는 발급 안내 → 체험 소개 → 시작
  수업에 참여하기  → 참여 코드 확인 → 수업 소개 → 시작
  이어서 하기      → 이전 활동 선택 → 자격 재확인 → 대화·파일 재개

작업 상단: [현재 활동 ▾]   [사용량]
  나의 AI 체험 / 참여한 수업 / 다른 수업에 참여
```

체험 선택은 홈페이지·PPT 등 결과물 선택이 아니다. 충분한 요청은 실행하고, 막막하면
한 턴에 필요한 질문 하나로 이어가는 NAT-03을 유지한다. 교과 과정의 도움·자료·순서는
해당 수업에서만 적용한다. 시작 안내는 작업 진입 후 캔버스를 점유하지 않는다.

전환의 제안 상태 흐름:

```text
현재 활동 A
  → B 선택 (A는 유지)
  → B 자격·정책·작업 위치 확인
  → A 실행의 완료 또는 확인된 중지 기다림
  → B 활성화·표시·실행 연결을 함께 확정
  → B에서 다음 요청
실패/취소 → A 유지, B 성공으로 표시하지 않음
```

진행 중인 요청은 A의 세션·자료·비용 출처에 남는다. 중지 요청만으로 B 도구를 활성화하지
않으며 확인되지 않은 외부 부작용을 재실행하지 않는다. 전환 준비 중에는 새 전송을 잠시
막고 입력을 보존한다. 옛 이벤트는 A 기록만 갱신한다. 다른 창의 활동까지 전역 변경하지 않는다.

App은 기존 SecretStorage·workspace·SDK/sessionSpool을, Service는 기존 account/access/
profile/session/usage 원장을 우선 확장한다. 사용자·활동 참조·실행/세션·workspace·정책 revision·
비용 출처의 귀속 의미를 먼저 정하되, 이 문서가 새로운 DB나 API를 확정하지는 않는다.
코드 간 계정 동일성을 추측하거나 credentials를 활동 목록/URL/로그에 저장하지 않는다.
단일 활성 코드에서 복수 활동으로의 변경은 US-2에서 조사·ADR·계약 대조를 먼저 제출한다.

## 배포와 계층

**체험과 수업은 서로 다른 제품 계층이 아니다.** 둘 다 같은 App·Service 기반에서 실행하는
프로그램이며 안내·자료·코치 지침·이용 조건으로 구분한다. Chalk는 강사 제품으로서 별도 역할을
유지한다. 개발용 별도 앱/서버를 체험의 필수 내부 계층으로 두지 않는다.

| 계층 | 소유할 것 | 전달·검증 |
|---|---|---|
| App | 공통 시작 화면, 활동 전환, 파일·세션·로컬 자격 경계 | OS별 하나의 App 산출물/업데이트 채널. 체험·수업은 같은 파일을 검증한다. OS 사이에 같은 hash를 요구하지 않는다. |
| Service | 신원·발급·참여·실행 권한·예산 집행 | 사용자용 체험·수업은 같은 공개 API 배포를 사용한다. 계정/수업 데이터와 정책은 구분한다. |
| Chalk | 강사의 강의 작성·권한 범위 운영 UI | 기존 Service 계약을 사용한다. 학생의 체험 기록을 자동 공개하지 않는다. |
| Module | 체험 지침·수업 자료·도움 방식 | 대상별 버전/pin을 보존한다. 현재 체험 prompt처럼 Service에 컴파일된 경우 Service revision을 기록한다. |

‘함께 릴리스’는 **공통 변경을 두 사용자 경로에서 검증하고 전달**한다는 뜻이다.
서버 문구 수정마다 App 전체를 재빌드하거나 Chalk·Module까지 동일 태그로 묶지 않는다.
App 후보는 OS별 동일 최종 산출물에서, Service 후보는 지원 App에서 체험·수업을 모두 검사한다.
특정 Module 변경은 그 대상과 공통 계약 영향을 확인하며 다른 수업의 고정 버전을 덮어쓰지 않는다.
코드 머지, 후보 생성, 검사, 공개 승격, 사용자 설치·재시작은 별도 상태다.

기존 fixture와 `e2e/native-trial-manifest.mjs`를 확장하고 #912의 운영 체크리스트를
실행 가능한 게이트로 연결하는 것이 후속 US-4다. 새 gate는 정상 후보 통과와
실패/누락/다른 SHA 증거 거부 대조를 먼저 통과해야 한다. 자동화 구현 전에는 수동 검사라고 표시한다.

로컬 리허설은 개발 옵션으로 남기되 사용자용 체험의 기본 경로로 두지 않는다.
공개 연결로 이행할 때 옛 localhost 토큰을 재사용하지 않고 정상 공개 자격을 확인한다.
기존 파일·대화·설정은 백업하고 복귀 경로를 제공한다. 기존 앱이 열려 있으면 교체 완료로
표시하지 않는다. 공개 권한이 없으면 발급/연결 단계가 BLOCKED이며 로컬 성공으로 대신하지 않는다.

## 범위와 결정이 필요한 항목

- 이번 발행: [US 요구사항](../requirements/unified-studio-experience.md),
  [US 테스트 계획](../testing/unified-studio-experience.md), [구현 이슈](../plan/unified-studio-experience.md).
- 코드 없이 시작하는 공개 체험: 발급 신원 확인 방식, 대상 연령/동의, 재체험 조건,
  기간·한도·비용 부담·남용 방지는 책임자의 결정과 기존 권한 계약으로 확정한다.
  그 전에는 기존 참여 코드/발급 안내를 제공하며 ‘클릭하면 즉시 무료 실행’이라고 약속하지 않는다.
- 복수 활동 연결의 기술 계약: US-2 ADR에서 기존 저장소와 credential scope를 확인한다.
  서버 검증 없이 이름이나 이메일 문자열만으로 서로 다른 사용자/코드를 합치지 않는다.
- 결제, 무제한 키, 새 로그인 공급자, 학습 등급, 공개 병원 사이트 변경은 범위 밖이다.
- 본 문서를 머지해도 실제 제품·자동 gate·공개 발급·OS 인수는 완료되지 않는다.
