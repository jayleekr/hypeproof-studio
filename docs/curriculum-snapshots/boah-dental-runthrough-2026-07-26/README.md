## 이 기록의 한계 — 반드시 읽을 것

**툴 호출과 코치의 생각(thinking)은 없다.** 채팅 패널의 활동 로그는 webview
React 상태(`toolLog`)라 workspaceState 에 영속화되지 않는다 — 패널을 숨겼다
켜면 그 자리에서 사라진다. 저장되는 것은 `{id, role, content, createdAt}` 뿐이다.

그래서 코치 발화는 **툴 호출 사이의 텍스트가 이어 붙은 형태**로 보인다.
"정답지 먼저 확인할게요!더 아래도 볼게요.구조 파악 완료!" 처럼 문장이 붙어
있으면 그 사이에 `browser_read` / `Read` 호출이 있었다는 뜻이다.

툴 트레이스가 필요하면 e2e 하네스(`e2e/tests/*.spec.ts`)의 `modalLog` + artifact
방식을 써야 한다. 실사용 세션에는 그 장치가 없다.

**이것 자체가 개선 후보다** — 실사용 세션에서 무슨 툴이 돌았는지 사후에 알 수
없으면, 회차에서 문제가 났을 때 재구성할 방법이 없다.

## errors.md 에서 나온 것 — 별건이지만 실재하는 결함

세션 중 코치 런타임 에러는 **하나도 없었다.** 대신 다른 게 나왔다:

```
Error: The language client requires VS Code version ^1.91.0 but received version 0.1.2
  vscode.html-language-features
  vscode.json-language-features
  vscode.markdown-language-features
```

`product.json.version` 이 HPS 릴리스 버전(`0.1.27`)이라, VS Code 엔진 버전
(`1.116.x`)을 기대하는 **내장 언어 확장 3종이 활성화에 실패**한다. 참가자가
에디터에서 HTML 을 열어도 자동완성·검증·미리보기가 없다.

`#361`(Mac 버전 스탬프)의 부작용으로 보이며 `#383`(Windows 짝)과 같은 계열이다.
별도 이슈로 올린다.
