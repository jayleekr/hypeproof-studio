## 1. 승인 모달 — 판단이 아니라 반사를 훈련하고 있다

### 실측

```
턴 1   6회    browser_open×2 · Bash×2 · Write×2
턴 2  19회    browser_open×4 · WebFetch×6 · Agent×4 · browser_click×1 · Write×2 · Bash×2
```

`+124.9s ~ +127.9s` 구간에 **WebFetch 4개가 1초 간격**으로 떴다. 읽고 판단할 수
있는 간격이 아니다. 승인 대기로 날린 시간도 잡혔다: `7.2s→28.5s`(21초),
`66.7s→100.8s`(34초).

`Bash(pwd)` 에도 모달이 떴다. 현재 폴더를 묻는 명령이다.

### 왜 나쁜가

승인 게이트의 목적은 **위임 판단**(seven-assets §5)을 훈련하는 것이다. 그런데
같은 질문을 25번 하면 학습되는 것은 판단이 아니라 **"뜨면 누른다"** 이다.
목적과 정반대 방향으로 훈련시킨다. 낮 세션 회고에도 같은 항목이 있다
(`.claude/rules/verification.md` — "강한 확인 남발 → 무지성 승인 훈련").

### Claude Code 는 어떻게 하나

세 층으로 나눈다.

```
1. 읽기는 애초에 안 묻는다        Read · Glob · Grep 은 승인 대상이 아니다
2. 기억하는 단위가 "패턴" 이다     Bash(npm run test:*) · WebFetch(domain:github.com)
                                  Read(//path/**) — 개별 호출이 아니라 규칙으로 저장
3. 모드로 한 번에 정한다           default / acceptEdits / plan / bypassPermissions
```

핵심은 **2번**이다. "이번 명령을 허용"이 아니라 **"이런 부류를 허용"**을 저장한다.
`.claude/settings.json` 의 `permissions.allow` 에 규칙으로 남고, 모달의
"항상 허용"이 그 규칙을 써 준다. 그래서 한 번의 판단이 이후 20번을 커버한다.

3번의 `acceptEdits` 는 "이 세션에서 파일 편집은 알아서 해라"를 한 번에 정하는
스위치다. 학습자가 **매 파일이 아니라 세션 단위로** 위임 결정을 내린다.

### 권고

우선순위 순으로.

- **루프백은 자동 허용**. `live_preview_start` 는 이미 자동인데 그렇게 띄운 서버를
  *열어서 보는 데* 모달이 뜬다. 앞뒤가 안 맞는다. → 이번에 수정함
  (`evaluateSdkToolUse` 의 `isLoopbackUrl` 분기)
- **오리진 단위 기억**. `boaclinic.com` 을 한 번 허용하면 `/about`, `/vision` 은
  안 묻는다. 셸의 `항상 허용(시그니처)` 과 같은 장치. → 이번에 수정함
  (`approvedBrowserOrigins`)
- **WebFetch 도 도메인 단위로**. 위와 같은 이유. 아직 안 함
- **읽기 전용 셸은 자동 허용 검토**. `pwd`·`ls`·`cat` 에 모달은 과하다.
  단 `shellPolicy` 는 "모달이 유일한 게이트"라는 전제로 설계돼 있으니
  (`sdkCoachHelpers.ts:1435-1455`) 이 전제를 바꾸는 결정이 먼저다
- **모드 스위치**. Claude Code 의 `acceptEdits` 상당. 첫 회차에서 강사가
  "이제 알아서 하게 두자"를 한 번 누르는 형태. 다만 **커리큘럼 결정**이지
  기술 결정이 아니다 — 위임 판단을 언제 가르치고 언제 면제할지의 문제

## 2. 재실행이 처음부터 다시 한다 ← 가장 크다

### 실측

20턴 한계로 죽어서 원장이 **다시 실행**을 눌렀다. 그 뒤 코치가 한 일:

```
Glob(**/*.{html,md})           재탐색
Read(index.html) × 3           앞서 이미 4번 읽음 → 누적 7회
browser_open(boaclinic.com)    이미 열었음
browser_read({})               이미 읽었음
Agent × 4                      앞서 WebFetch 6개로 이미 수집했던 것
```

**20턴 예산의 절반을 반복에 썼다.**

### 원인

```
webview   postToHost({ type:"retryMessage", prompt, history: state.messages })
host      handleSend(msg.prompt, msg.history)      ← 원래 프롬프트 재주입
```

이어가기가 아니라 **재시작**이다. 그리고 `state.messages` 는
`{id, role, content, createdAt}` 뿐이다 — **툴 호출도 툴 결과도 없다.**

그래서 코치는 *"내가 뭘 하겠다고 말했는지"* 는 알지만 *"뭘 읽었는지"* 는 통째로
잃는다. 살아남는 상태는 **디스크에 쓴 것뿐**이라, 코치가 기억이 아니라
파일시스템으로 복구한다. `agent.md` 가 그 역할을 우연히 해내고 있다.

### Claude Code 는 어떻게 하나

**대화 기록 자체가 상태다.** `tool_use` / `tool_result` 블록이 메시지 배열에
그대로 남고, `--continue` / `--resume` 은 그 배열을 복원한다. 툴 결과가 남으니
읽은 파일을 다시 읽지 않는다.

한계에 부딪히면 버리는 게 아니라 **압축**한다. 컨텍스트가 차면 auto-compact 가
지금까지의 작업을 요약으로 접고 **이어서** 간다. 사용자에게는 "요약했습니다"
한 줄만 보이고 작업은 끊기지 않는다.

즉 Claude Code 의 재시도는 *"프롬프트를 다시 보내기"* 가 아니라
*"상태를 들고 계속하기"* 다.

### 권고

두 단계로 나눌 수 있다. 위가 최소, 아래가 제대로.

- **최소** — 한계에 걸렸을 때 원래 프롬프트를 재주입하지 말고 **진행 요약**을
  주입한다. "이미 한 일: … / 남은 일: …". 코치가 마지막 턴에 그 요약을 내도록
  프롬프트에 박고, 재실행은 그 요약 + "이어서 해줘"를 보낸다. 웹뷰 변경만으로
  된다
- **제대로** — 히스토리에 툴 결과를 싣는다. 전량은 무겁고 워커 직렬화도 손대야
  하니, **툴 이름 + 인자 + 결과 요약** 정도의 압축 형태가 현실적이다.
  Claude Code 의 compaction 과 같은 발상

**재실행을 고치지 않으면 maxTurns 를 올려도 같은 자리에서 죽는다.** 순서가 있다.

## 3. maxTurns 20

```
maxTurnsFor()   성인 20 · 미성년 6      (sdkCoachHelpers.ts:337)
실측            한 턴에 툴 37회
```

#457 태그 노트에 *"지금 올리면 낭비를 감춘 채 넘어간다. 같은 시나리오를 다시
재본 뒤에 판단한다"* 고 적어 뒀다. **그 재측정이 이것이다.**

에러 배너가 아니라 **"여기까지 했고 다음은 이것"** 인계로 끝나야 한다 —
지금은 학생이 에러를 보고 버튼을 눌러야 하고, 누르면 처음부터 다시 한다.

같이.

**권고**: Read 의 반환 한도를 확인하고, 프롬프트에 재읽기 금지 규칙을 넣는다.
2번이 해결되면 뒤 3회는 자동으로 사라진다.

## 6. 코치가 작업 폴더를 못 찾는다 — 그리고 Read 가 상대경로를 거부한다

**이 항목이 오늘 가장 비쌌다.** 턴 3(151초)의 약 120초를 여기에 썼다.

### 실측 — 턴 3 전체

```
+  6.0s  Glob(**/*.{html,css,md})                        ✓
+ 10.0s  Read(agent.md)                                  ⚠️
+ 10.0s  Read(index.html)                                ⚠️
+ 13.0s  Bash(ls -la ~/Desktop/HypeProof Studio/workspace/)   ← 없는 경로를 지어냄
+ 90.3s  Bash(find ~ -name "agent.md" ...)               ← 홈 전체 스캔, 35초
+125.4s  Bash(ls -la ~/HypeProofClinic/)                 ← 겨우 찾음
+129.4s  Read(agent.md)                                  ✓
+129.4s  Read(index.html)                                ✓
```

`find ~` 는 #457 릴리스 노트에 *"홈 전체를 뒤지다 20턴 중 13턴을 태우고 세션이
죽었다"* 고 적어 둔 바로 그 행동이다. **고쳤다고 판단하고 넘어갔는데 재발했다.**

### 원인 — 절반은 확정

벤더된 SDK 타입 정의가 못박고 있다:

```
sdk-tools.d.ts   "absolute path to the file to read"
                 "absolute path to the file to write (must be absolute, not relative)"
```

**Read/Write/Edit 는 절대경로만 받는다.** 코치가 `agent.md` 를 넘기면 파일이
있든 없든 거부된다. 그래서 "파일이 없나?" → 홈 스캔으로 이어진다.

확정된 것: cwd 주입은 **설치된 앱 번들에 실제로 들어 있다**
(`Working directory (absolute)`, `<env>`, `no folder open`, `cwd is UNKNOWN`
전부 존재). `[coach]` 경고도 로그에 없으니 폴더는 열려 있고 cwd 는 넘어갔다.

**아직 모르는 것**: 그런데도 왜 코치가 상대경로를 쓰는가. env 블록이 실제 요청에
안 실리는지, 실렸는데 무시되는지, 긴 턴에서 밀려난 건지 — 밖에서는 구분되지
않는다. 실행 중인 앱에 나가는 시스템 프롬프트를 볼 수 없기 때문이다.
**여기서 짐작으로 판정하지 않는다.**

### Claude Code 는 어떻게 하나

두 겹이다.

1. 시스템 프롬프트에 작업 디렉터리를 넣는 것에 더해, **세션 시작 시 디렉터리
   구조를 미리 준다.** "여기 뭐가 있지"를 툴로 물을 이유가 없다.
2. 툴 설명이 절대경로를 요구할 때, **에러가 그 사실을 말해 준다** — 그리고 그
   에러가 대화 기록에 남아 다음 호출이 교정된다. 여기서는 실패가 아이콘 하나로
   끝나 교정 신호가 약하다(7번 참조).

### 권고

- **첫 턴 컨텍스트에 워크스페이스 파일 목록을 주입한다.** 코호트 워크스페이스는
  파일이 몇 개 안 되니 비용이 거의 없다. 이게 가장 값싼 한 수다
- **상대경로를 호스트에서 흡수한다.** `canUseTool` 훅이 이미 모든 호출을 가로채고
  있으므로, 상대경로가 오면 워크스페이스 루트 기준으로 절대화해서 통과시킬 수
  있다. 코치의 실수를 제품이 흡수하는 쪽이 프롬프트로 훈계하는 것보다 확실하다
- **cwd 가 실제로 나가는지 계측한다.** 지금은 확인할 방법이 없다는 것 자체가 문제다

## 7. 툴 실패가 사용자에게 안 보인다

턴 1 에서 `Write(index.html)` 이 실패했다. 코치 발화:

> 바로 만들겠습니다. … **저장됐습니다.** 브라우저에서 확인할게요!

실패 언급이 없다. `⚠️` 아이콘 하나가 전부였고, 원장이 그걸 잡아내 물었다.
참가자에게는 **"그냥 느리네"** 로만 보인다. 이 실패 하나로 143초를 재생성에 썼다.

### 툴 로그가 경로를 감춘다 — 이게 진짜 대가를 치렀다

라벨은 파일명만 보여준다 (`sdkCoachHelpers.ts:931` 이 경로를 `split("/").pop()`).
그래서 이 둘이 **화면에 똑같이 보인다**:

```
Read(/Users/jwcorp/HypeProofClinic/agent.md)   →  Read(agent.md)   ✓
Read(agent.md)                                  →  Read(agent.md)   ⚠️
```

절대경로 문제(6번)를 **밖에서 볼 수 없게 만드는 것이 정확히 이 표시 방식이다.**
같은 결함을 오늘 하루에 세 번 만났고, 매번 다른 원인으로 추정했다:

| 만난 시각 | 그때 추정한 원인 | 실제 |
|---|---|---|
| 턴 1 `Write` 실패 | 경로가 워크스페이스 밖? 승인 거부? | 미확정 (라벨이 감춤) |
| 턴 2 `Glob(lim)` 탐색 | cwd 폴백이 안 먹나 | 미확정 |
| 턴 3 `Read` 2회 실패 | — | **SDK 가 절대경로만 받음** |

턴 3 에서야 벤더 SDK 타입을 열어보고 확정했다. 라벨이 전체 경로를 보여줬다면
턴 1 에서 끝났을 일이다.

**권고**:
- 실패한 툴은 채팅에 **한 줄로 보이게** 하고, 라벨에 **실패 사유**를 붙인다
- 경로는 **워크스페이스 기준 상대경로**로 표시한다 (`./agent.md` vs `agent.md`
  가 구분되도록). 파일명만 남기는 축약은 정보를 너무 많이 버린다

## 9. 홈 페이지만 공통 CSS 를 안 쓴다

재실행 턴이 만들어 낸 결과물 구성:

```

index.html      28,302    shared.css 미연결 · 인라인 <style> 1개 유지
about/digital/prevention/senior.html    shared.css ✓
```

홈은 턴 1 에서 인라인 스타일로 만들어졌고, 서브페이지는 나중에 `shared.css` 로
만들어졌다. 코치가 `index.html` 을 `Edit` 5회로 고칠 때 **링크는 붙였지만
스타일 체계는 통합하지 않았다.**

당장 깨져 보이지는 않지만, 앞으로 색·폰트를 바꾸면 **홈만 안 바뀐다.** 참가자가
"왜 여기만 그대로예요?"를 만나는 지점이다.

덧붙여 `Edit` 5회는 정상 동작이었다 — 전체 재생성이 아니라 부분 수정이고,
서브페이지 링크 10곳이 실제로 반영됐다(검증함). **다만 편집 전후 파일 크기가
28,302 로 동일한 것은 설명되지 않는다** — 링크는 확실히 들어가 있으므로 표시상
문제일 수 있다. 미확정으로 남긴다.

## 계측기 자체의 오류 — 이번에 4건

`.claude/rules/verification.md` 규율대로 남긴다. 이번에도 전부 **짐작으로 기준을
세운** 데서 나왔다.

| 오판 | 짐작한 것 | 실제 |
|---|---|---|
| 승인 모달 관측 | DOM 에 있을 것 | macOS 기본은 **네이티브 NSAlert** — DOM 에 없다. 하네스는 `window.dialogStyle: custom` 을 강제해서 본다 |
| 턴 종료 판정 | 텍스트가 멈추면 끝 | 긴 툴 호출 중엔 멈춘다. 턴 2 를 조기 종료로 오판 (같은 실수 재발) |
| 활동 로그 행 정체성 | 행이 추가된다 | `💭` 는 **제자리 갱신**(`App.tsx:89-95`). 라벨을 키에 넣어 💭 개수가 몇 배로 부풀었다 |
| 번들 문자열 검사 | `grep -qF` 로 되겠지 | 번들이 **바이너리로 취급**돼 거짓 음성. `-a` 없이 "#457 이 빌드에 없다"는 오판을 낼 뻔했다 |

세 번째는 **턴별 인덱스 정합성 대조**를 돌려서 잡았다. 대조군이 없었으면 부풀린
숫자를 그대로 보고했을 것이다.

두 번째는 이 문서 규율에 **이미 적혀 있는 항목**인데 또 밟았다. 규칙을 아는 것과
계측기를 짤 때 적용하는 것은 다르다.
