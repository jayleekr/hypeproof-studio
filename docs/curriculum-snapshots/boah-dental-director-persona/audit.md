## 7 AI Native Assets — 학습 신호 점수

| Asset | 평가 | 무엇이 가르쳤나 |
|---|---|---|
| **Intent Clarity (E7)** | 🟡 작동, 약함 | weak chip 시각화 + "어떤 결정에 쓸지 모르면 검색이 안 잡혀요" 캡션이 *행동 이전*에 신호. 단, 막연한 입력에 모델이 "결정" 단어를 명시 안 하고 우회. |
| **Context Design (E2)** | 🟢 작동 | follow-up chip "환자군·상황·금지표현·판단 기준을 처음부터 풀로 적어줘"가 매 턴 노출. V1 first shot 응답에서도 "추론한 부분: ___로 잡았어요. 맞나요?"로 컨텍스트 보강을 *행동으로* 시연. |
| **V1 First Shot (#157)** | 🟢 작동 | 구체 검색 주제 + 직군 한 단락 → reframe 없이 즉시 V1 HTML skeleton 생성 (158줄). "▸ 📄 코드 보기"로 collapsed — 직원이 펴서 보는지는 별도 UX 검증 필요. |
| **Verification Reflex (E11)** | 🟢 작동, 매우 강함 | "이 검색을 *틀리게* 만드는 가장 확실한 방법은?" → 수술 단계 뭉개기 · 운동 종류 안 나누기 등 실제 약점을 *모델이 먼저 뽑음*. 출처 신뢰도 (학회/대학병원 vs 광고/블로그) 같이 surface. |
| **Iteration Reflex (E9)** | 🟢 작동, 매우 강함 | 한·영·전문용어 3쿼리를 표로 출력 + **각 쿼리가 닿는 출처**를 한 줄로 설명 ("영어는 ITI·ICOI 가이드라인", "osseointegration은 핵심 개념 검색"). 단순 변주가 아니라 *왜 이 변주가 필요한가*까지 학습. |
| **Delegation Judgment (E12)** | 🟢 작동, 이 여정의 highlight | 임상 베이트("환자한테 운동해도 돼?")에 "코치가 '돼요/안 돼요'를 직접 드리면 그게 우리 병원 기준이 되어버려요 — 위험해요" + "모의 원장님 판정으로 넘어갈까요?"로 게임 룰 환원. 위임 경계의 *이유*까지 명시. |
| **Taste (E13)** | 🟢 작동 | 환자용 ("운동은 원장님 지시에 따라 단계적으로") / 내부용 ("수술 단계·운동 종류별 재개 기준 — 원장님 컨펌 후") / 원장님 컨펌용 ("1차 수술 후 일반 운동·격렬한 운동 각각 재개 가능 시점") — 추상 사다리 3단이 명확히 분리. |
| **Ownership (E14)** | 🟡 작동, 약함 | verdict-card + `workshop-output/rules.md` 누적 메커니즘이 *기술적으로* surface. 단, "다음에도 자동 적용된다"는 약속이 모델 prose로 한 번 더 reinforce되지 않음 (UI 버튼 라벨에만 의존). |

## UX-as-curriculum — 도구 메커니즘 자체가 가르치는 것

1. **Welcome 1초 룰**: greeting이 "치과 지식 슈퍼서치엔진을 함께 만들어요 🔍 마지막엔 원장님을 이겨봅니다." — 게임 룰을 *전체 흐름의 형태*로 전달. 강의 X.
2. **5 initial chips의 직군 라벨링** (위생사·코디·사모님): 원장이 "내 직원 누구한테 어떤 거 가르치지?" 즉시 매핑 가능. 4번째 사모님(소모품·장비 비교) 칩은 가족 사업 보아치과의 실제 결제권자를 정확히 짚음.
3. **weak chip 시각화**: "치과 관련 질문 답해줘 — 어떤 결정에 쓸지 모르면 검색이 안 잡혀요." 흐린 톤으로 *빈약한 입력의 모양*을 행동 이전에 *대비*로 노출. 가장 효율적인 Intent Clarity 학습 신호.
4. **follow-up chips 8개의 caption 매핑**: V1 First Shot / Intent Clarity (E7) / Context Design (E2) / Iteration Reflex (E9) / Verification Reflex (E11) / Taste (E13) / Ownership (E14) / Delegation Judgment (E12) — **매 턴 자산 카탈로그가 클릭 한 번 거리로 노출**. 강의 없이 자산을 *행동 옵션*으로 학습.
5. **✨ 한 번 더 다듬어보기 버튼**: 검색 결과를 다시 묻는 *기본 동작*을 입력창 옆에 상시 노출 — Iteration Reflex의 entry point.
6. **🛠️ 검색엔진 만드는 중 — 검색어·출처 정리…**: 스트리밍 인디케이터가 *AI가 무엇을 하고 있는지*를 자연어로 표시. "AI는 마법이 아니라 검색어 정리 중"이라는 메타 학습.
7. **PII 가드 prose surface**: 시스템 프롬프트의 "prose 최소 룰 예외" 규약대로 — paste 직후 1~2줄 안내 → 마스킹 예시 (`환자 김OO / 연락처 미표시 / 차트 #***21`) → V1으로 redirect. 직원에게 *마스킹의 모양*을 한 번에 시각화.

## 보아치과 원장이 60분 후 *말할 수 있게 되는 것* (성공 지표)

시스템 프롬프트의 성공 지표는 "참가자가 *내가 만든 검색엔진이 원장님께 한 번 깨졌고, 그 깨진 이유가 우리 병원 검색 규칙으로 저장됐다*고 말할 수 있는 것".

이 페르소나 여정에서 본 발화 증거:

- ✅ V1 한 번 만듦 — `sw-dental-v1` skeleton 158줄 생성
- ✅ "원장님을 이겨라" 게임 룰 환기 — 임상 베이트 응답에서 자동 재호출
- 🟡 깨짐 (verdict) → 규칙 저장 흐름 — verdict card + rules.md 메커니즘은 작동. **단, 이 페르소나 여정에선 모의 원장님 PASS/더 확인/위험 verdict가 명시적으로 trigger되지 않았음** (V1 → verdict 호출이 별도 user 발화 필요). 실 워크숍에선 코치가 verdict 단계로 자연스럽게 넘기는지 별도 확인 필요.

## 청중 페르소나 별 *체감 학습*

이 여정은 원장님 본인이 *직원 자리에 앉아본* 시뮬레이션. 실 워크숍 청중은 4 페르소나:

| 페르소나 | 이 여정에서 본 학습 강도 | 보강 필요한 곳 |
|---|---|---|
| **위생사** | 🟢 매우 강함 — initial chips 2개가 위생사 직무. V1 + verdict 흐름이 환자 안내문 → 원장님 컨펌 사이클과 1:1. | 없음. 워크숍 핵심 청중. |
| **코디** | 🟡 적당함 — initial chip 1개 (리뷰 답글). V1/verdict 흐름이 검색-안내문 frame이라 *상담 표현/예약 표현* 같은 코디 업무는 살짝 weak fit. | 코디용 V1 skeleton 변형 검토 ("리뷰 답글 V1" template tier) — Phase 5 이후 |
| **사모님** | 🟡 적당함 — initial chip 1개 (장비 비교). 결제 결정자라 *Verification Reflex* (출처 신뢰도) + *Iteration Reflex* (3가지 후보) 흐름이 적합. | 임플란트 후 운동 같은 *임상* 베이트엔 사모님이 직접 안 부딪힘. 사모님 전용 V1 ("장비 후보 3개 비교") 시연 별도 |
| **원장님(시연자)** | 🟢 강함 — 첫 5분 시연 후 직원에게 넘기는 게임 진행자 역할. 이 여정이 그 5분 시연용 정확한 reference. | 원장님 *모의 원장님 판정* (PASS/더 확인/위험) 흐름이 본인 평소 판단 패턴과 일치하는지 dry-run 1회 권장 |

## 한 줄 요약

> **이 도구는 "AI가 임상 결론 못 낸다"는 위임 경계 + "검색 변주는 출처가 다른 곳에 닿게 한다"는 iteration 감각 두 가지만으로도 60분 값어치를 한다.** 나머지 5자산은 follow-up chips가 *행동 카탈로그*로 매 턴 노출되므로, 강의 없이 자산이 학습된다. 부족한 건 *Ownership 약속의 prose reinforce*와 *Intent Clarity의 "결정" 키워드 명시* — 둘 다 시스템 프롬프트 한 줄 추가로 닫힘.
