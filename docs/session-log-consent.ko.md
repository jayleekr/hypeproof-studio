# 세션 기록 업로드 — 고지·동의·보존 정책

> #606. 코드는 v0.1.45 로 출고 완료(#595 수집 · #602 업로드). 이 문서는 그 위에
> 얹히는 **정책**이다: 무엇을 모으고, 왜 모으고, 얼마나 갖고 있는가.
>
> 계약(행동)은 `docs/studio-requirements.md` REQ-Q1~Q12 가 갖는다. 이 문서는
> 거기에 없는 것 — 참가자에게 **무슨 말을 하는가** — 만 담는다.

## 1. 무엇이 업로드되나

업로드 단위는 **세션 디렉토리 하나**이고, 파일은 정확히 3종이다. 서버 allowlist
가 그 외 파일명을 거부한다(`worker/src/routes/logs.ts` `ALLOWED_FILES`).

| 파일 | 내용 |
|---|---|
| `session.meta.json` | 세션 id(UUID) · 코호트 · 사용자 핸들 · 시작 시각 · 개발호스트 표식 |
| `events.jsonl` | **질문 원문** · 요청 단위 토큰 usage 4종 · 행동 이벤트 · 턴 종료(비용 포함) |
| `manifest.json` | 위 파일 목록 + sha256 (완결 표식) |

`events.jsonl` 이 개인정보 관점의 핵심이다. 참가자가 코치에게 **친 문장이 그대로**
들어 있다(20,000자 캡, 잘리면 `text_truncated: true` 로 표기 — 무성 절단 없음).

들어 있지 **않은** 것: 코치의 응답 본문, 파일 내용, 화면 캡처, 이메일·전화번호 등
별도 수집 항목. 신원은 강사가 발급한 **핸들**(예: `보아치과-01`)이며 실명이 아니다.

## 2. 왜 모으나

두 가지뿐이다(#580).

1. **비용 통제** — 어떤 질문이 비싼지를 질문 원문 옆에 붙여서 본다. 요청 1건 =
   레코드 1건이라 "턴당 $0.024" 같은 값이 바로 나온다.
2. **커리큘럼 개선** — 어디서 막히는지, 어떤 표현이 통하는지를 감이 아니라
   데이터로 본다.

마케팅·광고·외부 제공·모델 학습에는 쓰지 않는다.

## 3. 언제 올라가나 — 네 조건이 **전부** 참일 때만

하나라도 거짓이면 업로드는 일어나지 않는다(fail-closed).

| # | 조건 | 현재 상태 |
|---|---|---|
| 1 | 워커가 업로드 라우트를 갖고 배포돼 있다 | ✅ 2026-08-19 배포 (afab426) |
| 2 | 그 코호트 프로필에 `analytics.upload_session_logs: true` | `canary-sdk-contract` 만 ON. 실코호트 전부 OFF |
| 3 | 사용자가 **버튼을 누른다** | 자동 업로드 경로 없음 (REQ-Q9) |
| 4 | 세션 신원 = 토큰 신원 | 공용 PC 에서 남의 세션이 내 이름으로 올라가지 않는다 |

②가 거짓이면 서버가 `403 upload_disabled` 로 거부하고 클라이언트 UI 에 버튼조차
뜨지 않는다. **2026-08-19 프로덕션 실측으로 양쪽 방향 확인**: canary 는 R2 적재
성공(바이트 대조), 보아치과(성인, OFF)는 403 거부.

## 4. 미성년

아동 코호트에는 이 플래그를 **켤 수 없다.** `validate.py` 가 HARD FAIL 로 막고
CI 가 그 검증기의 자기 테스트까지 돌린다.

미성년 대상으로 이 기능을 쓰려면 별도 절차가 선행되어야 한다 — 보호자 동의
서식, 그 동의를 코드가 확인할 방법, 그리고 이 문서의 재검토. **지금은 그 절차가
없고, 그래서 기능도 꺼져 있다.** 순서를 뒤집지 않는다.

## 5. 보존 기간

| 위치 | 기간 | 근거 |
|---|---|---|
| 참가자 PC (로컬 스풀) | 업로드 성공 후 **3일** 뒤 삭제. 미업로드분은 총량 200MB 캡까지 보존 | REQ-Q6 · REQ-Q12 |
| R2 (`studio-logs/`) | **90일** 후 자동 만료 | 아래 |

**90일을 고른 이유**: 한 코호트 시리즈(최대 4회차, 주 1회 = 약 1개월)가 끝나고
분석까지 마치는 데 필요한 창을 덮으면서, 목적 달성 후 지체 없이 파기한다는 원칙을
지키는 가장 짧은 값. 분석이 더 걸린다면 기간을 늘릴 게 아니라 **집계본을 남기고
원문을 버리는 쪽**이 맞다.

적용 상태 (2026-08-19 설정·확인):

```
bucket: hps-traces
rule:   studio-logs-retention-90d
prefix: studio-logs/
action: Expire objects after 90 days
```

프리픽스를 `studio-logs/` 로 좁힌 것은 같은 버킷의 다른 두 용도(`turns/` 턴 원문,
`backup/d1-` D1 백업 — 자체 회전 보유)를 건드리지 않기 위해서다.

## 6. 참가자 고지문

수업 시작 시 구두로 읽거나 안내문에 그대로 붙일 수 있는 문안. **업로드 버튼을
누르기 전에** 전달되어야 한다.

> **오늘 활동 기록에 대해 알려드립니다.**
>
> 수업 중 여러분이 코치에게 입력한 질문과, 그 질문에 든 비용·토큰 정보가 여러분
> PC 에 기록됩니다. 이 기록은 **여러분이 "오늘 활동 기록 보내기" 버튼을 직접
> 누르지 않는 한 PC 밖으로 나가지 않습니다.**
>
> 보내주시면 저희는 이것을 **수업 비용을 파악하고 커리큘럼을 개선하는 데에만**
> 씁니다. 광고나 외부 제공, AI 모델 학습에는 사용하지 않습니다.
>
> 보관 기간은 **90일**이고, 이후 자동 삭제됩니다. PC 에 남은 사본은 전송 후
> 3일 뒤 정리됩니다.
>
> 보내지 않으셔도 수업에는 아무 영향이 없습니다. 보내신 뒤 삭제를 원하시면
> 강사에게 말씀해 주세요.

마지막 문장은 약속이다 — **지킬 수 있을 때만 넣는다.** 현재 개별 삭제는 R2 키
프리픽스(`studio-logs/<코호트>/<핸들>/`)로 수동 삭제가 가능하다.

## 7. 첫 opt-in 대상

성인 코호트부터. 구체적으로 **보아치과 원장 트랙**
(`boah-dental-director-copyclone-2026-s1`) 이 후보다 — 성인이고, 이미 이 파이프
라인의 데이터가 가장 많이 쌓일 트랙이며, 미성년 절차 문제가 없다.

켜는 절차:

1. §6 고지문을 해당 회차 참가자에게 **실제로 전달**한다
2. 프로필에 `analytics: { upload_session_logs: true }` 한 줄 추가 (PR)
3. `npm run validate-profiles` 초록 확인 (아동 코호트였다면 여기서 HARD FAIL)
4. 워커 배포

**1번이 2번보다 먼저다.** 동의 없이 켠 수집은 켜지 않은 것만 못하다.
