# L5. 홈페이지 운영을 직접 통제하고 필요한 일은 맡기기

> 자동 생성 문서. 수정은 ../program.json에서 한다. 강사 검토 전 초안.

**수강생:** 윤도현 원장 (가상) (Owner)

상황: 여러 페이지를 운영하며 업체·호스팅·도메인 책임이 나뉘어 있다.

막히는 지점: 계정 소유와 복구 책임이 불명확하고 모든 것을 직접 하려다 지친다.

시작 역량: L4 제작과 L3 배포·복구 증거 보유

수강 후 행동: 운영 지도와 인계 문서를 만들고 모의 장애에서 복구·위임을 결정한다.

**목표:** 도메인·저장소·배포·복구 책임을 정리하고 모의 장애 2건의 대응·위임 계획을 검증한다.

준비: L3·L4 동등 실기. 가상 운영 카드 제공. 실제 DNS·계정·결제 설정 변경 없이 진행한다.

## 강사 진행안·학생 실습

### 0–15분 · 운영 구조 그리기

강사 발화: “웹사이트가 어디서 만들어지고 어디서 공개되는지 연결해봅시다.”

가상 운영 카드에서 도메인·DNS·저장소·배포·콘텐츠 담당을 연결한다.

Studio 요청 예시:

```text
가상 운영 카드를 구성요소, 소유자, 작업자, 복구 담당으로 정리해줘. 없는 정보는 미확인으로 둬.
```

막혔을 때: 자격증명 값 대신 담당과 접근 확인 상태만 적는다.

제출: ownership-map.md

완료 기준: 5개 구성요소의 소유·작업·복구 책임이 표시된다.

### 15–30분 · 정상 기준과 변경 판단

강사 발화: “혼자 모두 고치는 것이 목표는 아닙니다.”

강사가 오류 링크 수정과 도메인 접근 상실을 비교해 직접 수행·전문가 위임 기준을 시연한다.

Studio 요청 예시:

```text
콘텐츠 수정, 배포 실패, 도메인 접근 상실을 직접/AI 보조/전문가 인계로 분류할 질문을 제안해줘.
```

막혔을 때: 각 분류에 이유와 증거를 붙인다.

제출: 운영 판단 메모

완료 기준: 권한과 복구 가능성을 기준으로 설명한다.

### 30–60분 · 운영 수칙 작성

강사 발화: “수칙은 실제 다음 작업에 쓸 수 있어야 합니다.”

변경 요청→검수→배포→확인→복구 순서, 담당, 중단 기준, 정기 점검 항목을 작성한다.

Studio 요청 예시:

```text
내 연습 기록에 근거해 운영 수칙을 작성해줘. 하지 않은 복구나 점검을 완료로 쓰지 마.
```

막혔을 때: 모호한 정기 점검 대신 항목과 담당을 정한다.

제출: operating-playbook.md

완료 기준: 변경·중단·복구·담당·점검 시점이 구체적이다.

### 60–85분 · 모의 장애 두 건 대응

강사 발화: “먼저 영향과 마지막 정상 상태를 확인합니다.”

카드 A: 새 배포 뒤 시간표 링크 오류. 카드 B: 도메인 관리 접근 불가. 각각 초기 확인·복구/인계·증거를 작성한다.

Studio 요청 예시:

```text
두 가상 장애의 초기 확인 순서를 제안해줘. 실제 DNS 변경이나 계정 복구를 실행하지 마.
```

막혔을 때: A는 연습 파일로 재현, B는 탁상 시뮬레이션이다.

제출: incident-log.md

완료 기준: A의 링크 복구를 확인하고 B의 권한 없는 조작 대신 담당 인계를 정한다.

### 85–110분 · 업체 교체 인계 설계

강사 발화: “담당자가 바뀌어도 홈페이지를 통제할 수 있나요?”

가상 업체 교체 상황에서 필요한 자산·접근 확인·복구 증거·미확인 항목을 독립 정리한다.

막혔을 때: 비밀번호를 문서에 쓰지 않는다.

제출: 인계 체크리스트

완료 기준: 도메인·저장소·배포·백업·책임자 누락을 식별하고 확인 행동을 정한다.

### 110–120분 · 자기 환경에서 검증할 것

강사 발화: “오늘의 모의 연습과 실제 운영 역량을 구분합니다.”

실제 담당자와 확인할 항목, 재실습할 복구 작업, 본인이 맡지 않을 범위를 적는다.

Studio 요청 예시:

```text
미확인 항목만 다음 행동과 담당으로 정리해줘. 전체 운영 가능이라고 평가하지 마.
```

막혔을 때: 실제 수행 증거는 수업 후 보완한다.

제출: operating-playbook.md 후속 확인

완료 기준: 탁상 연습·연습 실기·실운영 확인을 구분한다.

## 평가 기록 (수행 전 빈칸)

## 수업 후 자기 환경에서 할 일

실제 담당자와 소유·접근·백업·복구 경로를 확인하고 연습 환경에서 복구를 다시 수행한다. 이 확인 전에는 통합 운영 독립을 인증하지 않는다.

## 도구가 막히면

이 패키지는 강의 자료와 authoring API 자동화다. Studio 학생 UI·미리보기·배포·복구·MCP가 이 강의 전체를 지원한다는 실행 증거는 아직 없다. 미리보기가 막히면 로컬 HTML, 배포가 막히면 모의 연습으로 전환하고 실기 미완료를 기록한다.
