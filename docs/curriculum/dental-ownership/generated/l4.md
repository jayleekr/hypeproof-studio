# L4. 우리 치과 디자인으로 채용 페이지 만들기

> 자동 생성 문서. 수정은 ../program.json에서 한다. 강사 검토 전 초안.

**수강생:** 정하린 원장 (가상) (Builder)

상황: 기존 홈페이지는 수정·운영하며 채용 페이지를 새로 만들고 싶다.

막히는 지점: AI가 많은 기능과 새로운 디자인을 덧붙여 일관성이 깨진다.

시작 역량: L3 연습 배포·복구 가능 또는 동등 실기

수강 후 행동: 요구사항에 맞는 채용 페이지를 만들고 기존 사이트와 연결·검수한다.

**목표:** 요구사항 5개를 기준으로 정적 채용 페이지를 만들고 기존 사이트와 연결해 검수한다.

준비: L3 동등 실기. 가상 채용 정보와 기존 starter 디자인. 실제 지원서 수집 기능은 만들지 않는다.

## 결과물

- careers.html
- page-brief.md: 요구사항·디자인 이유
- 페이지 연결·모바일 검수 기록

## 강사 진행안·학생 실습

### 0–15분 · 페이지 목적과 범위

강사 발화: “이번 페이지는 지원자가 역할과 절차를 이해하게 만드는 게 목적입니다.”

가상 채용 안내에 역할·업무·근무 조건 확인 방법·지원 절차·문의 안내라는 요구사항 5개를 정한다.

Studio 요청 예시:

```text
정적 채용 페이지 요구사항을 5개로 정리해줘. 실제 개인정보 수집 폼과 외부 연동은 제외해줘.
```

막혔을 때: 조건을 사실처럼 지어내지 말고 교육용임을 표시한다.

제출: page-brief.md

완료 기준: 대상·목적·5개 요구사항·제외 범위가 있다.

### 15–30분 · 기존 디자인에서 출발

강사 발화: “새 페이지도 같은 병원의 일부처럼 보여야 합니다.”

기존 색·글자 크기·간격·메뉴를 추출하고 재사용할 요소를 선택한다.

Studio 요청 예시:

```text
index.html에서 재사용할 스타일과 메뉴를 찾아 설명해줘. 새 프레임워크나 패키지를 추가하지 마.
```

막혔을 때: 브랜드 판단은 원장이 선택한다.

제출: 디자인 선택 메모

완료 기준: 재사용 요소 3개와 선택 이유가 있다.

### 30–60분 · 첫 페이지 제작

강사 발화: “첫 버전은 요구사항이 보이면 충분합니다.”

careers.html을 만들고 index.html에서 연결한다. 더미 지원 폼 대신 연습용 문의 안내 문구를 넣는다.

Studio 요청 예시:

```text
page-brief.md의 5개 항목으로 careers.html을 만들어줘. 기존 스타일을 재사용하고 index.html 메뉴에서 연결해줘. 개인정보 입력 폼은 넣지 마.
```

막혔을 때: 정보가 없으면 빈칸과 확인 필요 표시를 사용한다.

제출: careers.html·index.html

완료 기준: 요구사항 5개가 있고 두 페이지 사이 이동이 된다.

### 60–85분 · 디자인·범위 검수

강사 발화: “요청하지 않은 기능이 늘지 않았는지도 확인합니다.”

390px·1280px에서 정보 순서·줄바꿈·링크를 확인하고 한 가지 문제를 수정한다.

Studio 요청 예시:

```text
내가 발견한 문제 한 가지만 수정해줘. 나머지 구조는 유지하고 변경점을 설명해줘.
```

막혔을 때: 새 인증·DB·MCP가 필요하다는 제안은 별도 기능 요청으로 분리한다.

제출: 수정 전후 기록

완료 기준: 모바일 가로 잘림이 없고 불필요한 의존성이 없다.

### 85–110분 · 다른 조건으로 페이지 확장

강사 발화: “다른 페이지를 통째로 만들기보다 조건 변경에 대응해봅시다.”

가상 안내에서 모집 역할이 바뀌었을 때 제목·설명·문의 안내를 함께 수정하고 기존 링크를 재검수한다.

막혔을 때: 완료 기준을 먼저 확인한다.

제출: 독립 과제 파일·검수 기록

완료 기준: 새 역할 관련 문구가 일치하고 기존 메뉴가 동작한다.

### 110–120분 · 연습 배포와 인계

강사 발화: “누가 언제 내용을 갱신할지도 정합니다.”

가능하면 연습 환경에 반영하고 URL을 확인한다. 미완료면 파일 결과와 배포 대기 상태를 기록한다.

Studio 요청 예시:

```text
페이지 담당, 갱신 계기, 확인 항목을 인계 문서로 정리해줘.
```

막혔을 때: 파일 완성과 배포 완료를 별도 표시한다.

제출: page-brief.md 인계·배포 상태

완료 기준: 갱신 담당과 확인 방법이 있으며 배포 상태가 사실과 맞다.

## 평가 기록 (수행 전 빈칸)

자기 병원에서 필요한 새 페이지 1개의 목적·대상·필수 정보·운영 담당을 정한다.

## 도구가 막히면

이 패키지는 강의 자료와 authoring API 자동화다. Studio 학생 UI·미리보기·배포·복구·MCP가 이 강의 전체를 지원한다는 실행 증거는 아직 없다. 미리보기가 막히면 로컬 HTML, 배포가 막히면 모의 연습으로 전환하고 실기 미완료를 기록한다.
