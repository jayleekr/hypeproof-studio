# L1. 우리 치과 홈페이지, 무엇을 고칠지 판단하기

> 자동 생성 문서. 수정은 ../program.json에서 한다. 강사 검토 전 초안.

**수강생:** 박지훈 원장 (가상) (Reviewer)

상황: 홈페이지를 업체에 맡기고 수정은 메신저로 요청한다. 코드는 열어본 적이 없다.

막히는 지점: 좋아 보인다는 느낌은 있지만 무엇을 고쳐야 할지 말하기 어렵다.

시작 역량: 브라우저와 메신저 사용 가능

수강 후 행동: 환자가 해야 할 작업을 기준으로 시안의 문제와 수정 기준을 설명한다.

**목표:** 모바일 시안 2개를 비교해 3가지 수정 요청과 확인 기준을 작성한다.

준비: 코딩 경험 불필요. 가상 병원 컨텍스트와 starter/index.html 제공.

## 결과물

- review.md: 시안 비교·선택 이유·수정 요청 3개
- clinic-context.md: 대상 환자·우선 정보·확인할 사실

## 강사 진행안·학생 실습

### 0–15분 · 환자가 먼저 찾을 정보

강사 발화: “오늘은 예쁜 화면보다 환자가 필요한 정보를 찾는지 보겠습니다.”

가상 병원 컨텍스트를 읽고 첫 방문 환자의 질문 3개와 가장 중요한 행동 1개를 적는다.

Studio 요청 예시:

```text
온유 연습치과의 첫 방문 환자가 홈페이지에서 찾을 질문 후보를 제안해줘. 우선순위는 내가 고를 수 있게 이유를 붙여줘.
```

막혔을 때: 진료시간, 위치, 연락 방법부터 생각한다.

제출: clinic-context.md

완료 기준: 대상 환자·질문 3개·우선 행동 1개가 연결돼 있다.

### 15–30분 · 두 시안 비교 시연

강사 발화: “고급스럽다는 말 대신 어느 정보가 어디에 있는지 짚어봅시다.”

index.html과 reference-b.html을 폭 390px로 비교한다. 강사가 첫 항목을 시연하고 학생은 나머지 항목을 기록한다.

Studio 요청 예시:

```text
두 시안의 정보 순서와 글자 가독성을 비교할 질문 3개만 만들어줘. 내가 직접 화면을 보고 답할게.
```

막혔을 때: reference-b에는 의도적으로 작은 글자와 넓은 고정 폭이 있다.

제출: comparison.md

완료 기준: 실제 화면 위치를 지목한 비교 3개가 있다.

### 30–60분 · 수정 요청 작성

강사 발화: “변경 대상과 완료 조건을 함께 써야 같은 이야기를 반복하지 않습니다.”

원본에서 진료시간·위치·공지의 수정 요청 3개를 현재 상태/원하는 상태/확인 방법으로 쓴다.

Studio 요청 예시:

```text
내 수정 요청을 대상, 변경 내용, 확인 방법으로 정리해줘. 확인되지 않은 주소나 진료 정보를 만들어 넣지 마.
```

막혔을 때: 좋은 예: 첫 화면에서 진료시간 링크를 누르면 시간표로 이동한다.

제출: review.md

완료 기준: 3개 요청 모두 확인 가능한 완료 조건이 있다.

### 60–85분 · 상대가 이해하는지 확인

강사 발화: “짝이 요청만 읽고 어디를 바꿀지 찾을 수 있나요?”

짝에게 요청을 전달한다. 짝이 지목한 위치가 다르면 문장을 고친다.

Studio 요청 예시:

```text
이 요청에서 작업자가 되물을 만한 애매한 부분을 질문으로 알려줘.
```

막혔을 때: 요청 범위를 한 번에 한 요소로 줄인다.

제출: review.md의 수정 전후

완료 기준: 짝의 해석과 작성자의 의도가 일치한다.

### 85–110분 · 다른 시안 독립 평가

강사 발화: “이번에는 힌트 없이 새 조건으로 판단해봅시다.”

reference-b에서 가로 스크롤·작은 글자·찾기 어려운 시간표를 직접 확인하고 수정 요청을 쓴다.

막혔을 때: 도움이 필요하면 요청하되 도움 후 수행으로 기록한다.

제출: assessment.md: 발견 위치와 요청

완료 기준: 심은 3개 문제를 화면 근거와 함께 모두 설명한다. 힌트 사용 여부를 남긴다.

### 110–120분 · 내가 결정할 것 남기기

강사 발화: “AI와 업체가 제안해도 최종 정보와 방향은 원장이 결정합니다.”

직접 판단할 것·업체가 구현할 것·사실 확인할 것을 구분한다.

Studio 요청 예시:

```text
내 요청 목록을 판단/구현/사실 확인으로 나눠줘. 애매한 항목은 질문해줘.
```

막혔을 때: 시안 선택과 의료 내용 확인을 구분한다.

제출: review.md 마지막 인계 목록

완료 기준: 담당과 다음 확인 행동이 적혀 있다.

## 평가 기록 (수행 전 빈칸)

## 수업 후 자기 환경에서 할 일

자기 병원 공개 홈페이지에서 환자가 진료시간과 위치를 찾는 과정을 관찰하고 수정 요청 1개 작성. 실제 개인정보를 자료에 옮기지 않는다.

## 도구가 막히면

이 패키지는 강의 자료와 authoring API 자동화다. Studio 학생 UI·미리보기·배포·복구·MCP가 이 강의 전체를 지원한다는 실행 증거는 아직 없다. 미리보기가 막히면 로컬 HTML, 배포가 막히면 모의 연습으로 전환하고 실기 미완료를 기록한다.
