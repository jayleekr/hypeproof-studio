# L2. 진료시간·공지·FAQ를 직접 수정하기

> 자동 생성 문서. 수정은 ../program.json에서 한다. 강사 검토 전 초안.

**수강생:** 이수진 원장 (가상) (Editor)

상황: 홈페이지의 문제는 설명할 수 있지만 진료시간 수정도 업체를 기다린다.

막히는 지점: 작은 수정으로 레이아웃 전체가 깨질까 두렵다.

시작 역량: L1 수정 요청 작성 가능 또는 동등 실기

수강 후 행동: 기존 디자인 안에서 콘텐츠 3건을 수정하고 확인·복구한다.

**목표:** 예제 사이트의 콘텐츠 3건을 변경하고 모바일 검수와 원본 복원을 수행한다.

준비: L1 수준의 요구 설명. starter 폴더의 개인 복사본과 로컬 미리보기.

## 결과물

- 수정한 index.html
- change-log.md: 변경 3건과 확인 결과
- 수정 전 원본 사본

## 강사 진행안·학생 실습

### 0–15분 · 수정 범위와 원본 보관

강사 발화: “전체를 다시 만들지 않고 필요한 부분만 바꾸겠습니다.”

starter를 개인 폴더로 복사하고 index.html을 before.html로 보관한다. 변경할 항목 3개를 적는다.

Studio 요청 예시:

```text
진료시간, 공지, FAQ만 수정할 계획을 써줘. CSS와 다른 링크는 유지해줘.
```

막혔을 때: 파일 복사부터 확인한다.

제출: before.html·change-log.md

완료 기준: 원본 사본이 열리고 변경 범위 3개가 적혀 있다.

### 15–30분 · 시간표 한 항목 시연

강사 발화: “요청 후 화면을 확인하는 것까지가 한 작업입니다.”

강사가 화요일 종료 시간을 18:00에서 19:00로 바꾸고 전후를 비교한다.

Studio 요청 예시:

```text
화요일 진료 종료만 19:00로 바꿔줘. 다른 요일은 유지하고 바뀐 부분을 설명해줘.
```

막혔을 때: hours 표의 화요일 행을 찾는다.

제출: 시간표 변경 결과

완료 기준: 화요일만 달라지고 다른 요일은 동일하다.

### 30–60분 · 공지와 FAQ 직접 수정

강사 발화: “내용은 원장이 제공하고 AI는 편집을 돕습니다.”

가상 공지에 10월 9일 휴진을 추가하고 주차 FAQ를 제공된 가상 문장으로 바꾼다.

Studio 요청 예시:

```text
공지에 교육용 가상 일정인 10월 9일 휴진을 넣고, 주차 FAQ는 주차 안내는 방문 전 확인해주세요로 바꿔줘. 다른 내용은 유지해줘.
```

막혔을 때: 실제 병원 공지로 사용하지 않는다.

제출: index.html

완료 기준: 시간표·공지·FAQ 3건이 요청과 일치한다.

### 60–85분 · 모바일 검수와 되돌리기

강사 발화: “파일을 저장했다는 말 대신 화면이 맞는지 보겠습니다.”

390px 폭에서 글자·시간표·앵커 링크를 확인하고 before.html로 한 번 복원한 뒤 수정본을 다시 연다.

Studio 요청 예시:

```text
변경 3건을 사람이 확인할 체크리스트로 정리해줘. 통과 여부는 내가 확인해서 적을게.
```

막혔을 때: 화면 캐시로 헷갈리면 파일 이름과 새로고침을 확인한다.

제출: change-log.md·전후 화면 기록

완료 기준: 가로 잘림 없이 내용이 보이고 원본 복원을 실제로 했다.

### 85–110분 · 새 공지 독립 변경

강사 발화: “시연과 다른 내용을 혼자 바꿔봅시다.”

가상 휴진일을 10월 9일에서 10월 16일로 바꾸고 다른 내용이 유지됐는지 확인한다.

막혔을 때: 모르는 부분을 질문하면 도움 후 수행으로 기록한다.

제출: 독립 과제 파일·검수 기록

완료 기준: 새 날짜만 반영되고 다른 변경 2건이 유지된다.

### 110–120분 · 반복 작업 메모

강사 발화: “다음번에도 같은 순서로 할 수 있어야 합니다.”

수정 요청·원본 보관·검수·복구 순서를 자기 말로 적는다.

Studio 요청 예시:

```text
내가 실제로 수행한 순서만 재사용 메모로 정리해줘. 배포했다고 쓰지 마.
```

막혔을 때: 운영 배포는 이번 강의 범위가 아니다.

제출: change-log.md

완료 기준: 파일 수정과 운영 반영의 차이를 설명한다.

## 평가 기록 (수행 전 빈칸)

각 증거를 0=미제출/작동하지 않음, 1=힌트·도움 후 수행, 2=독립 수행으로 기록한다. 필수 증거 모두 2면 해당 작업의 독립 수행 확인. 평균 점수로 누락을 가리지 않는다. 실제 점수는 빈칸으로 시작한다.

## 도구가 막히면

이 패키지는 강의 자료와 authoring API 자동화다. Studio 학생 UI·미리보기·배포·복구·MCP가 이 강의 전체를 지원한다는 실행 증거는 아직 없다. 미리보기가 막히면 로컬 HTML, 배포가 막히면 모의 연습으로 전환하고 실기 미완료를 기록한다.
