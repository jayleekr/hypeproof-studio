# L3. 수정한 홈페이지를 검수하고 되돌리기

> 자동 생성 문서. 수정은 ../program.json에서 한다. 강사 검토 전 초안.

**수강생:** 최민석 원장 (가상) (Operator)

상황: 콘텐츠 수정은 가능하지만 배포와 장애 대응은 업체에 맡긴다.

막히는 지점: 어느 버전이 공개됐는지, 어떻게 복구하는지 모른다.

시작 역량: L2 수정·원본 복원 가능, 연습 저장소 접근

수강 후 행동: 연습 환경에서 변경 검수·배포·이전 버전 복구의 증거를 남긴다.

**목표:** 연습 환경에 변경을 반영하고 심은 링크 오류를 발견해 이전 버전으로 복구한다.

준비: L2 동등 실기. 강사가 사전 확인한 비운영 저장소·배포 환경. 없으면 모의 실습으로 표시하고 배포 실기 통과를 보류한다.

## 강사 진행안·학생 실습

### 0–15분 · 배포와 승인 기준

강사 발화: “저장과 공개는 다른 단계입니다.”

정상 버전 식별자와 연습 URL을 기록하고 어떤 상태면 배포를 멈출지 정한다.

Studio 요청 예시:

```text
진료시간 수정 배포의 중단 조건을 링크, 화면, 내용 기준으로 정리해줘.
```

막혔을 때: 실제 운영 계정 대신 연습 환경인지 먼저 확인한다.

제출: release-checklist.md

완료 기준: 배포 대상·정상 버전·중단 조건이 적혀 있다.

### 15–30분 · 변경 확인과 연습 배포 시연

강사 발화: “변경 파일과 화면을 함께 보겠습니다.”

강사가 작은 공지를 바꾸고 차이 확인→미리보기→연습 배포→URL 확인을 시연한다.

Studio 요청 예시:

```text
이번 변경에 없는 파일이 바뀌었다면 알려줘. 배포 실행 전 대상과 복구 버전을 먼저 보여줘.
```

막혔을 때: 계정 권한이 없으면 강사 환경에서 관찰하고 실기 미완료를 기록한다.

제출: 시연 관찰 메모

완료 기준: 저장 파일과 실제 열린 버전을 구분해 설명한다.

### 30–60분 · 내 변경 검수·연습 반영

강사 발화: “체크리스트 빈칸을 AI가 채우게 하지 마세요.”

L2 수정본을 연습 브랜치에 기록하고 390px·1280px 화면과 내부 링크를 확인한 뒤 비운영 URL로 반영한다.

Studio 요청 예시:

```text
검수 순서를 제안해줘. 확인 결과는 내가 입력할 때까지 미확인으로 둬.
```

막혔을 때: 도구 실패는 메시지와 시각을 기록한다.

제출: 연습 URL·버전·검수 결과

완료 기준: URL에서 바뀐 공지를 확인한다. URL 없이 배포 통과로 기록하지 않는다.

### 60–85분 · 링크 오류 발견·복구

강사 발화: “문제를 더 고치기 전에 정상 상태로 돌아갈 수 있어야 합니다.”

연습 사본의 시간표 링크를 #missing으로 바꿔 검사한다. 오류를 찾은 후 직전 정상 버전으로 복구한다.

Studio 요청 예시:

```text
현재 링크 오류의 범위를 확인하고 직전 정상 버전으로 돌아가는 절차를 제안해줘. 대상은 연습 환경이야.
```

막혔을 때: 도구가 없으면 파일 복원만 기록하고 배포 복구는 미완료로 둔다.

제출: rollback-log.md

완료 기준: 오류 링크를 발견하고 복구 후 시간표 이동을 다시 확인한다.

### 85–110분 · 다른 변경의 독립 운영

강사 발화: “이번에는 FAQ 변경을 같은 기준으로 운영해봅시다.”

가상 FAQ 한 문장을 변경하고 검수·반영·URL 확인·복구를 혼자 수행한다.

막혔을 때: 시간 초과 시 마지막 성공 지점을 기록한다.

제출: 독립 과제 URL·두 버전 식별자

완료 기준: 배포와 복구 각각의 실제 URL 확인 증거가 있다.

### 110–120분 · 도움 요청 기준

강사 발화: “혼자 해결하지 않을 조건도 운영 능력입니다.”

접근 권한 없음·복구 실패·정보 불일치의 담당과 연락할 때 필요한 증거를 적는다.

Studio 요청 예시:

```text
실패 단계, 대상, 마지막 정상 버전, 재현 방법을 담은 지원 요청 양식을 만들어줘.
```

막혔을 때: 비밀번호나 토큰은 요청에 넣지 않는다.

제출: rollback-log.md 인계 항목

완료 기준: 요청에 재현 방법과 복구 기준이 있다.

## 평가 기록 (수행 전 빈칸)

각 증거를 0=미제출/작동하지 않음, 1=힌트·도움 후 수행, 2=독립 수행으로 기록한다. 필수 증거 모두 2면 해당 작업의 독립 수행 확인. 평균 점수로 누락을 가리지 않는다. 실제 점수는 빈칸으로 시작한다.

## 도구가 막히면

이 패키지는 강의 자료와 authoring API 자동화다. Studio 학생 UI·미리보기·배포·복구·MCP가 이 강의 전체를 지원한다는 실행 증거는 아직 없다. 미리보기가 막히면 로컬 HTML, 배포가 막히면 모의 연습으로 전환하고 실기 미완료를 기록한다.
