HypeProof Lab Workshop

보아치과 AI 홈페이지 실습 큐시트

19:00-21:00 · 홈페이지 제작, 배포, GitHub 저장, AI agent 인수인계까지

운영 방식

수강생치과원장 11명
운영진메인강사 1명, 보조강사 5명
지원 배치보조강사 1명당 수강생 2명 담당, 11번째 수강생은 3인 포드 배치
메인강사는 보아치과 홈페이지를 만든다고 가정하고 스크린을 띄워 단계별로 진행한다. 수강생은 같은 단계에서 각자 병원 홈페이지를 만들고, 보조강사는 중간중간 막히는 부분을 현장에서 지원한다.

최종 결과물

1. 홈페이지본인 치과용 최종 홈페이지
2. 배포 URLCloudflare 또는 GitHub Pages URL
3. GitHub 저장소홈페이지 파일과 작업 히스토리 저장
4. agent.md다음 AI agent에게 넘길 인수인계 문서

사전 준비물

1. BOA 치과 완성 데모완성 홈페이지와 제작 채팅 로그
2. HypeProof Studio 등록 플로우설치, 학생 등록, 토큰 발급, 토큰 입력, 채팅 테스트 5분 컷
3. 배포 스킬Cloudflare, GitHub Pages
4. 디자인 스킬레이아웃과 시각 품질 자동 정리
5. Playwright MCP화면 검사와 루브릭 확인

Reference First

  • 보아치과 홈페이지 제작 화면 기준으로 실습 시작
  • 참고 홈페이지 URL만 넣고 1차 초안 생성
  • 참고 URL이 없는 경우 BOA 치과 주소 사용
  • 본인 치과 홈페이지 1차 초안 생성
URL만 줘도 AI는 빠르게 초안을 만든다. 결과는 참고 사이트의 분위기를 따라가지만, 우리 병원의 맥락은 아직 부족하다.
19:45-20:05

Context Engineering

  • 1차 초안에 병원 컨텍스트 추가
  • URL만 넣은 결과와 컨텍스트를 자세히 넣은 결과 비교
  • 본인 치과 컨텍스트 입력: 어필 포인트, 밀고 싶은 진료, 주요 환자층, 병원의 톤, 첫 화면 인상, 빼고 싶은 표현
  • 2차 초안 생성
  • 보조강사가 좋은 컨텍스트 사례 2-3개 수집
  • best-case 큐레이션: *봉호님 작성 예정
대충 URL만 넣었을 때와 병원 컨텍스트를 자세히 알려줬을 때의 결과 차이를 체감한다.
20:05-20:35

Loop Engineering

  • 홈페이지 평가 루브릭 작성
  • Playwright MCP로 화면 검사
  • 루브릭 미달 항목 확인
  • AI에게 수정 지시
  • 다시 검사
  • 루브릭을 만족할 때까지 검사와 수정을 반복
  • 보조강사가 좋은 루브릭/자동 개선 사례 2-3개 수집
  • best-case 큐레이션: *봉호님 작성 예정
루브릭을 정의하고, 그 기준을 만족할 때까지 AI가 계속 검사하고 고치게 한다. 핵심은 될 때까지 반복시키는 것이다.
