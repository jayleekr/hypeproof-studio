## 결론과 범위

**명확한 요청에 실행 대신 질문하는 결함을 실제 응답에서 발견했다.** 규칙을 덧붙인
첫 수정에서도 반복됐고, 프롬프트의 기본 진단 순서를 제거한 후 같은 시료에서 초안을
먼저 제공했다. 이는 각 버전의 두 합성 시료를 관측한 결과다. 성공률·일반화·학습 효과를
추정하지 않는다. T04 전체는 PARTIAL이며 다른 분기와 실제 앱 조합은 아래 미실행 상태다.

기존 `worker/test/native-personas-live.mjs`를 `HPS_NATIVE_LIVE=1`,
`HPS_NATIVE_PERSONAS=P1,P2`로 실행했다. 실제 Anthropic 모델은 `claude-sonnet-4-6`이다.
서버 개발 자격증명만 사용했고 원문은 모두 합성이다. 각 시료는 coach 요청과 별도 관찰
요청을 각각 한 번 보낸다. 스크립트의 PASS는 API/관찰 계약에 한정되며 대화 품질은
원본 응답을 읽어 별도로 판정했다. 새 채점 정규식이나 가짜 호스트 이벤트를 만들지 않았다.

원본 실패 응답은 음성 대조, P1의 단일 정보 질문과 마지막 P2의 실제 초안은 양성

두 P2의 실패를 놓친다는 점을 확인했다. 마지막 비교표의 가격·영양·업체 가용성은
검증하지 않았다. **실행 분기의 PASS가 생성 내용의 정확성이나 검증 완료를 뜻하지 않는다.**

원본 입력·공급자 응답/request ID·관찰 응답·스크립트 결과와 프롬프트/하네스 해시는
[근거 묶음](../research/agent-experience-acceptance-2026-09-08/product-intent/capture.json)에 있다.
세 실행의 동일한 P1/P2 입력과 하네스 해시를 대조했다. 실패를 지우거나 마지막 응답만
남기지 않았다. 이후 main 통합의 이름/문서 변경은 이 프롬프트의 SHA를 대체하지 않는다.
