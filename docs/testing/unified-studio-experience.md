## 합성 페르소나와 환경

| 페르소나 | 준비 상태 | 관측할 일 |
|---|---|---|
| 처음 온 성인 | 활동 없음, 유효 체험 코드 또는 미발급 | 시작 버튼 발견, 실제 자격 확인, 막막한 요청과 안내 |
| 체험 후 수업 참여자 | 자기 체험 파일/대화, 새 수업 참여 코드 | 전환·취소·복귀, 자료가 자동 공유되지 않음 |
| 두 수업 참여자 | 다른 정책/Module/예산을 가진 수업 A/B | 현재 활동 식별, 권한·도구·비용·문맥 격리 |
| 만료 후 재방문자 | 만료/소진된 활동과 로컬 산출물 | 새 실행 차단과 결과 열람·내보내기 양립 |
| 구버전 사용자 | 예전 앱 사본, localhost 자격, 별도 user-data | 백업·공개 연결·실행 경로 전환과 복구 |
| 담당 강사 | 수업 A 운영 권한만 있음 | 학생 개인 체험/수업 B 기록이 보이지 않음 |

모두 합성 사용자·자료를 사용한다. 기간·예산은 명시된 테스트 정책이며 실제 상품 조건이
아니다. 실제 참가자 정보·토큰·모델 키는 증거에 넣지 않는다. SDK·Service·UI 귀속을 확인하며
예제 결과물을 학생 수행으로 표시하지 않는다. 허용된 자기 프로세스만 종료한다.

## 실행 순서와 비용

1. UI/상태 전이/권한/예산/gate의 API 비용 없는 양성·실패 대조를 먼저 실행한다.
2. 기존 `e2e/native-trial.config.ts`, `scripts/test-native-trial-laptop.sh`, native trial checks와
   manifest를 확장한다. 새 UX는 현재 DOM과 완료 이벤트 확인 후 자동화한다.
3. 의미 판단이 필요한 US-T15와 최소 실제 SDK 인수만 승인된 모델 경로로 실행한다.
   요청·시간·동시성 상한을 실험마다 명시하고 실제 사용량을 기록한다. 구독/OAuth를
   Service 한도 우회나 무료 API 호출로 해석하지 않는다.
4. 최종 패키지는 주입 없는 산출물로 인수한다. OS별 App digest는 서로 다르지만
   같은 OS에서 체험/수업에 사용한 digest는 같아야 한다.
5. 공개 승격 전 비운영 후보·합성 자격으로 검증하고, 승인된 공개 검증 범위에서
   실제 배포 endpoint/profile/version을 확인한다. 새 참여자·운영 데이터를 만들지 않는다.

이 문서는 아직 없는 실행 파일명이나 CLI 옵션을 확정하지 않는다. 구현 PR이 기존 harness에
연결한 명령과 의존성·환경을 기록해야 한다. 기능이 미구현인 행은 NOT RUN, 실행에 필요한
환경/권한이 없는 행은 BLOCKED와 정확한 원인을 남긴다.

## 증거와 공개 게이트

각 런은 requirement/test ID, 환경·OS·App/extension/Service/Module revision, 실제 실행 경로,
검사기 commit, 합성 입력·응답·도구 결과·request 귀속, 파일 diff/hash·스크린샷,
PASS/FAIL/BLOCKED/NOT RUN 및 오류·재실행·복구 근거를 남긴다. 모델 원문은 합성 실험의
허용된 범위만 기록하며 credentials를 제외한다. 환경 파일은 기존 manifest를 확장해 사용한다.

- App: 최종 산출물 생성 후, 공개 stable/mirror 승격 전에 지원 OS의 체험·수업 인수.
- Service: 비운영 후보에서 현재 공개 App의 두 활동 및 정책/예산 회귀 후 공개 배포.
- Module: 대상 revision/pin과 영향을 받는 프로그램 확인. 무관한 강의의 pin까지 올리지 않는다.
- 공통 게이트: 불완전·오래된 증거·필수 OS 미실행은 공개 승격을 막는다. 마이그레이션으로
  사용자 앱 재시작이 필요하면 ‘업데이트 제공’과 ‘사용자 적용 완료’를 분리한다.
- 복귀: 이전 App/Service/Module 대상과 데이터 호환성을 미리 확보한다. 복구 검사도
  실행 결과여야 하며 실제 운영 DB를 파괴적으로 되돌려 테스트하지 않는다.

문서 발행 시 이 gate는 요구사항이다. 현행 워크플로가 강제한다고 주장하지 않는다.
US-T21의 사람 관찰은 기술 release gate와 별도 채택 근거다. 사람 관찰 없이 기술 인수를
보고할 수는 있지만 쉬운 전환/이해도/학습 효과를 검증했다고 쓰지 않는다.

## #916 P0 진입 구현 검사

[실행 기록](unified-entry-916-evidence.md)은 공통 진입의 부분 검증이다. 위 US-T 행 전체 인수와 공개 배포 상태는 별도다.
