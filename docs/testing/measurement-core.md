## Jay 실제 수용

1. Jay가 평소 하려던 실제 제품 작업을 최소 3건 수행한다. Claude Code와 Codex 각각에서 기록·검토·제출을 확인하고, 한 작업은 두 host 사이를 이동한다. 세션 수를 작업 수로 세지 않는다.
2. 실패·수정·미확인 중 실제 발생한 사례를 포함한다. 현실에서 안 생긴 사례는 제품 fault test로 따로 검증하고 실사용 발생으로 꾸미지 않는다. 부족한 실제 사례는 수용 범위의 미관찰로 남긴다.
3. Jay가 근거를 열고 해석을 확인하거나 정정한다. 화면상 자기 이름과 AI가 작성한 확인 문구만으로 사용자 검토 완료 처리하지 않는다.
4. 제출된 묶음·접수·공유 제외 내용을 확인한다. 최소 하나의 개선점을 다음 작업과 연결하고 후속 시도 여부·관찰된 결과·미확인을 기록한다.
5. Jay가 가치·부담·신뢰를 검토해 확대/수정/중단을 결정한다. 편했는지, 틀린 해석이 무엇이었는지, 기록을 다시 썼는지와 소요 시간을 남긴다.

3건과 100회 지연 측정은 경로 확인을 위한 최소 수용 표본이다. 학습 효과나 역량 모델의 타당성 입증을 뜻하지 않는다. 원격 팀 제출은 이 수용의 성공 범위가 아니다. Studio는 기존 앱/extension의 실제 연결 검증이 필요하며 동일 함수의 단위 테스트만으로 세 호스트 재사용 완료를 선언하지 않는다.

## 실행 기록 양식

각 구현 PR은 test ID, commit, host·core·adapter·schema/모델 revision, 환경, 실행 주체, 입력 출처, 기대/실제, PASS/FAIL/NOT RUN, 근거 위치, 미관찰 범위를 기록한다. 사용자 로그를 공개 저장소에 올리지 않고 공개 보고에는 가린 요약·비식별 fixture만 사용한다.

현재 위 시험은 전부 NOT RUN이다. 기존 Studio 시험 결과는 해당 기존 기능에만 유효하다. 이 문서의 모든 P0 시험이 충족되고 Jay 실제 수용이 확인되어야 #1020의 첫 dogfood 완료를 판단한다.
