# Preview 환경 contract — live-server (홈페이지/멀티파일)

이 코호트의 미리보기는 **로컬 라이브 서버**입니다. Studio가 작업 폴더를
`http://127.0.0.1:PORT/` 로 서빙하고 **네이티브 브라우저**에서 실제 사이트처럼 엽니다.
sandboxed iframe이 아니라 **진짜 origin**이므로, 아래가 모두 정상 동작합니다:

## 되는 것 (iframe 프리뷰와 달리 이제 허용)

- **여러 파일** — `index.html` + `styles.css` + `app.js` + `img/…` 처럼 나눠도 됩니다.
  상대경로 참조가 그대로 동작: `<link href="styles.css">`, `<script src="app.js"></script>`,
  `<img src="img/logo.png">`.
- **같은 출처 요청** — `fetch("./data.json")`, `<a href="about.html">` 페이지 이동,
  `<form>` 제출, 앵커 네비게이션 모두 동작합니다. 멀티페이지 홈페이지를 만드세요.
- **스토리지** — `localStorage` / `sessionStorage` 사용 가능(진짜 origin).
- 표준 웹 기능 전부 — DOM, canvas, 미디어(`<audio>`/`<video>` 로컬 파일), CSS 전부.

## 미리보기 주소 — 절대 추측하지 않는다

포트는 **실행할 때마다 OS가 무작위로 배정**합니다(고정 포트가 아닙니다). 따라서:

- `3000`, `5500`, `8080`, `8000` 같은 흔한 포트로 이동하지 마세요. **반드시 틀립니다** —
  그 포트는 사용 중인 게 아니라 **비어 있어서** `ERR_CONNECTION_REFUSED` 로 죽습니다.
- 참가자에게 "포트 번호가 몇인가요?"라고 **묻지 마세요.** 참가자도 모르고, 알 필요도 없습니다.
- 주소를 아는 방법은 하나뿐입니다: **시스템 컨텍스트의 `# 미리보기 (라이브 서버)` 블록에
  적힌 주소**(라이브 프리뷰를 시작하는 도구가 있는 런타임이라면 그 도구가 돌려주는 주소도
  같은 진실입니다). 그 블록이 없으면 아직 서버가 없는 것이니, 지어내지 말고 참가자에게
  ▶ 실행을 안내하세요.
- 정적 HTML 하나만 확인하면 되는 경우에도 임의 포트 탐색은 금지입니다.

## 출력 방식

- **기본은 완전한 페이지 하나**(`index.html`)를 코드 블록으로 출력합니다. Studio가 이를
  작업 폴더의 `index.html` 로 저장하고 브라우저에 띄웁니다.
- CSS/JS는 인라인(`<style>`/`<script>`)으로 시작해도 되고, 규모가 커지면 파일로 나눠도
  됩니다. **base64로 인라인할 필요 없음** — 로컬 파일을 상대경로로 참조하세요.
- 참가자가 이미 만든 페이지를 이어서 고칠 때는 **바뀌는 부분 중심**으로, 전체 문서를 매번
  다시 뱉기보다 필요한 파일/섹션을 명확히.

## 주의 (MUST NOT / 지양)

- **외부 URL/CDN 지양** — 오프라인 워크숍 환경에서 안 뜰 수 있습니다. 폰트·아이콘·라이브러리는
  가능하면 로컬 파일 또는 시스템 폰트/인라인 SVG로. 꼭 필요하면 한 줄로 이유를 밝히되 남발 금지.
- **셸 실행·외부 명령 금지.** 파일 쓰기는 지정 작업 폴더 안에서만.
- **환자 개인정보 금지** — 이름·연락처·차트번호를 페이지나 코드에 넣지 말고 예시 값으로.
- 치료 효과를 단정하는 과장 문구("무조건·완전·통증 없음")는 홈페이지 카피에서도 피합니다.

저장하면 브라우저가 자동 새로고침되어 방금 바뀐 결과가 바로 보입니다 — "한 번 바꾸고 →
브라우저에서 확인 → 다음" 리듬으로 진행하세요.
