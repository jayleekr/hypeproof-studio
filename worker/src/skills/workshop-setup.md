# 스킬: 환경 세팅 점검 — Jay 의 설치 스크립트를 그대로 돌린다

참가자가 **환경 세팅·도구 점검을 명시적으로 요청**했을 때만 이 스킬을 따른다
(첫 화면 칩 "환경 세팅 점검해줘" 가 정식 입구다). 홈페이지 만들기 도중에
끼어드는 스킬이 아니다.

**이 스킬에 자체 설치 로직은 없다.** 공식 설치 스크립트를 그대로 실행하고,
그 스크립트의 판정(doctor)을 그대로 전달하는 것이 전부다. 스크립트는 도구별로
"이미 있으면 건너뜀"이라 **이미 세팅된 사람이 발동해도 무해하다** — 전부
present 로 찍히고 30초 안에 끝난다.

## 어느 쪽인지는 작업 폴더 경로가 말해준다

```
C:\ 로 시작              → Windows. 아래 절차를 실행한다
/Users/ · /home/ 로 시작  → macOS. 실행하지 말고 이 한 줄만 안내한다
```

> **macOS 안내문**: "맥은 다운로드 페이지의 **[🍎 Mac 설치]** 버튼으로 해주세요 —
> 터미널에 붙여넣기 한 번이면 전부 설치됩니다. 막히면 스태프를 불러 주세요."
>
> 페이지 주소는 정확히 이것이다 — **다른 주소를 지어내지 마라**:
> `https://hypeproof-ai.xyz/adult-edu/boa#download` (browser_open 으로 열어줘라)"
>
> 이유(참가자에게 설명할 필요는 없다): 새 맥은 설치 중 관리자 암호를 물어야
> 하는데, 여기(앱 속 셸)서는 암호를 받을 수 없다. 터미널에서는 된다.

## Windows 절차

### 1. 백그라운드로 띄우고 로그로 지켜본다

설치는 수 분 걸리고 셸 도구는 2분에 끊긴다. **그대로 실행하면 중간에 끊겨
"반쯤 하다 만 것"처럼 보인다.** 아래를 통째로 그대로 실행해라 — 손대면
오늘까지 세 번 깨진 그 자리다:

```powershell
Start-Process powershell -WindowStyle Hidden -ArgumentList '-ExecutionPolicy','Bypass','-Command',"`$env:HPS_SKIP_STUDIO='1'; `$env:HPS_NONINTERACTIVE='1'; irm https://raw.githubusercontent.com/jayleekr/hypeproof-studio/main/scripts/install.ps1 | iex *> `$env:TEMP\hps-setup.log"
Start-Sleep 5
Get-Content "$env:TEMP\hps-setup.log" -Tail 15
```

`HPS_SKIP_STUDIO=1` 은 "앱은 이미 깔려 있으니 도구만" 이라는 공식 플래그다.
앱 설치 블록이 빠지는 것 외에는 터미널에서 돌리는 것과 완전히 같다.

### 2. 판정 줄을 "로그에서 인용" 하기 전에는 결론이 없다

마지막으로 읽은 로그에 `==> doctor:` 로 시작하는 줄이 **없으면 아직 안 끝난
것이다.** 그때 할 수 있는 말은 "아직 설치 중이에요(지금 git 까는 중)" 뿐이고,
반드시 다시 읽어야 한다:

```powershell
Start-Sleep 30; Get-Content "$env:TEMP\hps-setup.log" -Tail 15
```

`==> doctor:` 줄이 나올 때까지 이걸 반복해라 (설치는 보통 3~8분, 최대 10회).

결론을 말할 때는 **그 판정 줄을 로그에서 그대로 복사해 인용**하고 시작해라:

> 로그 판정: `==> doctor: ALL CHECKS PASSED`

**인용할 줄이 없으면 결론도 없다.** "OK … installed" 줄 몇 개를 보고 성공을
추정하는 것은 이 스킬이 금지하는 바로 그 행동이다 — 진행 중 로그에도 OK 줄은
계속 찍힌다. 실사용 검증에서 코치가 진행 중 로그만 보고 "ALL CHECKS PASSED" 를
지어내 선언한 사례가 실제로 있었다. 그 말을 믿고 참가자는 수업을 시작한다.

```
==> doctor: ALL CHECKS PASSED     → 성공. 3단계로
==> doctor: FAILURES              → 실패. XX 줄들을 그대로 인용해 보고
```

UAC(사용자 계정 컨트롤) 창이 참가자 화면에 뜰 수 있다. 그건 정상이고
**[예]를 눌러 달라**고 안내해라. UAC 를 눌렀다는 답이 와도 그것은 설치가
끝났다는 뜻이 아니다 — 판정 줄이 나올 때까지 계속 읽는다.

### 3. 성공 후 — 새로 깐 게 있으면 재시작 한 번

로그에서 구분할 수 있다:

```
"... present ("   만 있음   → 원래 다 있었음. 재시작 불필요. "이미 준비돼 있었어요 ✓"
"... installed (" 가 있음   → 새로 깔린 것이 있음. 아래 안내:
```

> "설치 끝났어요! 딱 하나만 — **앱을 완전히 종료했다가 다시 열어 주세요.**
> 새로 설치된 도구를 앱이 인식하려면 한 번 껐다 켜야 해요. 다시 만나요!"

이유: 이미 켜져 있는 앱은 예전 환경을 물고 있다. 재시작해야 새 PATH 를 읽는다.

### 4. 실패했을 때

- 로그의 `XX` 줄을 **그대로** 전달하고, 성공한 척하지 마라
- 이 세팅이 실패해도 **수업은 계속된다** — 홈페이지 만들기는 지금 이대로 되고,
  깃허브 올리기는 브라우저로 직접 올리는 정식 폴백이 있다
- 네트워크류 실패면 한 번만 재실행해 본다 (스크립트가 멱등이라 안전).
  두 번째도 실패면 스태프를 불러 달라고 안내

## 하지 마라

- doctor 판정 없이 "됐다"고 말하지 마라
- macOS 에서 설치를 시도하지 마라 — 안내 한 줄이 전부다
