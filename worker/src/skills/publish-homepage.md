# 스킬: 홈페이지를 인터넷에 올리기

참가자의 홈페이지를 **실제로 열리는 주소**로 만든다. 큐시트 20:35 블록.

참가자는 git을 모른다. GitHub 아이디만 있으면 된다 — 나머지는 네가 하고,
참가자가 눌러야 하는 것만 짚어준다.

## 절대 규칙 — 주소를 지어내지 마라

**열리는 것을 확인하기 전에는 주소를 말하지 마라.** 배포했다고 쓰고 URL을
덧붙이는 것은 최악의 실패다. 참가자는 그 주소를 받아적고 집에 가서 404를 본다.

주소를 말하기 전에 반드시:

```
curl -sIL -o /dev/null -w "%{http_code}\n" <주소>
```

200이 아니면 아직 배포된 게 아니다. 그렇게 말해라. GitHub Pages는 첫 배포에
1~2분 걸리니 "지금 만들어지는 중, 1분 뒤 다시 확인할게요"가 정직한 답이다.

## 0. 정적인가 동적인가

먼저 판단한다. 물어볼 것도 있고 파일을 보면 아는 것도 있다.

- **정적** — HTML/CSS/JS/이미지뿐. 치과 홈페이지는 거의 항상 여기다 → **1번 경로**
- **동적** — 서버가 필요하다(폼 접수 저장, DB, 예약 API, 서버사이드 렌더링)
  → **2번 경로**

애매하면 정적으로 본다. 지금 만든 것이 브라우저만으로 도는지 확인하면 된다.

## 1. 정적 → GitHub Pages (집에 가져가는 주소)

git은 쓰지 않는다. macOS의 `/usr/bin/git`은 껍데기라서 부르면 참가자 화면에
"명령어 라인 개발자 도구 설치" 창이 뜨고 2GB를 받는다. **수업 중에 절대 하지
마라.** `gh` 하나로 API를 통해 전부 처리한다.

### 1-1. gh 준비

이미 있으면 건너뛴다:

```
command -v gh || ls ~/Library/Application\ Support/HypeProof-Studio/bin/gh
```

없으면 받는다. **파일 이름을 직접 조립하지 마라** — 버전이 바뀌면 404가 난다.
릴리스 API가 주는 `browser_download_url`을 그대로 쓴다:

```
mkdir -p ~/Library/Application\ Support/HypeProof-Studio/bin
curl -sL https://api.github.com/repos/cli/cli/releases/latest \
  | grep -o '"browser_download_url": *"[^"]*macOS_arm64\.zip"' \
  | head -1 | cut -d'"' -f4
```

나온 주소를 그대로 `curl -L -o /tmp/gh.zip <주소>` 하고, `unzip`으로 풀어
`gh_*/bin/gh`를 위 `bin/`으로 옮긴다. `curl`·`unzip`·`tar`는 모든 맥에 있으니
따로 설치할 것이 없다. sudo도 필요 없다.

설치 명령은 참가자에게 **뭘 왜 받는지 한 줄로 설명하고** 승인을 받아라.
인터넷에서 실행 파일을 받는 일이다 — 조용히 지나가면 안 된다.

### 1-2. 로그인 (참가자가 8자만 친다)

```
gh auth login --hostname github.com --git-protocol https --web
```

코드가 나온다(예: `A1B2-C3D4`). 참가자에게:

> 브라우저가 열리면 이 여덟 글자를 넣어주세요: **A1B2-C3D4**

브라우저는 네가 열어준다. 참가자는 이미 GitHub에 로그인돼 있으니 코드만
넣으면 끝난다. 비밀번호도 토큰도 만들 필요 없다.

되면 확인:

```
gh api user --jq .login
```

### 1-3. 저장소 만들고 파일 올리기

참가자에게 저장소 이름을 제안하고 동의를 받는다(예: `boa-dental`).
이름은 주소에 그대로 들어간다고 알려줘라.

```
gh repo create <이름> --public
```

파일은 Contents API로 올린다. 각 파일마다:

```
gh api -X PUT repos/{owner}/<이름>/contents/<파일명> \
  -f message="홈페이지 올리기" \
  -f content="$(base64 -i <파일경로>)"
```

`index.html`을 먼저, 그다음 이미지들. 이미지도 같은 방식으로 올라간다
(base64라서 바이너리도 된다).

### 1-4. Pages 켜기

```
gh api -X POST repos/{owner}/<이름>/pages -f "source[branch]=main" -f "source[path]=/"
```

주소는 `https://<아이디>.github.io/<이름>/` 이다. **여기서 바로 말하지 말고**
위의 `curl -sIL`로 200을 확인한 뒤에 말해라. 1~2분 걸린다.

### 1-5. 참가자에게 남기기

주소가 열리면:

- 브라우저로 열어 보여준다
- 이 주소는 **영구적**이고, 노트북을 꺼도 살아 있다고 알려준다
- 나중에 고치려면 같은 저장소에 파일을 다시 올리면 된다고 알려준다

## 2. 동적이거나 1번이 막힐 때 → Cloudflare 빠른 터널

로그인이 필요 없다. 지금 도는 화면을 그대로 인터넷에 노출한다.

### 2-1. cloudflared 준비

`gh`와 같은 방식이다. 파일명을 조립하지 말고 릴리스 API를 쓴다:

```
curl -sL https://api.github.com/repos/cloudflare/cloudflared/releases/latest \
  | grep -o '"browser_download_url": *"[^"]*darwin-arm64\.tgz"' \
  | head -1 | cut -d'"' -f4
```

받아서 `tar -xzf`로 풀고 같은 `bin/`에 둔다. 18MB 정도다.

### 2-2. 터널 열기

Studio의 미리보기 서버가 이미 `http://127.0.0.1:<포트>` 로 돌고 있다. 그 포트에
붙인다:

```
cloudflared tunnel --url http://127.0.0.1:<포트>
```

출력에 `https://<무작위>.trycloudflare.com` 이 나온다. 이것도 `curl -sIL`로
200을 확인하고 말해라.

### 2-3. 반드시 알려줄 것

이 주소는 **임시다.** 터널을 닫거나 노트북을 덮으면 죽는다. 참가자가 "집에
가져가는 주소"로 오해하면 안 된다. 정확히 이렇게 말해라:

> 지금 바로 폰으로 열어볼 수 있는 주소예요. 다만 노트북을 덮으면 꺼집니다.
> 계속 살아있는 주소가 필요하면 GitHub Pages로 올려드릴게요.

정적 사이트인데 이 경로로 왔다면(예: 로그인이 안 풀렸다) 수업이 끝나기 전에
1번 경로를 한 번 더 시도해서 영구 주소를 만들어 준다.

## 막혔을 때

**막힌 것을 막혔다고 말해라.** 우회해서 성공한 척하는 것이 가장 나쁘다.

| 증상 | 대응 |
|---|---|
| `gh auth login` 코드 입력이 안 끝남 | 브라우저에서 GitHub 로그인 여부부터 확인. 다시 시도 |
| 저장소 이름 중복 | 다른 이름을 제안하고 참가자 동의를 받아라 |
| Pages 주소가 계속 404 | 1~2분 더 기다린다. 5분 넘으면 Settings→Pages 화면을 열어 참가자와 같이 본다 |
| 다운로드가 느림/실패 | 행사장 와이파이일 수 있다. 2번 경로(18MB)가 더 가볍다 |
| 어느 것도 안 됨 | 정직하게 말하고 파일은 안전하게 남아 있다고 알려줘라. 강사를 부르는 것도 방법이다 |

## 이 스킬이 가르치는 것

**Ownership.** 참가자는 자기 이름으로 된 저장소와 주소를 갖고 나간다. 네가
대신 해주는 것이 아니라, 참가자의 계정에 참가자의 것으로 올라간다.

**Verification reflex.** 배포했다는 말은 주소가 200을 돌려줄 때만 한다.
"됐어요"와 "확인했어요"는 다른 말이고, 참가자도 그 차이를 배워야 한다.
