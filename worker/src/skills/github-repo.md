# 스킬: GitHub 저장소에 내 것으로 올리기

참가자의 작업을 **참가자 계정의 저장소**로 올린다. 큐시트 최종 결과물 3번.

이 문서는 순서를 지시하지 않는다. **순서는 당신이 정한다.** 여기 있는 것은
당신이 실행해 보기 전에는 알 수 없는 사실들과, 어겨서는 안 되는 것 셋이다.

## 절대 하지 마라

**git 을 부르지 마라.** macOS 의 `/usr/bin/git` 은 껍데기(CLT stub)다. 부르는
순간 참가자 화면에 **"명령어 라인 개발자 도구 설치" 창이 뜨고 2GB 를 받는다.**
회차가 거기서 끝난다. Windows 에도 git 이 없을 수 있고 설치시키면 같은 함정이다.
`gh` 하나로 생성·업로드·설정이 전부 된다.

**브라우저로 GitHub 을 조작하지 마라.** 저장소 생성·파일 업로드·Pages 설정을
`browser_click`/`browser_type` 으로 하지 마라. 느리고, 로그인 상태·팝업·레이아웃
변경에 깨지고, 실패해도 어디서 틀렸는지 남지 않는다. `gh api` 는 결과가 JSON 으로
돌아와 **실재를 확인할 수 있다** — "확인하고 말하기"가 거기서 나온다. 브라우저는
셋에만 쓴다: 로그인 코드 화면 열어주기 · 다 된 뒤 보여주기 · 수동 폴백 안내.
셋 다 참가자가 보거나 누르는 용도다.

**참가자에게 명령을 붙여넣으라고 시키지 마라.** 실행 도구를 가진 것은 당신이다.

## 참가자는 이런 상태다

- **터미널이 없다.** "복사해서 터미널에 붙여넣으세요" 는 실행 불가능한 지시다
- 방금 가입했을 수 있다. **아이디와 비밀번호만 안다** — 토큰도 SSH 키도 없다
- git 을 모르고, 알 필요도 없다
- **"모르겠어요 / 알아서 해주세요" 는 진행하라는 뜻이다.** 되묻지 마라
- 참가자만 아는 값(저장소 이름)만 물어라. 나머지는 명령으로 알아낸다.
  계정이 있는지, 로그인이 됐는지는 **묻지 말고 `gh api user` 로 확인해라**

## 알아야 할 것

실행해 보기 전에는 알 수 없는 것들이다. 나머지는 당신이 판단해라.

| 사실 | 그래서 |
|---|---|
| `gh auth login` 을 플래그 없이 부르면 화살표 메뉴(TUI)가 떠서 **응답 없이 멈춘다** | `--web --hostname github.com --git-protocol https` 를 항상 명시 |
| `--web` 도 참가자가 승인할 때까지 **반환하지 않는다** | 아래 "로그인" 참조 |
| 릴리스 자산 파일명을 손으로 조립하면 버전이 오를 때 404 | `browser_download_url` 을 릴리스 API 에서 받아 쓴다 |
| Windows 에 `base64` 명령이 없다. `certutil -encode` 는 머리말이 붙어 깨진다 | `powershell -Command "[Convert]::ToBase64String([IO.File]::ReadAllBytes('<경로>'))"` |
| Contents API 로 **덮어쓸 때는 `sha` 가 필요하다** | 없으면 409. `gh api repos/{owner}/<이름>/contents/<파일> --jq .sha` |
| `.github/workflows/` 파일은 `workflow` 스코프 없이 못 올린다 | 로그인 때 `--scopes repo,workflow` |
| 저장소 이름은 주소에 그대로 들어간다 (`<아이디>.github.io/<이름>/`) | 이름은 **제안하고 동의를 받는다.** 임의로 바꾸지 않는다 |
| 갓 만든 계정은 **이메일 인증 전 저장소 생성이 막히는 것으로 보인다** (미확인) | 미리 분기하지 마라. 에러를 읽고 "메일함 확인" 으로 넘겨라 |
| gh 설치는 sudo 가 필요 없다 | 받아서 풀고 실행 파일을 옮기면 끝. 다만 **뭘 왜 받는지 설명하고 승인받아라** |

## 로그인 — 명령이 끝나기를 기다리면 안 된다

`gh auth login --web` 은 참가자가 브라우저에서 승인할 때까지 **반환하지 않는다.**
그냥 실행하면 서로 상대를 기다리다 몇 분이 날아간다. 게다가 **코드가 그 명령의
출력에 갇혀 있어서 참가자는 뭘 입력해야 하는지조차 못 본다.**

띄워놓고 코드만 꺼내라:

```
nohup gh auth login --web --hostname github.com \
      --git-protocol https --scopes repo,workflow \
      < /dev/null > /tmp/hps-ghlogin.log 2>&1 &
sleep 3
grep -oE '[A-Z0-9]{4}-[A-Z0-9]{4}' /tmp/hps-ghlogin.log | head -1
```

여덟 글자를 **참가자에게 크게 보여주고** `https://github.com/login/device` 를
열어준다. 브라우저가 GitHub 에 로그인돼 있으면 코드만 넣으면 끝이다 —
**비밀번호도 토큰도 새로 만들 필요 없다.**

끝났는지는 그 프로세스가 아니라 **결과로** 확인한다:

```
gh api user --jq .login
```

계정이 아예 없는 사람은 이 화면에서 스스로 드러난다("Sign up" 을 눌러야 하는
상황). 그때 `github.com/signup` 을 열어주고 한 번에 한 단계씩 읽어주면 된다 —
이메일 · 비밀번호 · **아이디(주소에 들어간다고 미리 말해줘라)** · 확인 코드.
가입이 끝나면 브라우저가 로그인 상태가 되니 위 로그인으로 돌아온다.

`nohup` 은 Windows 에 없다. PowerShell `Start-Process -NoNewWindow
-RedirectStandardOutput` 로 같은 모양을 만들 수 있으나 **실기기 미검증이다(#451).**
한 번에 안 되면 붙잡지 말고 수동 폴백으로 가라.

## 막혔을 때

**막힌 것을 막혔다고 말해라.** 우회해서 성공한 척하는 것이 가장 나쁘다.

| 증상 | 대응 |
|---|---|
| 로그인 코드가 안 끝남 | 브라우저의 GitHub 로그인 여부부터. 코드는 15분 뒤 만료 — 다시 띄우면 새 코드가 나온다 |
| 저장소 이름 중복 | 다른 이름을 **제안**하고 동의를 받아라 |
| 다운로드가 느림/실패 | 행사장 와이파이다. 수동 폴백으로 |
| 계정이 없음 | 3분이면 된다. 부끄러워할 일이 아니라고 짚어줘라 |
| Windows 에서 막힘 | 붙잡지 말고 수동 폴백. 실기기 미검증 경로다(#451) |
| `gh` 가 안 돼서 브라우저로 하고 싶어짐 | **하지 마라.** 코치가 클릭해 만드는 경로는 없다. 수동 폴백으로 |
| 어느 것도 안 됨 | 정직하게 말해라. 파일은 워크스페이스에 안전하게 있다 |

**수동 폴백** — 참가자가 직접 한다. **Windows 에서는 이쪽이 더 빠를 수 있다.**
부끄러운 우회가 아니라 정식 경로다. 브라우저와 폴더를 열어주고 한 번에 한 단계씩:

① `github.com/new` → 이름 → **Public** → Create repository
② 빈 저장소 화면의 **"uploading an existing file"** 링크
③ 워크스페이스 폴더를 열어주고(macOS `open <폴더>` · Windows `explorer <폴더>`)
   `index.html`·`agent.md` 를 끌어다 놓기
④ **Commit changes**
⑤ 새로고침해서 파일이 보이는지 **같이 확인한다**

## 끝내고 나면

저장소 주소를 브라우저로 열어 보여주고, **참가자 계정의 참가자 것**이라고 분명히
말한다. 올린 뒤에는 말하기 전에 확인해라 — `gh api repos/{owner}/<이름>/contents
--jq '.[].name'`. 배포까지 가려면 `publish-homepage` 로 이어간다.

## 이 스킬이 가르치는 것

**Ownership.** 결과물이 참가자 계정에 참가자 이름으로 남는다. 오늘 수업이
끝나도 참가자 것이고, 다른 도구로 이어서 할 수 있다.
