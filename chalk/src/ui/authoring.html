02 · 커리큘럼
이번 주 미션 · 완료 조건 — 학생 Studio 맨 위에 보입니다 미션을 두지 않으면 학생 화면에는 ‘미션이 정해지지 않았습니다.’가 그대로 보입니다. 제목이나 목표로 미션을 대신 만들지 않습니다.

완료 조건 (선택 · 10개까지)

학생 화면에는 모두 ‘확인 전(☐)’으로 보입니다. 학생이 실제로 남긴 기록이 생기기 전에는 완료로 표시하지 않습니다. 기록 종류는 어떤 기록이 이 조건의 근거가 되는지입니다.

    추가 자료 · AI 설정 학생 Studio의 헤더와 답변 이름에 그대로 표시됩니다(40자 이내, 한 줄). 비우면 코호트 기본 규칙(고정 이름 또는 학생이 직접 짓기)을 따르고, 이름을 넣으면 학생이 지은 이름 대신 이 이름이 고정됩니다. 이름은 도구 권한·모델·AI 고지를 바꾸지 않습니다. 버전을 고정한 뒤의 편집은 새 버전에만 적용됩니다.

    코호트가 허용한 모델 안에서 선택합니다. 설정은 새 확정 버전부터 적용됩니다.

    한 모델로 고정하면 답변과 보조 요청에 같은 모델을 사용합니다. 모델 변경은 새 버전을 고정하고 학생 조건으로 리허설한 뒤 배정하세요.
    Effort
    먼저 수업 모델 목록을 불러오고 모델 사용 방식을 정하세요. 지원 모델에만 적용되며, 같은 설정이라도 모델마다 속도와 사용량이 다릅니다.

    코호트가 이미 가진 기능 중에서 줄이기만 합니다. 여기서 새 권한이 생기지는 않습니다.

    고른 기능만 이 수업에서 켜집니다. 나머지는 꺼집니다. 여기서 코호트에 없는 기능이 생기지는 않습니다. 브라우저는 실행 경로와 무관하게 하나로 묶여 있습니다.

    수업 진행 순서

    각 활동에서 무엇을 하고, 무엇을 확인할지 적어주세요.

    03 · 바뀌는 내용 확인 · 확정 버전 다시 쓰기

    저장한 초안이 확정된 버전과 비교해 학생에게 무엇이 달라지는지 봅니다. 확정된 버전의 내용이나 단계 하나를 가져와 새 초안으로 고칠 수도 있습니다. 학생 기록·명단·참여 코드·사용량은 가져오지 않습니다.

      04 · 학생 조건 리허설

      저장한 초안을 바꿀 수 없는 리허설 후보로 고정한 뒤, 강사 권한이 아닌 학생 코드로 Studio에서 실제로 실행해 봅니다. 후보를 고정하거나 코드를 발급한 것만으로는 준비가 끝나지 않습니다.

      버전 정보 
      
세션 콘솔에서 연습 세션을 열고 이 ID를 명단에 등록한 뒤 발급하세요. 실제 학생 ID 대신 리허설 전용 ID를 쓰세요.



      Studio에서 이 코드로 들어가 단계마다 화면을 열어 보고 AI에게 한 번 이상 물어본 뒤 ‘리허설 결과 보내기’를 누르세요. 결과는 Service가 그 코드로 실제 실행된 요청과 맞춰 판정합니다.
      


      후보를 고정하면 리허설 상태가 여기 나옵니다.
      

      리허설 근거 — 강의 digest · App · 실행 요청
      

      

      05 · 수업 버전 확정

      리허설을 통과한 바로 그 후보만 확정할 수 있습니다. 확정해도 진행 중인 수업은 바뀌지 않습니다.
      

      

      

      06 · 학생에게 보내기

      진행 중인 수업에서는 운영 보드의 ‘보내기 → 수업 설정’에서 확정한 버전을 고른 학생에게 보냅니다. 고른 학생만 다음 질문부터 바뀌고, 이미 쓴 초안·대화·파일은 그대로입니다. 새로 들어오는 학생에게는 아래 ‘학생 초대’에서 이 버전의 참여 코드를 발급합니다.
