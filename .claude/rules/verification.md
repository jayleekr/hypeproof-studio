# 검증 규율 — 짐작으로 판정하지 않는다

큐시트 검증 하네스(`e2e/`, `docs/rubric-boah-cuesheet-runthrough.md`)를 쓰거나
고칠 때 로드된다. 2026-07-25~26 첫 완주에서 **하네스가 9번 틀린** 경험에서 나왔다.

## 왜 이 문서가 있나

커리큘럼 검증은 2중 루프다.

```
바깥 루프   큐시트 → 제품이 이걸 지탱하나 → 실기기 검증
안쪽 루프   하네스 → 이게 제대로 재나 → ???
```

안쪽에 검증이 없으면 **검증되지 않은 계측기로 제품을 판정**하게 된다. 실제로
그렇게 됐고, 오류 9건이 전부 같은 원인이었다: **관측 대상을 확인하지 않고
짐작해서 판정 기준을 세웠다.**

| 오판 | 짐작한 것 | 실제 |
|---|---|---|
| 워크스페이스 위치 | e2e 임시 폴더에 있을 것 | #424가 코호트 폴더를 연다 |
| 종료 판정 | 텍스트가 멈추면 끝 | 긴 툴 호출 중엔 당연히 멈춘다 |
| 종료 판정 | 진행 칩이 항상 붙는다 | 내용이 비면 텍스트만 렌더된다 |
| 산출물 경로 | 파일로 나올 것 | 기본 출력은 채팅 ```html 펜스 |
| transition | `ms` 로 쓸 것 | `.15s`/`.2s` 로 쓴다 |
| 루브릭 형식 | 목록으로 낼 것 | 마크다운 표로 낸다 |
| URL 추출 | 주소만 있을 것 | `**https://…**` 로 굵게 쓴다 |
| 프리뷰 탭 | 라벨에 URL 이 있을 것 | 라벨은 **페이지 제목**이다 |
| artifact 헬퍼 | 이미 있을 것 | 호출만 넣고 정의를 안 넣었다 |

**9건이 전부 "실패" 쪽으로 틀려서 파보다 드러났다.** 통과 쪽으로 틀렸다면 거짓
초록을 그대로 보고했을 것이다. 그중 넷은 정상 동작을 미달로 보고할 뻔했고,
하나는 실제로 그렇게 보고했다가 수동 확인으로 겨우 뒤집었다.

## 규칙

### 1. 판정 기준을 세우기 전에 대상을 열어본다

정규식·셀렉터·임계값을 쓰기 전에 **그것이 재려는 실물**을 확인한다.

- DOM 셀렉터 → 해당 컴포넌트의 렌더 분기를 읽는다 (`ChatPanel.tsx` 등)
- 산출물 형식 → 코호트 프롬프트가 뭘 내라고 지시하는지 읽는다
- 툴 동작 → 그 툴의 소스를 읽는다

"아마 이렇게 나올 것"으로 시작한 기준은 예외 없이 틀렸다.

### 2. 실기기 런 전에 대조군을 돌린다

```
cd e2e && node --experimental-strip-types tests/scoring.smoke.mjs
```

밀리초 만에 돈다. 채점 함수는 `e2e/scoring.ts` 에 순수 함수로 있고, 대조군
두 종류가 계측기 자체를 검증한다.

- **양성 대조군** — 확실히 좋은 시료가 **통과해야** 한다 → *너무 엄격한* 계측기를 잡는다
- **음성 대조군** — 확실히 나쁜 시료가 **실패해야** 한다 → *너무 관대한* 계측기를 잡는다

오늘 오류는 대부분 "너무 엄격" 쪽이었으므로 **양성 대조군이 핵심**이다.
새 채점 로직을 추가하면 대조군도 같이 추가한다. 대조군 없는 채점기는 신뢰하지
않는다.

### 3. 정답을 심고 시작한다

B3(루프 엔지니어링)만 한 번도 오판하지 않았다. 이유는 하나 — **결함 5종을
심어놓고 "몇 개 찾나"를 세기 때문**이다. 정답을 아는 상태라 계측기가 고장나면
즉시 드러난다.

열린 출력을 정규식으로 긁는 방식은 틀려도 알 방법이 없다. 가능하면 **심은
정답 대비**로 재라.

### 4. 아티팩트를 읽고 판정하지 않는다 — 다시 돌린다

계측기를 고쳤으면 **고친 코드로 다시 돌린다.** 아티팩트를 눈으로 읽고
"정상이겠다"고 판단하는 것은 판정이 아니다. 실제로 마지막 보고에서 이 실수를
한 번 더 했다.

### 5. 코치의 말은 증거가 아니다 — 그리고 내 추출도 아니다

R0(지어낸 성공 금지)는 코치에게만 적용되는 규칙이 아니다.

- 코치가 "배포했어요" → **테스트가 독립적으로** `curl` 로 200 을 확인한다
- 테스트가 "주소가 안 열린다" → **그 주소를 어떻게 뽑았는지** 먼저 의심한다

두 번째를 안 해서 정상 배포를 R0 위반으로 보고했다.

### 6. 실패 방향을 의식한다

`FAIL` 이 뜨면 두 가지 가능성이 있고, **순서가 정해져 있다**:

1. 계측기가 틀렸나 (오늘 9번 중 9번)
2. 제품이 틀렸나

먼저 1번을 배제한 뒤에 2번을 보고한다. 반대로 하면 멀쩡한 기능을 고치러 간다.

## 환경 함정 (매번 걸린다)

**세션이 열려 있어야 채팅이 된다.** 안 열려 있으면 코치가 **빈 응답만** 낸다.
검증자 눈엔 앱 고장으로 보이고, 실제로 전체 스위트 한 바퀴를 이것 때문에 날렸다.

```
skills/hype-session 또는 /console 로 열기 → **끝나면 닫기**
```

**`401` 과 `403` 은 다르다.**

- `403 session_inactive` → 세션을 열어야 함
- `401` → 학생 토큰 만료 (하루에 세 번 걸렸다). 검증은 길어지니 **10~12시간**짜리로 발급

**토큰 발급 전에 roster 등록이 먼저다** (#367). 안 하면 `not_in_roster` 로 막힌다.

**터널 프로세스가 런마다 쌓인다.** 끝나면 `pkill -f cloudflared`.

## CI 초록은 아무것도 보장하지 않는다

첫 완주에서 실기기로만 잡힌 제품 결함이 **7건**이고 전부 단위 테스트 통과 ·
CI 초록 상태였다.

```
sdk_tools.shell 이 /v1/profile 직렬화에서 잘림      셸 전체 inert
GitHub Pages 레거시 빌더 startup_failure           배포 전원 실패
코치가 지킬 수 없는 알림 약속                       참가자 무한 대기
강한 확인 남발 (명령 8개 중 6개)                    무지성 승인 훈련
프롬프트에 "셸 실행 금지" 잔존                      셸 부여 무력화
중첩 코드펜스가 agent.md 절단                      결과물 4번 반쪽
터널 포트 오인 (디버깅 포트)                        폴백 경로 불안정
```

특히 1번과 5번은 **"설정은 맞는데 동작이 없는"** 유형이다. 프로필 → 워커
직렬화 → 클라이언트 정책, 세 계층 중 하나만 끊겨도 기능이 설정된 것처럼
보이면서 죽는다. 배포 후 **프로덕션에 실제 토큰으로 질의**해서 확인한다:

```
curl -H "Authorization: Bearer <학생토큰>" https://api.hypeproof-ai.xyz/v1/profile | jq .sdk_tools
```
