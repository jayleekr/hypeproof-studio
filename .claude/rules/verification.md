# 검증 규율 — 짐작으로 판정하지 않는다

실사용을 관측하거나(`e2e/observe/`) 무언가를 "확인했다"고 말하려 할 때 로드된다.
2026-07-25~27 사흘 동안 **계측기가 열다섯 번 틀린** 경험에서 나왔다.

## 왜 이 문서가 있나

커리큘럼 검증은 2중 루프다.

```
바깥 루프   큐시트 → 제품이 이걸 지탱하나 → 실기기 검증
안쪽 루프   하네스 → 이게 제대로 재나 → ???
```

안쪽에 검증이 없으면 **검증되지 않은 계측기로 제품을 판정**하게 된다. 실제로
그렇게 됐고, 오류 9건이 전부 같은 원인이었다: **관측 대상을 확인하지 않고
짐작해서 판정 기준을 세웠다.**

| 오판 | 짐작한 것 | 실제 |
|---|---|---|
| 워크스페이스 위치 | e2e 임시 폴더에 있을 것 | #424가 코호트 폴더를 연다 |
| 종료 판정 | 텍스트가 멈추면 끝 | 긴 툴 호출 중엔 당연히 멈춘다 |
| 종료 판정 | 진행 칩이 항상 붙는다 | 내용이 비면 텍스트만 렌더된다 |
| 산출물 경로 | 파일로 나올 것 | 기본 출력은 채팅 ```html 펜스 |
| transition | `ms` 로 쓸 것 | `.15s`/`.2s` 로 쓴다 |
| 루브릭 형식 | 목록으로 낼 것 | 마크다운 표로 낸다 |
| URL 추출 | 주소만 있을 것 | `**https://…**` 로 굵게 쓴다 |
| 프리뷰 탭 | 라벨에 URL 이 있을 것 | 라벨은 **페이지 제목**이다 |
| artifact 헬퍼 | 이미 있을 것 | 호출만 넣고 정의를 안 넣었다 |

**9건이 전부 "실패" 쪽으로 틀려서 파보다 드러났다.** 통과 쪽으로 틀렸다면 거짓
초록을 그대로 보고했을 것이다. 그중 넷은 정상 동작을 미달로 보고할 뻔했고,
하나는 실제로 그렇게 보고했다가 수동 확인으로 겨우 뒤집었다.

## 규칙

### 1. 판정 기준을 세우기 전에 대상을 열어본다

정규식·셀렉터·임계값을 쓰기 전에 **그것이 재려는 실물**을 확인한다.

- DOM 셀렉터 → 해당 컴포넌트의 렌더 분기를 읽는다 (`ChatPanel.tsx` 등)
- 산출물 형식 → 코호트 프롬프트가 뭘 내라고 지시하는지 읽는다
- 툴 동작 → 그 툴의 소스를 읽는다

"아마 이렇게 나올 것"으로 시작한 기준은 예외 없이 틀렸다.

#### 1b. **범위 주장도 판정이다** — PR·패치 본문에 쓰는 문장에 똑같이 적용된다

규칙 1 은 정규식·셀렉터에 관한 것으로 읽히기 쉽다. 그런데 **산문으로 쓴 범위 주장**이
같은 실수에 더 취약하고, 값은 더 크다 — 사람이 그 문장을 읽고 보안 결정을 내린다.

2026-09-11, 마이크 패치 v3 의 헤더와 PR 본문에 이렇게 썼다:

> 앞으로 만들 `hypeproof-preview` → **구조적으로 범위 밖** (다른 확장 id)

**틀렸다.** 미리보기 webview 는 아직 `hypeproof-chat` **안**에서 만들어진다
(`previewProvider.ts:127`, `enableScripts: true`) — 같은 확장 id 라 게이트가 통과시킨다.
METAPLAN 이 `hypeproof-preview` 를 별도 sprint 로 적어 둔 것을 보고 **구조에서 추론**했고
출하되는 코드를 열어보지 않았다. Codex 가 실측으로 잡았다: **같은 확장의 시작 화면도
`allowsFeature('microphone')` 이 true.** 승인을 요구한 표면이 webview 1개가 아니라 3개였고,
그 틀린 숫자가 사람 결정(H-08) 앞에 이틀 놓여 있었다.

**기계적 검사** — "X 는 범위 밖" 을 쓰기 전에 X 의 **생성 지점을 센다**:

```bash
# 이 확장이 실제로 만드는 webview 가 몇 개인가
grep -rn "createWebviewPanel\|registerWebviewViewProvider" extensions/*/src/*.ts
grep -rn "enableScripts" extensions/*/src/*.ts
```

30초다. 그리고 **"별도 sprint" 는 "별도 확장" 이 아니다** — 계획 문서의 미래형을 오늘의
코드 구조로 읽지 않는다.

같은 날 같은 형태를 한 번 더 했다: `path_links` 로 경로를 연결한 것과
`config/traceability.json` 에 노드를 넣은 것을 구분하지 않고 "매핑했다" 고 말했다. 동료
세션이 어느 쪽이냐고 물어서 **세어 봤고** 다행히 진짜 노드였다 — 맞은 것은 운이었다.
`docs/HYPE-PR.ko.md` 에 그 함정을 적어 뒀다.

### 2. 실기기 런 전에 대조군을 돌린다

순수 함수로 뽑아낼 수 있는 판정은 앱 없이 먼저 돌린다(밀리초). 대조군 두 종류가
계측기 자체를 검증한다.

- **양성 대조군** — 확실히 좋은 시료가 **통과해야** 한다 → *너무 엄격한* 계측기를 잡는다
- **음성 대조군** — 확실히 나쁜 시료가 **실패해야** 한다 → *너무 관대한* 계측기를 잡는다

오늘 오류는 대부분 "너무 엄격" 쪽이었으므로 **양성 대조군이 핵심**이다.
새 채점 로직을 추가하면 대조군도 같이 추가한다. 대조군 없는 채점기는 신뢰하지
않는다.

### 3. 정답을 심고 시작한다

B3(루프 엔지니어링)만 한 번도 오판하지 않았다. 이유는 하나 — **결함 5종을
심어놓고 "몇 개 찾나"를 세기 때문**이다. 정답을 아는 상태라 계측기가 고장나면
즉시 드러난다.

열린 출력을 정규식으로 긁는 방식은 틀려도 알 방법이 없다. 가능하면 **심은
정답 대비**로 재라.

### 4. 아티팩트를 읽고 판정하지 않는다 — 다시 돌린다

계측기를 고쳤으면 **고친 코드로 다시 돌린다.** 아티팩트를 눈으로 읽고
"정상이겠다"고 판단하는 것은 판정이 아니다. 실제로 마지막 보고에서 이 실수를
한 번 더 했다.

### 5. 코치의 말은 증거가 아니다 — 그리고 내 추출도 아니다

R0(지어낸 성공 금지)는 코치에게만 적용되는 규칙이 아니다.

- 코치가 "배포했어요" → **테스트가 독립적으로** `curl` 로 200 을 확인한다
- 테스트가 "주소가 안 열린다" → **그 주소를 어떻게 뽑았는지** 먼저 의심한다

두 번째를 안 해서 정상 배포를 R0 위반으로 보고했다.

### 6. 실패 방향을 의식한다

`FAIL` 이 뜨면 두 가지 가능성이 있고, **순서가 정해져 있다**:

1. 계측기가 틀렸나 (오늘 9번 중 9번)
2. 제품이 틀렸나

먼저 1번을 배제한 뒤에 2번을 보고한다. 반대로 하면 멀쩡한 기능을 고치러 간다.

### 7. 충돌을 «푼 것»과 내용이 «살아 있는 것»은 다르다

`git merge` 가 성공하고 검사가 전부 초록인데 **내용이 사라져 있을 수 있다.** 2026-09-20 밤
열다섯 PR 을 합치면서 **같은 형태로 세 번** 틀렸다.

| 무엇을 했나 | 무엇이 사라졌나 |
|---|---|
| `authoring.html` 의 충돌은 `#1036` **구역 하나**였는데 `--ours` 로 **파일 전체**를 취했다 | 같은 파일의 관문 UI · 리허설 표시 · step-note · 학생 주소 **넷이 통째로** |
| `config/requirement-work.json`(배열)을 `--ours` 로 | 상대 브랜치의 **항목 갱신 1건** |
| 같은 파일을 `--theirs` 로 | `main` 의 **신규 항목 5건** |

**셋 다 머지 성공 · 검사 초록이었다.** 아무도 안 물었고 테스트도 안 깨졌다. **세어 봐야만 보였다.**

#### 그래서 — 해소 **전에** 적고, 해소 **후에** 센다

```
해소 전 : 양쪽에서 살아남아야 할 표식을 파일로 적는다 (고유 심볼 · id · 문자열)
해소 후 : grep -c 로 센다. 0 이 나오면 해소가 틀린 것이다
```

**«양쪽» 이 핵심이다.** 내 것만 세면 **상대 것이 죽어도 모른다.** 실제로 `#1137` 을 합칠 때
내 심볼 여섯을 세고 끝냈다면 `main` 이 새로 옮긴 영문 주석이 사라진 것을 못 봤을 것이다 —
그것도 같이 세서 살렸다.

#### 라벨은 방어가 아니다

*"`#1036` 은 main 것으로 뒀다"* 는 **참인데도** 저작 화면 넷이 사라진 것은 그 문장 어디에도
없다. **라벨은 «무엇을 골랐나» 를 말하지 «무엇이 사라졌나» 를 말하지 않는다.**
정직하게 라벨을 쓰고도 거짓인 트리가 나온다. 세는 것만이 그것을 잡는다.

#### 파일 단위 `--ours`/`--theirs` 는 한 작업만 얹혀 있을 때만

한 파일에 여러 사람의 작업이 얹혀 있으면 한쪽을 통째로 취하는 순간 나머지가 죽는다.
**구역 단위로 푼다.**

배열·목록 파일은 **항목 단위 3-way** 로 합친다 — `--ours`/`--theirs` 는 **둘 다** 내용을
떨어뜨린다(위 표의 2·3행이 같은 파일의 양방향이다).

- `worker/package.json` 의 `"test"` — 50여 파일을 한 줄에 이은 ` && ` 목록
- `config/requirement-work.json` 의 `work_items` — id 를 가진 객체 배열

#### 「누가 바꿨나」는 **base 기준**으로 잰다

`ours` 와 `theirs` 를 **직접 비교하면 «양쪽이 다 바꿨다» 로 오판한다** — 한쪽이 base 그대로일 때
그 차이가 그대로 나온다. 실제로 바꾼 쪽이 누구인지는 **base 를 끼워야** 나온다.

```
base == ours,  base != theirs   →  theirs 가 바꿨다. theirs 를 취한다
base != ours,  base == theirs   →  ours 가 바꿨다
둘 다 base 와 다르다            →  사람이 본다. 자동으로 고르지 않는다
```

(2026-09-20 `#1133` 해소 중 동료 세션이 잡았다.)

#### 집합만 세지 마라 — **수정**은 카운트를 빠져나간다

배열을 합칠 때 **id 집합**만 대조하면 «추가» 는 잡히지만 **«같은 id 의 내용 수정» 은 안 잡힌다.**
그 항목은 양쪽에 다 있으므로 어느 집합 차집합에도 안 나온다.

`config/requirement-work.json` 에서 정확히 그렇게 놓쳤다 — id 는 47개 그대로인데 한 항목의
`verification_inputs` 열 줄이 통째로 사라져 있었다. **«없어진 id» 가 아니라 «달라진 내용» 을
물어야 잡힌다.**

```
for id in 합집합:  base/ours/theirs 세 값을 비교한다   ← 집합이 아니라 값
```

(같은 날 동료 세션이 별도로 같은 것을 짚었다.)

#### 지시가 «저쪽 것으로» 일 때는 단위를 되묻는다

*"main 쪽을 그대로 취해라"* 를 받고 **파일 단위**로 읽어 넷을 날렸다. 지시한 쪽은 **충돌 구역
하나**를 말한 것이었다. **«그 구역은 저쪽 것» 과 «그 파일은 저쪽 것» 은 다른 말이다.**


## 환경 함정 (매번 걸린다)

**브랜치를 누가 쥐고 있는지는 PR 목록으로 알 수 없다.** 작성자가 전부 같은 계정이라
`gh pr list` 로는 안 갈린다. `git worktree list` 만이 "지금 누가 체크아웃하고 있나" 를 말하는데,
**경로 접두사가 두 종**이라 한쪽만 보면 놓친다:

```
-Users-jj-home-Git-HypeProof-hypeproof-studio/…   ← studio 세션
-Users-jj-home-Git-HypeProof/…                     ← 워크스페이스 루트 세션
```

2026-09-20 에 한 브랜치를 "주인 없음" 으로 읽고 밀 뻔했다 — 두 번째 접두사에 있었다.
**`git worktree list` 를 grep 없이 전부 읽거나, 두 접두사를 모두 확인한다.**

**세션이 열려 있어야 채팅이 된다.** 안 열려 있으면 코치가 **빈 응답만** 낸다.
검증자 눈엔 앱 고장으로 보이고, 실제로 전체 스위트 한 바퀴를 이것 때문에 날렸다.

```
skills/hype-session 또는 /console 로 열기 → **끝나면 닫기**
```

**`401` 과 `403` 은 다르다.**

- `403 session_inactive` → 세션을 열어야 함
- `401` → 토큰이 **거부됐다**. 만료가 흔한 원인이지만 만료"라고 단정하지 마라". 검증은 길어지니 **10~12시간**짜리로 발급

**`401` 을 만료로 읽는 습관이 실제로 이틀을 태웠다 (2026-07-28).** agent-sdk 경로에서
"토큰 만료" 배너가 계속 떴는데 토큰은 9.7시간 남은 멀쩡한 것이었다. 진짜 원인은
CLI 가 `ANTHROPIC_AUTH_TOKEN` 대신 그 PC 에 저장된 **개인 Claude 계정 자격증명**을
써서 게이트웨이가 거부한 것이었다(REQ-M13, `sdkConfigDirFor`). 배너 문구가 원인을
단정하는 바람에 아무도 그쪽을 보지 않았다.

**토큰을 의심하기 전에 토큰을 직접 찔러봐라.** 30초면 원인을 반으로 가른다:

```
curl -H "Authorization: Bearer <학생토큰>" https://api.hypeproof-ai.xyz/v1/profile
```

200 이면 토큰은 무죄다 — 클라이언트가 **무엇을 대신 보냈는지**를 봐야 한다. 확실히
보려면 `ANTHROPIC_BASE_URL` 을 헤더만 찍는 로컬 서버로 돌려서 실제로 나가는
`authorization` 헤더를 읽는다. 짐작하지 말고 관측한다(규칙 1).

**토큰 발급 전에 roster 등록이 먼저다** (#367). 안 하면 `not_in_roster` 로 막힌다.

**터널 프로세스가 런마다 쌓인다.** 끝나면 `pkill -f cloudflared`.

## CI 초록은 아무것도 보장하지 않는다

첫 완주에서 실기기로만 잡힌 제품 결함이 **7건**이고 전부 단위 테스트 통과 ·
CI 초록 상태였다.

```
sdk_tools.shell 이 /v1/profile 직렬화에서 잘림      셸 전체 inert
GitHub Pages 레거시 빌더 startup_failure           배포 전원 실패
코치가 지킬 수 없는 알림 약속                       참가자 무한 대기
강한 확인 남발 (명령 8개 중 6개)                    무지성 승인 훈련
프롬프트에 "셸 실행 금지" 잔존                      셸 부여 무력화
중첩 코드펜스가 agent.md 절단                      결과물 4번 반쪽
터널 포트 오인 (디버깅 포트)                        폴백 경로 불안정
```

특히 1번과 5번은 **"설정은 맞는데 동작이 없는"** 유형이다. 프로필 → 워커
직렬화 → 클라이언트 정책, 세 계층 중 하나만 끊겨도 기능이 설정된 것처럼
보이면서 죽는다. 배포 후 **프로덕션에 실제 토큰으로 질의**해서 확인한다:

```
curl -H "Authorization: Bearer <학생토큰>" https://api.hypeproof-ai.xyz/v1/profile | jq .sdk_tools
```

## 관측 루프

큐시트는 **강사가 채팅으로 몬다.** 자동 스위트로 대신 돌리지 않는다.

```
강사가 친다  →  관측한다  →  이상한 걸 짚는다  →  고친다  →  빌드한다
```

도구와 함정은 `e2e/observe/README.md` 에 있다. 특히 거기 적힌 **계측기 오류 6건**을
읽고 나서 관측기를 고쳐라 — 전부 "아마 이럴 것"으로 시작해서 틀린 것들이다.
