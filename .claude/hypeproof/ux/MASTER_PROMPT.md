## 2. 완료의 정의 — 여섯 게이트

task 는 아래가 **전부** 참일 때 끝난다. 하나라도 아니면 `STATE.md` 에 **어느 것이 왜** 빠졌는지 이름으로 적는다. "대체로 됐다"는 없다.

### G1. machine_gate — 번들러 둘 + CI 게이트

```bash
cd worker && npx tsc --noEmit && npm test
cd extensions/hypeproof-chat && npx tsc --noEmit -p . && npm test
cd extensions/hypeproof-chat/webview-ui && npm run build     # ← 앞 둘이 초록인데 빨간 적 있다
python3 scripts/next-work.py --check                          # 요구 문서 등록 누락
python3 scripts/docs-harness/check.py --min-score 95          # 있으면
```

- **렌더 계측기는 esbuild, 출하는 vite 다.** 번들러가 둘이면 둘 다 돌린다
- 요구 문서를 새로 만들었으면 `config/requirement-work.json` 등록까지가 G1 이다. 미등록은 CI `coverage` 가 `GAP: unregistered document` 로 잡는다
- **로컬에서 못 도는 스위트가 있다는 사실은 "그 절반은 아마 괜찮다" 가 아니다.** → G6

### G2. control 이 **실제 경로**를 지나고, **빨강의 사유가 정보를 갖는다**

control 은 구현 **전에** 쓰고 빨간 것을 본다. 그것만으로는 부족하다. 두 가지를 더 본다.

**(a) 무엇을 지나는가.**

- 화면 → **실제 컴포넌트를 렌더**한다. 문자열 사본이 아니라
- 클라이언트 동작 → **클라이언트의 그 함수를 import** 한다. 헤더·URL·인자를 손으로 다시 적지 않는다
- 저장 → **진짜 검증기**에 통과시킨다. "저장됐다"는 다음 읽기에서 거절되면 거짓이다
- 서버 응답이 걸린 기능 → **라우트 응답을 직접 읽는다.** 헬퍼 단위 테스트는 못 잡는다

> 2026-09-20: 두 라우트가 같은 함수로 협상하는지 재면서 **테스트가 양쪽에 같은 헤더를 보냈다.**
> 실제 클라이언트는 두 곳에서 다른 헤더를 만들고 있었다. 검사 9개가 초록인 채로 기능은 죽어 있었다.

**(b) 왜 빨간가 — 사유를 읽고 적는다.**

`ERR_MODULE_NOT_FOUND` · `ENOENT` · `unsupported_*` 로 빨간 대조군은 **정보가 0** 이다.
파일이 없어서 빨간 것은 아무것도 재지 않는다. 두 판정서가 연속으로 지적했다.

> 새 task 의 control 은 **기존 파일의 기존 함수에 걸리는 단언을 최소 하나** 포함한다.
> (새 포맷을 여는 task 라면: 기존 검증기가 그 배치를 `unsupported_*` 가 **아닌** 이유로 거절하는가)
> control 로그의 **실패 사유 한 줄을 그대로** `STATE.md` 에 붙인다. 못 적으면 그 대조군은 없는 것이다.

### G3. 심은 결함 — **목록은 요구에서 뽑고**, 실패는 사유까지 단언한다

**(a) 목록의 출처.** 자기 구현에서 뽑은 결함은 **코드가 이미 하는 일만 확인**한다.
2026-09-20 에 내가 ~66개를 심어 전부 CAUGHT 였는데, 외부 판정자가 자기 목록 15개로
**MISSED 2개**를 찾았다. 그래서:

> 결함 목록은 이 단계가 다루는 **SX 행의 부정 조건**("…하지 않는다 / …는 통과하지 못한다")에서 뽑는다.
> 부정 조건을 전부 나열하고 대응 검사 규칙이 있는지 **표로 대조**한다.
> 규칙이 없는 행은 `NOT COVERED` 로 `STATE.md` 에 적는다. **심지 않은 결함은 잡히지 않는다.**

**(b) 절차.** 심는다 → 돌린다 → 빨간가 → 원복 → 다음. 전부 CAUGHT 까지. 원복 후 초록도 확인.

- 심은 결함이 **도달 불가능한 경로**에 있으면 무효다. MISSED 로 읽고 단언을 고치면 **엉뚱한 방향으로** 고친다
- 결함이 사는 **층에** 대조군을 둔다. 워커 검사는 확장 호출부를 돌리지 않는다

**(c) 실패를 기대하는 단언은 실패 사유까지 단언한다.**

> 시료를 최소로 깎아 **의도한 절 하나만** 남기고, 그 절을 지웠을 때만 초록이 되는지 확인한다.
> 다른 절이 먼저 false 를 내면 그 검사는 **이름만 SX-xx** 다.
> **0 을 세면서 초록인 단언은 빨간 것보다 나쁘다.**

(2026-09-20: `actor:"ai"` 거절을 단언하면서 시료에 `student_text` 가 없어 텍스트 절이 먼저 막았다.
actor 절을 통째로 지워도 스위트 전체가 초록이었다.)

### G4. 도달 가능성 — 이 기능이 실제로 켜지는가

> **2026-09-20 P1 은 G1·G2·G3 을 전부 통과하고도 학생 화면에 한 픽셀도 나오지 않았다.**

1. 켜지려면 **무엇이 참이어야 하나** (프로필 플래그? 응답 필드? 설정?)
2. 지금 그게 참인 좌석이 **존재하나.** 없으면 기능은 없는 것이다
3. 그 조건을 정하는 **모든 지점을 센다.** grep 하고 **개수를 `STATE.md` 에 적는다**
4. **협상되는 포맷·프로토콜이면 네 칸을 표로 적는다** — 구앱×구서버 · 구앱×신서버 · 신앱×구서버 · 신앱×신서버. 존재할 수 있는 칸마다 검사 하나
5. **역방향도 본다** — 새로 켜진 것 말고 **이미 되던 것이 그대로 되는가**

```bash
grep -rn "<그 리터럴>" worker/src extensions/hypeproof-chat/src | grep -v node_modules | wc -l
```

`worker/src/routes/chat.ts` 주석이 이 실패를 **이미 경고하고 있었다**("ship INERT on every SDK seat").
`verification.md` 도 같은 함정을 적어 뒀다. **두 번 적힌 함정에 또 빠졌다.**

**좌석을 만들 수 있다.** §8 이 금지하는 것은 *기존* 코호트 변경이다. **합성 코호트 신설**과
**카나리(`canary-sdk-contract`, 로스터 0명) 플래그**는 허용이고, 그것이 G4 를 만족시키는 길이다.
*어느 실제 코호트가 언제* 쓰는지는 수업 결정이라 `STATE.md` 사람 결정 항목으로 간다.

### G5. 실기 증거 — **있는 스크립트로**, 조용히, 라벨을 달아서

`bash build.sh` 는 금지다(1~2시간·10~20GB). **그것이 "실기 검증을 하지 말라"가 아니다.**

**있는 것을 쓴다. 손으로 다시 만들지 않는다.**

```bash
bash scripts/test-native-trial-laptop.sh      # 설치본 복사 + 확장 주입 + SDK 시드
```

이 스크립트는 `ditto`(덮어쓰기가 아니라 병합) + `scripts/seed-sdk-binary.sh` + 릴리스 검증 중
주입 차단을 이미 갖고 있다. **폴더를 통째로 교체하면 안 된다** — 설치본의
`dist/vendor` 는 **14 MB**(벤더된 Agent SDK)이고 저장소 `dist` 는 **400 KB** 다.
교체하면 SDK 코치가 **조용히** 프록시 전용으로 떨어진다(`build-pipeline.md` `REQUIRE_SDK_VENDOR`).

**세 가지를 반드시 지킨다.**

1. **조용히.** Jay 의 상시 규칙: 화면이 잠겨 있지 않으면 **Electron 을 띄우지 않는다**
   (memory `gui-e2e-local-quiet-policy`, 2026-07-14). 야간 실행은 quiet 모드 + 화면 잠금 게이트를
   지나는 러너만 쓴다. 직접 `.mjs` 러너를 띄우면 Jay 의 맥을 뺏는다
2. **서버가 걸려 있으면 로컬 워커를 띄운다**(`wrangler dev`) + 앱의 `hypeproofChat.proxyUrl` 을 돌린다.
   운영 서버에는 이 세션의 변경이 없다 — 그냥 열면 **여전히 안 보인다**
3. **라벨을 단다.** `docs/testing/studio-learning-experience.md` 가 셋을 정의한다:
   `live-host` / `captured-replay` / `synthetic`. **주입된 구버전 셸에서 얻은 것은 live-host 가 아니다.**
   SX-T60 은 live-host 만 인정한다. 라벨 없는 증거는 synthetic 으로 취급된다

**화면을 만든 단계는 SX-T 행 0 개로 닫지 않는다.** 최소 세 행(`SX-T04` real/simulated ·
`SX-T23` 근거 6종 · `SX-T26` source_state 라벨)은 시도한다. **막히면 명령과 오류 문구를
그대로** 적는다 — "승인 대기"는 시도하지 않은 것의 다른 이름이다. 승인이 필요한 것은
`bash build.sh` **하나뿐**이다.

## 3. 요구가 틀렸을 때 — 발명하되 **세고, 갚는다**

| 상황 | 무엇을 하나 |
|---|---|
| **모호하다** (두 해석 가능) | 원문(`ui-philosophy-2026-09-18.md`)으로 돌아간다. 거기서도 갈리면 **좁은 쪽**을 고르고 고른 이유와 **버린 쪽**을 적는다 |
| **요구와 설계가 반대다** | **설계를 따른다**(더 구체적이므로). 개정 제안에 **결과까지** 적는다 |
| **문자 그대로 불가능하다** | **가장 좁은 예외**를 만들고 `spec-debt` 로 표시한다. 멈추지 않는다 — 멈추면 DAG 가 통째로 선다 |

**단, 갚아야 한다:**

- 예외 하나마다 `STATE.md` 개정 제안에 **선택지와 추천**까지 적는다
- **한 단계에 `spec-debt` 가 2건을 넘으면 그 단계의 새 task 를 받지 않는다.** 남은 것을 정리하고 사람 결정을 기다린다. 2026-09-20 은 **한 단계에 6건**을 쌓았다
- 단계 PR 본문에 `spec-debt` 개수를 적는다. 0 이 아니면 "완료"라고 쓰지 않는다

**개정 제안은 결과까지 쓴다.** "필수를 좁혔다"는 절반이다. "그래서 이런 입력이 이제
통과한다/막힌다"가 나머지 절반이고, **사람은 그 절반을 읽고 결정한다.**

## 4. 주장하기 전에 센다 — 산문·주석·이름 전부

산문으로 쓰는 **범위 주장도 판정이다.** 정규식보다 자주 틀리고 값은 더 크다.

**(a) 이 문장들을 쓰기 전에 명령을 돌리고 개수를 본문에 적는다.**

- "X 는 범위 밖이다" / "이 둘은 갈라질 수 없다" / "부작용이 없다" / "A 만 고치면 된다"
- **"…가 없다 / 구현되지 않았다"** ← 과소 주장도 센다. 2026-09-20 에 이미 출하된 것을
  "없다"고 적었고, 다음 세션이 **다시 만들 뻔했다**
- **"바뀌지 않는다 / 바이트 그대로"** ← 어느 **입력 집합**에 대해 참인지 같이 적는다

**(b) 주석·파일 머리 설명도 범위 주장이다.**
`legacy-observation.ts` 머리의 "byte for byte"는 human 판정이 `actor` 를 보기 시작하면서
거짓이 됐다. **회귀 코퍼스가 초록인 것은 "규칙이 안 바뀌었다"의 증거가 아니다** —
코퍼스에 없는 조합을 **손으로 하나 만들어** 옛 구현과 새 구현에 각각 통과시켜 본다.
동작이 바뀌었으면 주석을 좁히고 **그 자리에 단언을 남긴다**(무검사 가드는 다음 세션이 지운다).

**(c) 이름을 옮기면 그 이름을 쓰는 모든 검사를 센다.**

```bash
grep -rn "<옛 클래스|옛 문구|옛 aria-label>" e2e/ chalk/ scripts/ extensions/ worker/ | grep -v node_modules
```

2026-09-20: 활동 줄을 헤더로 옮기며 `aria-label="현재 활동"` 을 잃었고(CI 가 잡음),
`e2e/trial-ux` 는 **사라진 클래스의 개수 0** 을 세며 초록이었다.
**자리를 옮기는 것과 라벨을 잃는 것은 다르다.** 렌더 스모크에 `aria-label` 단언을 같이 넣는다.

**(d) 원문에서 베낀 데이터도 드리프트한다.**

## 5. 검증은 2단, 그리고 **파일로 남는다**

```
구현 → 평가자(다른 에이전트) → 수리 → 검증자(또 다른 에이전트) → 다음
                                 ↑                    │
                                 └──── 실패하면 ──────┘
```

- **단위: 단계(phase)마다.** task 마다가 아니다 — task 단위면 6배 비용이다
- **평가자**는 `.claude/evals/STUDIO_UX_EVAL.md` 로 채점하고 `judge-<단계>-<날짜>.md` 에 쓴다
- **검증자**도 파일을 남긴다: `verify-<단계>-<날짜>.md`. 2026-09-20 의 2차 검증은
  `STATE.md` 한 절로만 존재한다 — 그건 기록이 아니다
- 검증자에게 시키는 것은 "이게 맞나"가 아니라 **"이게 틀렸다는 걸 증명해 봐라"**
- 평가자가 심은 결함 중 **MISSED 가 있으면 그것부터** 고친다. 그게 계측기의 구멍이다
- **수리도 변경이다** — 수리 뒤 기존 경로(구버전 앱·기존 코호트)를 다시 재고,
  수리가 만든 새 리터럴·새 조건을 §4 대로 **다시 센다**
- **판정서가 다음 평가자에게 남긴 지시를 읽고 수행한다.** 하나는 이미 두 번 연속 건너뛰었다

## 6. 실행 원칙

- **DAG 가 순서다.** `depends_on` 이 풀리는 순서로만. 병렬 task 를 나눠도 **같은 파일을 둘이 동시에 고치지 않는다**
- **task 를 집으면 그 task 의 `spec_section`·`control`·`acceptance` 를 먼저 읽는다.** 60행짜리 요구 문서를 훑는 것보다 이게 먼저다
- **계측기를 먼저 의심한다.** 실패는 `harness_fixable / harness_undecided / product / spec / flake` 로 분류한다. `harness_undecided` 와 `spec` 은 사람 몫 — 고치지 말고 적는다
- **층 규칙.** 로컬 자원 → App, 데이터 → Module, 참가자 런타임 → Service, 강사·운영 → Surface. **숫자 상수를 App 에 박지 않는다.** 6주 커리큘럼은 Module 이다
- **측정 코어를 복제하지 않는다.** 제2 저장소·제2 채점기·새 점수 없음. 기존 계약을 **같은 파일 안에서** 확장한다
- **작업 중 화면에 숫자·등급·배지가 없다.** SX-59·SX-T05·SX-T40 의 계약이다. **개수를 세는 것도 점수다** — "반응 3건"이 생기면 그것이 곧 등급이다
- **카피.** 학생 화면 **합니다체**(`PROJECT_RULES.md`, 루브릭 F). 관찰 문장은 행동이 주어.
  금지 라벨은 lint 로. 사람에 대한 "성장" 주장은 쓰지 않는다. 화면 이름은 "나의 변화 기록".
  **코호트별 어투(초등 해요체)는 사람이 정할 일이다** — 세션이 바꾸지 않는다

## 9. PR — 스택이면 본문을 관리한다

`hype-pr` 절차: `inspect` → assessment → `prepare` → `create --preparation --apply`. **머지하지 않는다.**

본문 필수: 다룬 SX ID · 실행한 게이트와 exit code · **NOT RUN 목록** · 실기 증거 경로와 **라벨**(없으면 "없음") · 심은 결함 N/N · **`spec-debt` 개수** · 이 PR 이 **담지 않은 것**(표로).

- 부분 범위 PR 은 허용. "P1 완료"라고 쓰지 않는다
- 스택이면 **머지 순서를 본문 맨 위에**
- **PR 을 올린 직후, 앞 PR 본문을 다시 읽는다.** 이번 PR 이 앞 PR 의 주장을 거짓으로 만들었으면
  **정정 배너를 붙인다. 본문은 고쳐 쓰지 않는다** — 무엇을 틀렸는지가 기록의 값이다
- 증거보다 넓은 문장을 쓰지 않는다. **"완료가 열린다"와 "완료된다"는 다른 주장이다**
