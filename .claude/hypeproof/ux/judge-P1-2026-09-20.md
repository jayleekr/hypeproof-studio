## 감점 목록과 수정 지시 (각 한 줄)

### F-1 · P1 의 화면은 어떤 빌드에서도 렌더되지 않는다 (가장 크다)

세 층이 전부 `/1` 로 못 박혀 있다. 하나만 끊겨도 죽는데 셋 다 끊겨 있다.

```
worker/src/routes/chat.ts:294        observation: { format: 'hps-observation/1', ... }   ← 하드코딩, /2 분기 없음
worker/src/routes/observations.ts:27,63   format: OBSERVATION_FORMAT                     ← context 응답도 /1
extensions/hypeproof-chat/src/proxyClient.ts:397,422   'x-hps-observation-format': 'hps-observation/1'
```

`ls worker/src/profiles/` 의 **어느 코호트도** `observation.format` 을 선언하지 않는다
(`{ enabled: true|false }` 뿐). 그래서 `prepareObservation()` 의
`OBSERVATION_FORMATS.includes(profile?.observation?.format)` 가 참이 되는 경로가 없고,
`currentLearningRecorder()` → `null` → `postLearningState()` 즉시 return →
`ChatPanel` 의 `learning === null` → `{learning && <section …>}` 가 **한 번도 참이 아니다.**

덧붙여, 설령 프로필을 고쳐도 `/observations/context` 가 `/1` 을 돌려주므로
`recordLearningEvent()` 가 `observation_format` 으로 던진다. **두 군데를 같이 고쳐야 한다.**

곁가지: `/2` 가 열리는 순간 `ChatPanel` 마지막 두 줄이 모순을 그린다 —
`observation.format !== 'hps-observation/1'` 조건 때문에 서랍이 동작하는 화면에서
`"현재 연결은 작업 관찰을 지원하지 않습니다"` 가 같이 뜬다.

> **수정**: `worker/src/routes/chat.ts:294` 와 `worker/src/routes/observations.ts:27,63` 이
> 프로필의 `observation.format` 을 읽도록 바꾸고, 코호트 하나(`canary-sdk-contract` 가
> 적당하다)에 `observation: { enabled: true, format: 'hps-observation/2' }` 를 선언한 뒤,
> **프로덕션에 실제 토큰으로 `curl … /v1/profile | jq .observation.format` 을 쳐서 `/2` 가
> 나오는 것을 확인**하라(verification.md "배포 후 프로덕션에 실제 토큰으로 질의").
> 그 전까지는 PR 본문에서 "완료가 열린다/막힌다" 대신 **"순수 함수는 옳고 화면은 아직
> 연결되지 않았다"** 로 주장을 좁혀라.

### F-2 · `actor=ai` 기대 조건이 게이트를 막는다는 단언이 공전한다

`test/sx-evidence-gate.smoke.mjs:77-86` 은 `actor: "ai"` 인 `criterion_set` 을 넣고
`complete.ok === false` 를 단언하면서 메시지에 `(SX-45)` 를 단다. 그런데 그 시료에는
`student_text` 가 **없다**. `satisfiesGate()` 는 텍스트 절에서 이미 false 를 내므로
**actor 절은 한 번도 실행되지 않는다.** 직접 재었다:

```
smoke fixture (actor=ai, no student_text) satisfiesGate: false
text clause ALONE on the same fixture           : false   ← actor 절이 막은 것이 아니다
text clause ALONE on actor=ai WITH student_text : true    ← 이 시료라야 actor 절만 남는다
```

그리고 `satisfiesGate` 에서 `|| !isStudentAuthored(event)` 를 **통째로 지워도 워커·확장
스위트가 전부 초록**이다(심은 결함 #14). 이 절이 유일한 방어인 자리는 `student_text` 칸이
아예 없는 `test_observed`·`retest_confirmed` 이고, 강사는 `learning.completion` 에서
8종 중 아무거나 고를 수 있다.

> **수정**: `sx-evidence-gate.smoke.mjs` 의 actor=ai 시료에 `student_text` 를 넣고(검증기는
> 그것을 거절하지만 `satisfiesGate` 는 순수 함수라 직접 부를 수 있다), 별도로
> `ev("test_observed", { actor: "ai", criterion_ref, artifact_after, outcome })` 가 완료
> 게이트를 열지 **못하는지** 단언을 하나 더 추가하라.

### F-3 · `Task.curriculum` 이 "없다" 는 자기 보고가 틀렸다 (과소 주장)

STATE.md 제안 12번과 PR #1177 본문이 "`Task.curriculum` 영속화와 phase 전이가 없다" 고
적었다. 실제로는 `worker/src/lib/measurement-core/local-record.ts` 에 `CurriculumPhase`,
`TaskCurriculum`, `updateCurriculum()` 이 **전부 출하됐고**, 전이표(한 칸씩 앞으로만),
뒤로 가기 거절, **SX-55 의 부정 조건(`submitted` 없이 `reflected`)까지 `invalid_phase_transition`
으로 거절**하며, `worker/test/learning-events.test.mjs:232-268` 이 그것을 단언한다.

없는 것은 **호출부**다 — 확장·라우트 어디에서도 `updateCurriculum` 을 부르지 않고
(`grep -rn "updateCurriculum" extensions/ worker/src` → 0), `LearningStatePayload.phase` 는
`input.phase ?? "working"` 으로 고정돼 내려간다.

틀린 방향이 안전한 쪽(과소)이라 위험하지는 않지만, **다음 세션이 이미 있는 것을 다시
만들 수 있다.**

> **수정**: STATE.md 제안 12번과 PR 본문을 "상태 기계는 코어에 있고 테스트도 있다.
> **없는 것은 호스트 호출부와 영속화다**" 로 고치고, 남은 일을 `updateCurriculum` 호출
> 지점 하나로 명시하라.

### F-4 · `/1` 이 "바이트 그대로" 라는 주장이 증거보다 넓다

`legacy-observation.ts` 머리 주석: `"/1 behaviour is pinned to the pre-extraction verdicts …
and must reproduce them byte for byte."` **golden 코퍼스에 대해서는 맞다** — 내가 pre 트리와
HEAD 의 코어를 **같은 하나의 코퍼스**로 돌려 직접 비교했다:

```
runLegacyCases: batches=16 findings=14 diffs=0
golden vs post: diffs=0
```

그런데 `validateFindings` 의 human 판정이 `e.kind === "user" || e.kind === "correction"` 에서
`isHumanEvidence(e)` 로 바뀌었고, 새 함수는 **`actor` 를 본다.** `/1` 은 `approval` 이 아닌
kind 의 `actor` 를 제약하지 않으므로 `kind:"user", actor:"policy"` 는 유효한 `/1` 이벤트다.
직접 찔러 보았다:

```
[A1] /1 kind=user + actor=policy  pre=ACCEPTED  post=refused:missing_human_evidence
[A2] /1 kind=user + actor=ai      pre=ACCEPTED  post=refused:missing_human_evidence
[A3] /1 untouched                 pre=ACCEPTED  post=ACCEPTED
```

**방향은 옳다**(더 엄격해졌고 SX-45 의 취지에 맞는다). 문제는 두 가지다 — 주석이
"바이트 그대로" 라고 단정하는데 규칙은 바뀌었고, **그 새 가드에 테스트가 없다**
(심은 결함 #15: `isHumanEvidence` 의 actor 줄을 지워도 `measurement-core.test.mjs` 포함
전부 초록). verification.md 규칙 1b 가 말하는 "산문으로 쓴 범위 주장" 이 바로 이것이다.

> **수정**: 주석을 "`/1` **golden 코퍼스**를 바이트 그대로 재현한다. human 판정은
> `actor` 를 추가로 보므로 `actor` 를 실은 `/1` 이벤트에서는 `/1` 과 다를 수 있다" 로 좁히고,
> `learning-events.test.mjs` 에 `isHumanEvidence({kind:"user", actor:"ai"}) === false` 와
> `=== "policy"` 두 줄을 추가하라.

### F-5 · SX-14 의 "코치 제안 기대 조건은 게이트를 통과하지 못한다" 를 반대로 구현했다
