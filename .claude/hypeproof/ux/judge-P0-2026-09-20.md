   결함이고 `spec` 으로 분류한다.

### D-3 · 감사기의 수치 규칙에 맨숫자 구멍이 있다
`NUMERIC_PATTERNS` 는 `N점`·`N%`·`N/6·7·10·100` 만 잡는다. **단위 없는 맨숫자**
(`0.82`, `72`), `레벨 3`·`Lv 3`, 별점 문자열(`★★★☆☆`), 알파벳 등급(`B+`, "등급"
낱말 없이)은 전부 통과한다. `ALLOWED_NUMERIC.count_ko` 가 `\d+개`·`\d+건` 을 마스킹하므로
"완료 3개 / 미완 2개" 같은 진행률 카드도 통과한다. `region:"metric"` 은 4·6주차에
대해 수치 규칙을 **통째로** 끈다 — 지표 주차에 진짜 점수 카드가 들어오면 안 잡힌다.

> **수정**: 마스킹 후 남은 맨숫자(`(?<![\w])\d+(\.\d+)?(?![\w])`)와 `(레벨|Lv\.?)\s*\d+`,
> 별점 연속(`[★☆]{3,}`)을 `NUMERIC_PATTERNS` 에 더하고, `region:"metric"` 은 규칙을
> 끄는 대신 그 주차의 `metric_board` 가 허용하는 수치 형태만 `ALLOWED_NUMERIC` 에
> 추가하는 방식으로 바꿔라.

## 평가자가 확인하지 못한 것

정직하게 적는다. 아래는 **모른다**는 뜻이지 통과했다는 뜻이 아니다.

1. **`ChatPanel` 의 실제 렌더를 보지 못했다.** 직접 esbuild 로 묶어 렌더를 시도했고
   `StartPage`(353자, 감사 0건)는 성공했지만 `ChatPanel` 은 `config` 표면이 너무 커서
   (`ux.hints.short_input` → `welcome.greeting_md` → 그 다음 `undefined.length`) 세 번
   보강하고도 렌더에 실패했다. **C1 의 "작업 중 화면" 판정은 렌더가 아니라 소스
   정규식에 근거한다.** 조건부 분기·템플릿 조립은 소스 grep 이 놓친다(verification.md
   규칙 1). 이것이 D-1 을 가장 크게 잡은 이유다.
2. **실기 앱을 띄우지 않았다.** 상태바에 `$(graph)` 항목이 실제로 사라졌는지(SX-59
   부정문), 1280·390 뷰포트에서 Primary 가 하나인지(SX-T13), 스크롤·탭 전환 중에도
   Mission header 가 붙어 있는지(SX-T10~T14)는 **전부 확인하지 못했다.** `bash build.sh`
   는 사용자 승인 사항이고 승인이 없었다.
3. **5초 회상 테스트와 미션 문장이 가장 큰 활자인지**를 판정하지 못했다. CSS 를
   렌더에 적용해 실제 계산 폰트 크기를 잰 것이 아니라 클래스 이름과 `tokens.css` 를
   읽었을 뿐이다.
4. **코치가 `never` 를 실제로 지키는지** 모른다. 금지 문장이 프롬프트에 **닿는다**는
   것은 공급자 요청 본문에서 실측으로 확인했지만, 모델이 그것을 지키는지는 실제
   모델 호출이 필요하고 하지 않았다. SX-58 의 절반이 비어 있다는 구현자의 자기
   신고가 맞다.
5. **P0-A 대조군의 7/26 vs 6/27 중 어느 검사가 뒤집혔는지** 특정하지 못했다.
   구현자가 잰 시점의 트리 상태(픽스처가 몇 개였는지)를 재현할 방법이 없었다.
6. **`python3 scripts/hype-pr/pr.py inspect`** 는 돌리지 않았다. 지시된 게이트 목록에
   없었고, 형제 harness 체크아웃 상태에 의존해 이 세션에서 신뢰할 수 없다.
7. **`chalk` 의 `npm ci`** 를 돌리지 않았다(지시대로). 기존 `node_modules` 로 초록이
   나왔지만 깨끗한 설치에서도 같은지는 모른다.
8. **`config/traceability.json` 의 4노드가 실제 노드인지** 그래프 도구로 확인하지
   않았다. 문서 하네스 100/100 과 diff(삽입만, 기존 노드 변경 0)만 보았다.
   memory "hype-pr" 함정이 바로 이 구분이므로, 다음 평가자는 세어 보기 바란다.
