# AUTONOMY_POLICY: 언제 계속하고 언제 멈추는가

> 작성일 2026-09-18 · 상태: 활성 · 상위: `docs/AUTONOMY-MANDATE.md`(저장소 정책이 이긴다)

## 기본값

**계속한다.** 가장 방어 가능한 결정을 내리고 `STATE.md`에 적고 다음으로 간다. 사용자는 아침까지 없다.

## 묻지 않고 정하는 것

- 간격·글자 크기·줄 높이·색 단계 값. 토큰 6개의 역할은 설계 문서가 정했고 값은 거기서 읽는다
- 컴포넌트 이름, 파일 위치, 상태 관리 방식, 웹뷰/호스트 분담(설계 문서의 분담을 따르되 세부는 자유)
- 세션 설계 파일의 필드 이름(설계 문서의 예시를 따름)과 3주차 예시 내용(원문 GlobalBuddy 그대로)
- 한국어 카피의 문장 선택. 규칙: 합니다체, 행동이 주어, 금지 라벨 없음, 원문의 "쓴다" 열을 우선 사용
- 기존 테스트 파일에 대한 의도적 구조 변경 시 스펙 갱신(단언을 약하게 하지 않는 한)
- 서브에이전트 분할, 병렬 정도, 재시도 횟수(한도 안에서)

해결 순서: `docs/requirements/studio-learning-experience.md` → `docs/design/studio-learning-experience.md` → 원문 `ui-philosophy-2026-09-18.md` → 기존 저장소 관례 → 평가자 피드백.

## 진짜 blocker (이것만 `STATE.md`에 적고 다음 독립 task로 간다)

1. 세션에 없는 자격증명·인증이 필요할 때
2. 범위 밖의 파괴적 마이그레이션이 필요할 때
3. 두 요구가 논리적으로 양립 불가일 때(예: SX 행끼리, 또는 SX와 기존 AE/NAT/MC가 충돌)
4. 안전하게 추정할 수 없고 뜻을 바꾸는 사업 정보(참가자 데이터·동의·기관 정책·가격)
5. 수정 3회 + 적대적 진단 1회 + 마지막 시도 1회 뒤에도 게이트 미달
6. 저장소가 이미 깨져 있어 의미 있는 구현이 불가능하고 격리할 수 없을 때

## 정하지 말고 올리는 것 (설계 결정이 아니다)

- 요구 문장의 뜻을 바꾸는 개정(오타·링크·명백한 모순 제외)
- 새 점수·등급·순위·배지·스트릭. 어떤 사유로도 만들지 않는다
- 참가자 데이터, 기존 코호트 프로필, 기존 수업 정책, 보존·삭제 정책
- 프로덕션 배포, Cloudflare·시크릿·계정·결제
- Lab 저장소 변경
- 테스트 단언 완화, 통과선 인하, 루브릭 수정
- `bash build.sh` 전체 앱 빌드

## 시간 예산

한 task에 machine gate 초록까지 90분을 넘기면 원인을 분류해 적고 다음 독립 task로 간다. 단계(P0/P1/P2) 하나가 4시간을 넘기면 그 단계의 PR을 부분 범위로 열고(본문에 미완 SX 명시) 다음 단계로 간다. 아침에 부분이라도 머지 가능한 PR이 있는 편이 낫다.
