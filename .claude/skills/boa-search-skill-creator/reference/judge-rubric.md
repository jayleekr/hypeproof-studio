# Phase 2 LLM-judge 채점 rubric

임직원이 child search skill을 발동시킨 한 턴을 보고, 7자산 각각에 **0/1/2점**을 매긴다. 채점자는 이 세션의 Claude(LLM-judge).

## 핵심 원칙 — 행동 증거 기반

**채점은 임직원이 *말한 내용*이 아니라 *보인 행동*으로 한다.** 7자산은 절차적 역량 (procedural) 이지 선언적 지식 (declarative)이 아니다.

- "출처 두 곳 확인합니다"라고 *말한 것* → 0점
- 결과 받고 다음 메시지에 "이 출처 믿을 수 있어?", "발행 언제야?", "링크 줘" 같은 *행동이 보인 것* → 1점/2점

이 구분이 깨지면 채점 자체가 의미 없다.

## 첫 턴 룰

**첫 턴은 점수 없음 — 기록만 한다.** 행동 누적 없이 단일 턴으로 절차적 역량 추론 불가. JSONL에 `prompt / result / owner_feedback / self_note`는 채우되, `scores` 는 `null` 로 둔다.

두 번째 턴부터 점수 산정. 단일 턴 점수도 *그 턴에서 보인 행동 증거*가 있을 때만 매긴다 — 신호 없으면 해당 자산은 `null` 두고 다음 턴 기다림.

## 다른 일반 원칙

- **원장님 피드백이 ground truth**. 결과가 좋아 보여도 원장님 RISK면 ownership/verification에서 감점.
- **0/1/2 의미**:
  - **0** — 해당 자산을 무시했거나 반대로 갔다.
  - **1** — 약한 행동 증거 1개.
  - **2** — 명확한 행동 증거 2개 이상 또는 누적 패턴.
- 각 점수마다 **행동 증거를 인용한 한 줄 근거**를 단다. ("L4 메시지: '이 출처 어디야' 등장" 처럼)
- 모호하면 `null`. 후한 채점은 학습을 망친다.

## 자산별 행동 증거 기준

### 1. Intent clarity (의도 명확성)

**보는 것**: 임직원의 *첫 프롬프트*에 누구·무엇을·왜가 들어있는가.

| 점수 | 행동 증거 |
|---|---|
| 0 | 프롬프트가 "X에 대해 알려줘" 수준. 대상 청자·다음 행동 신호 0 |
| 1 | 셋 중 둘이 있음 (예: 대상은 명시, 다음 행동은 모호) |
| 2 | 셋이 한 문장에 모두 있음 — "원장님께 보고용으로 가격 top3" 류 |

근거 예: "첫 메시지 '원장님이 가격 알아보라는데 top3' → 대상(원장님)·목적(보고)·결과(top3) 있으나 'top3' 의미 모호 → 1점"

### 2. Taste (안목)

**보는 것**: 첫 결과를 *그대로 받았는지, 어디가 부족한지 짚었는지*.

| 점수 | 행동 증거 |
|---|---|
| 0 | 첫 결과 받고 후속 메시지 없음 또는 "감사합니다"만 |
| 1 | 결과에 대해 한 부족점 짚음 ("이거 너무 길어", "출처가 약함") |
| 2 | 부족점 2개 이상 + 어떤 모양이 좋은지 명시 |

근거 예: "L3 메시지: '자주 쓰는 거 가격 달라했는데 왜 안 줘' → 부족점 2개(자주 쓰는·가격) → 2점 후보, 단 좋은 모양 명시 없어 1점"

### 3. Context design (컨텍스트 설계)

**보는 것**: 임직원이 *직접 던진* 컨텍스트. child skill의 `context.md` 자동 로드는 계산 안 함 — 그건 도구가 주는 거지 임직원의 역량이 아니다.

| 점수 | 행동 증거 |
|---|---|
| 0 | 프롬프트에 본인 상황·대상 환자·우리 정책 한 줄도 없음 |
| 1 | 그 중 1개 들어감 (예: 환자 상황만) |
| 2 | 2개 이상 (예: 환자군 + 원장님 의도) |

근거 예: "프롬프트에 '원장님이 시킴'만 있고 본인 역할·환자 상황·도입 검토인지 견적 비교인지 미명시 → 1점"

### 4. Verification reflex (검증 반사)

**보는 것**: 결과 받고 *바로 다음 메시지*에 검증 행동이 나오는가.

| 점수 | 행동 증거 |
|---|---|
| 0 | 결과를 그대로 받고 후속 검증 메시지 없음 |
| 1 | 검증 행동 1개 (출처·연도·링크·재검색 요청 중 하나) |
| 2 | 검증 행동 2개 이상 또는 child skill 자체에 검증 룰을 추가하라고 요청 |

근거 예: "L5 메시지: '출처는 웹링크 줘 보아검색 스킬 다듬어줘' → 검증 룰을 도구에 박는 행동 → 2점"

### 5. Delegation judgment (위임 판단)

**보는 것**: 결과를 *그대로 환자/원장님에 넘겼는지*, 사람 컨펌 layer를 명시했는지.

| 점수 | 행동 증거 |
|---|---|
| 0 | AI 결과 (특히 의학·가격·환자 발화)를 *그대로 사용* 의도 표현 |
| 1 | "원장님께 보고" 정도 의도. 명시적 컨펌 layer는 약함 |
| 2 | "원장님 컨펌 받기 전엔 환자한테 안 보냄" 류 *명시적 사람 단계* 선언 또는 행동 |

근거 예: "원장님 보고용으로만 쓴다는 의도 있으나 'human-needed 컨펌'을 명시 안 함 → 1점"

### 6. Iteration reflex (반복 반사)

**보는 것**: 같은 목적 안에서 *메시지 수정 횟수* + child skill 자체를 *깎으러 왔는지*.

| 점수 | 행동 증거 |
|---|---|
| 0 | 한 번 받고 끝. 후속 수정 0회. child skill 안 깎음 |
| 1 | 같은 목적 안에서 1~2회 수정 OR 첫 turn에 깎기 요청 |
| 2 | 누적 — 여러 턴에 걸쳐 child skill 자체를 손보러 옴 (장기 신호) |

**누적 신호** — 단일 턴으로는 2점 어려움. 여러 턴 JSONL을 같이 봐야 함. 새 임직원의 첫 깎기는 1점 cap.

근거 예: "한 턴 안에서 2회 수정 + child skill SKILL.md/verification.md 룰 추가까지 trigger → 1점 (누적 부족으로 2점 보류)"

### 7. Ownership (소유감)

**보는 것**: `self_note` 와 결과 부정 메시지의 *언어 패턴*. 1인칭 책임 vs 외재 귀인.

| 점수 | 행동 증거 |
|---|---|
| 0 | "AI가 이상했어요" / "검색이 별로네요" — 외재 귀인. 본인 책임 누락 |
| 1 | 결과 부정은 하지만 누구 책임인지 모호 |
| 2 | "내 프롬프트가 약했네 — 다음엔 X 추가할게" / "내 도구라서 룰 박을게" — 1인칭 책임 + 자기 도구화 행동 |

근거 예: "L5에서 결과 부족 즉시 child skill에 룰 박음 = '내 도구' 인식 + 본인이 고침 → 2점"

## 출력 형식

JSONL 한 줄로 `~/.claude/boa-skills/logs/<child-skill-name>.jsonl` 에 append.

- `ts` (ISO 8601 UTC)
- `skill` (child skill 이름)
- `prompt`, `result`, `owner_feedback{verdict,comment}`, `self_note`
- `scores.<asset> = {score: 0|1|2|null, reason: "<행동 증거 인용>"}` 7개
  - 첫 턴: 전부 `null`
  - 그 외: 행동 증거 없는 자산도 `null` 가능 (모호하면 `null`)

## 임직원에게 보여주는 양

기록 직후엔 한 줄만 — "📝 기록합니다 (`<child-skill-name>` #N턴)". 점수·근거·약점은 임직원이 "히스토그램 보여줘" / "약점 짚어줘" 명시 요청할 때만. 7자산 자동 나열 금지.
