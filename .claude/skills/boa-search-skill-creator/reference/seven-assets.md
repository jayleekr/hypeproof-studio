# 7 AI Native Assets — 보아치과 search skill 맥락

> Canonical 원본: `/Users/jwcorp/hypeproof-studio/docs/seven-assets.md` (v0.2, Owner: Jay, 2026-05-23).
> 이 파일은 메타-스킬 안에서 즉시 참조할 수 있게 복사·각색한 사본.
> 원본과 충돌 시 원본이 우선.

이 7가지가 search skill 만들기·깎기에서 어떻게 발현되는지 같이 정리해 둔다. Phase 1 Q&A와 Phase 2 채점 rubric은 모두 이 정의에 정렬돼야 한다.

---

## 1. Taste (안목)

> AI가 아무리 많이 만들어줘도, 무엇이 좋은지 아는 사람이 좋은 결과를 낸다.

**search skill 맥락**: "좋은 검색 결과"가 무엇인지 임직원이 구체적으로 말할 수 있는가. 출처 권위? 환자 눈높이? 가격 비교 가능성? 그림 포함 여부? Taste 없으면 AI 결과가 좋아도 좋은 줄 모르고, 나빠도 나쁜 줄 모른다.

## 2. Intent clarity (의도 명확성)

> AI를 켜기 전에 내가 뭘 원하는지 안다. 프롬프트 기술이 아니라 자기 이해.

**search skill 맥락**: 검색의 **목적**과 **다음 행동**을 한 문장으로 말할 수 있는가. "임플란트 가격이 궁금해"가 아니라 "오후 상담 들어오는 60대 환자 분께 임플란트 비용 범위 + 보철 옵션을 보여드리고 본인 견적과 비교하게 하고 싶어." 이렇게 명확해지면 검색은 절반 끝난다.

## 3. Context design (컨텍스트 설계)

> AI에게 무엇을 주느냐가 모든 것을 결정한다는 것. 기술이 아니라 설계 감각.

**search skill 맥락**: 매번 같이 던질 **고정 컨텍스트**를 설계할 수 있는가. 임직원 역할, 환자군 특성, 보아치과 가격 정책, 자주 받는 질문, 금기사항. 이걸 child skill의 `reference/context.md`에 박아두면 매번 새로 설명할 필요 없다.

## 4. Verification reflex (검증 반사)

> AI 출력을 자동으로 검증하는 습관. 맹신도 불신도 아닌, 검증이 기본값.

**search skill 맥락**: 검색 결과를 받자마자 **무엇을 자동으로 확인할 것인가**. 출처 두 곳 이상? 한국 식약처/대한치과의사협회? 발행 연도 3년 이내? 원장님 컨펌 필요 케이스? Verification 룰은 child skill의 `reference/verification.md`에 체크리스트로 박는다.

## 5. Delegation judgment (위임 판단)

> 무엇을 AI에게 맡기고 무엇을 내가 할지 빠르게 판단하는 능력. 이게 없으면 AI에 끌려다닌다.

**search skill 맥락**: AI에 **절대 못 맡기는 부분**을 미리 정의했는가. 환자에게 직접 발화하는 문장 작성? 의학적 final call? 가격 견적 확정? 이건 사람이 한다. 검색·요약·후보 추리기까지가 AI 영역. 이 경계가 흐리면 사고난다.

## 6. Iteration reflex (반복 반사)

> 완벽한 첫 결과를 기다리지 않는다. 빠른 V1 + 반복이 기본값.

**search skill 맥락**: V1을 거칠게라도 일단 만들고 쓰면서 깎는 자세. Phase 1 Q&A에서 답이 안 떠오르면 **default 안을 받고 진행**하는 것도 iteration. "처음부터 완벽한 검색 스킬"은 환상.

## 7. Ownership (소유감)

> AI가 만들어줘도 "내 것"으로 만드는 것. 책임과 소유감.

**search skill 맥락**: child skill의 이름·트리거 문구·실패 모드를 **임직원 본인이** 결정한다. 메타-스킬이 정해주는 게 아니다. 검색 결과로 환자 응대에 사고가 나도 "AI가 그랬어요"가 아니라 "내 도구로 내가 했어요"라고 말할 수 있어야 한다.
